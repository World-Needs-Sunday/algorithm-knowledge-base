# 添加知识点

> 详细规范见 `PROJECT_FRAMEWORK.md` §3（frontmatter 字段、章节、命名、KaTeX 陷阱）；本文件只讲**怎么一步步做**。

## 铁律（先确认自己记得）

1. **不代写 `.cpp` 实现**——用户的代码只**搬运**，不改逻辑、不补函数、不"顺手优化"。缺代码就留任务卡注释并提醒用户写。
2. **改完必须过门禁**：`node tools/lint.js`（error 必须 0）→ `node build.js`。
3. **数据只从用户材料里取**：题号、复杂度、来源、样例，一律不许编。

## 输入：用户给的一个文件夹

```
任意文件夹/
├── 代码.cpp        ← 用户本人写的实现（文件名可能是 源.cpp / Untitled1.cpp …）
└── 思路.md         ← 用户的思路总结（可能是网页版 AI 总结出的笔记）
```

- 知识点**没有**题目文件；如果有题面，那大概率是题目（转 `add-problem`）。
- 文件名不固定：**按内容判断**（代码看 `#include`/`main`；思路看小标题与讲解口吻）。
- 初赛笔记类知识点可以**没有代码**（此时省略 `codePath`）。

## 步骤

### Step 1 · 读材料，列出元数据让用户确认（不要猜）

一次性列清，让用户一回就够：

| 字段 | 怎么定 |
|---|---|
| `id` | `{前缀}-{子分类缩写}-{算法名}`，小写连字符；前缀见 `PROJECT_FRAMEWORK.md` §3.6 |
| `title` | 正式算法名；**禁止**"自己写的""以前没学过" |
| `category` | 8 个大类之一 |
| `subcategory` / `subSubcategory` | 需在图谱里登记过（否则 lint W005/W006）；**同类知识点多时用 `subSubcategory` 做二级标签**（例：数学·数论基础 → 素数 / 同余与模运算 / 数论函数；数据结构·可持久化数据结构 → 可持久化线段树） |
| `tags` | 3–6 个（>8 触发 W010） |
| `timeComplexity` / `spaceComplexity` | 从思路或代码层数推出；**不许写"未知"** |
| `level` | 默认 `A`；用户说要详解/深挖再给 B/C |
| `codePath` | `{大类}\{子分类}\{算法名}\Untitled1.cpp`（反斜杠） |

> 拿不准的字段**必须问**，尤其 `category` / `subcategory` / `id`。
> **作者（必确认）**：默认「站主」（你本人）→ 文件用 `content/<id>.md`。若是**其他作者**（如焚风），先确认作者名与 key，在 `build.js` 的 `AUTHOR_KEYS` 登记，文件用 `content/<id>--作者.md`，`id` 仍写 base id，`source` 填作者全名（详见下文「多版本」）。

### Step 2 · 建骨架（脚手架会自动建代码文件占位 + 图谱空条目）

```bash
node tools/new-kp.js --id <id> --title "<标题>" --category <大类> --subcategory <子分类> \
  --tags "<标签1,标签2,标签3>" --time "<O(...)>" --space "<O(...)>" --level A \
  --code "<大类>\<子分类>\<算法名>\Untitled1.cpp"
```

先加 `--dry-run` 看它准备写哪些文件，确认无误再去掉。

### Step 3 · 放代码（原样搬运）

把用户的代码文件复制到 `codePath` 指向的位置（目录不存在就创建）。
**不要改一个字符**；只有用户明确要求时，才允许删除调试/计时代码（`printf("耗时…")` 这类，lint W030）。

### Step 4 · 写正文：把「思路」映射成规范章节

| 思路文件里的小节 | 落到知识点的哪一章 |
|---|---|
| 一句话结论 / 思路是怎么想出来的 | `## 算法原理`（结论先行，再写"从什么信号想到这条路、关键性质是什么、哪条路走不通"） |
| 具体做法 / 关键公式 | `## 核心公式 / 状态定义与转移方程`（状态要写清每个维度含义与范围） |
| （数据结构类）结构示意 | `## 数据结构图示`（ASCII 图）＋ `## 核心操作详解` |
| 代码片段与讲解 | `## 逐行代码解析` |
| 复杂度 | `## 复杂度分析`（时间+空间，并说明怎么数出来的） |
| 适用场景 | `## 适用场景`（什么题用它、什么题不要用它） |
| 容易错的地方 | `## 常见陷阱与注意事项`（覆盖溢出/边界 n=1/初始化/下标哨兵/退化/卡常；条数以讲清为准，不设上限） |
| 可以迁移到哪 | `## 对比与扩展`（与易混算法对比、变体、可复用套路） |

> **不设字数/条数上限**：以"讲透"为准。尤其「算法原理」要把**核心思想怎么来的**、**题面/定义里没明说但能推出的关键性质（不变量）**显式挖出来并推导，别为短而跳步。

**「逐行代码解析」用「模块式」写（参考 `ds-block-decomposition`），不要"整段代码 + 大段解释"**：

````
### <模块名>（如 全局变量 / read 读入 / mul 函数 / main）

```cpp
<该模块的代码，逐行加 // 注释>
```

- 关键点 1（这个变量/循环干什么）
- 关键点 2（边界为什么是这个范围 / 哪个符号容易错）
````

- 按逻辑拆模块，模块数与每条要点**以讲清为准，不设上限**。
- 所有模块的代码块**按顺序拼接起来，必须与 `.cpp` 完全一致**（lint W028 会按这个校验；`//` 注释随便加，不影响判定）。
- 某模块不重要就只放一行关键片段 + 说明（片段式也合格）；**最忌"接近整段、内容又与 `.cpp` 不同"**。

### Step 5 · 图谱

- `knowledgePoints` 里填 `prerequisites` / `related`，**只能用已存在的知识点 id**（否则 E011）。
- `related` 保持**双向**（A→B 且 B→A），否则 W033。
- 新子分类要补 `subcategories` 描述；新小分类补 `subSubcategories`（并同步 .md 的 `subSubcategory`）。

### Step 6 · 门禁与验证

```bash
node tools/lint.js          # error 必须 0
node build.js               # 产物：109 → 110 之类
```

再让用户（或你自己用无头浏览器）**Ctrl+F5** 看：公式渲染、代码高亮、前置/相关链接、侧边栏归类是否正常。

## 验收清单

- [ ] `id` 与文件名一致，全库唯一
- [ ] 章节齐全且标题用规范名（算法类 7 章 / 数据结构类 8 章）
- [ ] 复杂度非"未知"，与正文、与代码三者一致
- [ ] `codePath` 指向的文件真实存在，内容 = 用户给的代码
- [ ] 图谱有条目，`related` 双向
- [ ] `node tools/lint.js` error = 0
- [ ] `node build.js` 知识点数量 +1，无"代码文件未找到"

## 常见坑

| 坑 | 表现 | 处理 |
|---|---|---|
| 忘了放 `.cpp` 就写 `codePath` | lint E007 | 先复制文件再写路径 |
| 正文代码块是"我抄的旧版" | lint W028 | 以 `.cpp` 为准同步 |
| 复杂度照抄模型结论 | 与实现不符 | 数循环层数，或问用户 |
| 图谱 `related` 单向 | W033（113 处那种规模很难修） | 加一条反向边 |
| 标题带"自己写的" | W002 | 改成正式名（版本差异用 `-self` 后缀放 id 里） |
| 表格公式里的 `|` | W019，表格错位 | 写 `\lvert…\rvert` |

## 多版本（给知识点加"其他作者的版本"）

每个知识点可有多个作者各自的版本（正文 + 代码各一套），详情页顶部 tab 切换：

- 站主版：`content/<id>.md`；其他作者版：`content/<id>--作者.md`（作者 key 见 `build.js` 顶部 `AUTHOR_KEYS`）。
- 版本文件 `id` 与站主版相同（base id，不含 `--作者`），`category/subcategory` 一致，`source` 填作者全名，`codePath` 用**独立路径**（同目录文件名加 `--作者` 后缀，不覆盖站主 `.cpp`）。
- 只给某作者加版本时：新建 `content/<id>--作者.md`，不碰站主版；新建作者时先在 `AUTHOR_KEYS` 登记 key → 显示名。
- 版本文件同样走门禁（`node tools/lint.js` + `build.js`）。

## 汇报模板

```
【改动】content/<id>.md（新建）、<大类>\<子分类>\<算法名>\Untitled1.cpp（搬运）、knowledge_graph.json（+1 条目）
【验证】node tools/lint.js → error 0 / warning N；node build.js → X 知识点 / Y 题目
【需要你本人做】确认 category/subcategory 是否合适；代码是否需要删掉调试输出
【待确认】<我判断过的地方 + 回退方式>
```
