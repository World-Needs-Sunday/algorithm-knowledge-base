# 添加题目

> 详细规范见 `PROJECT_FRAMEWORK.md` §3。题目**不需要**改 `knowledge_graph.json`（所有信息从 frontmatter 读）。

## 铁律（先确认自己记得）

1. **不代写 `.cpp` 实现**——只搬运用户的代码。
2. **改完必须过门禁**：`node tools/lint.js`（error 必须 0）→ `node build.js`。
3. **题面、数据范围、样例、题号一律不许编**；查不到就写 `来源未考证` / `-`，样例缺失就如实说"官方样例未取得"。

## 输入：用户给的一个文件夹

```
任意文件夹/
├── 题目.md        ← 题面（可能是 题面.txt / statement.* ；也可能是 OJ 页面截图里的文字）
├── 代码.cpp       ← 用户本人写的正解
└── 思路.md        ← 用户的思路总结
```

**按内容判断**哪个是哪个；三个角色缺一不可（缺题面就问用户要，缺思路可以用代码 + 提问补，缺代码就留任务卡注释）。

## 步骤

### Step 1 · 抽取元数据，列给用户确认

| 字段 | 怎么定 |
|---|---|
| `id` | `prob-<oj缩写>-<题号或题名>`，如 `prob-luogu-p1050`、`prob-cf-2252d` |
| `title` | 题名；**去掉 `D.` / `C1.` / `F.` 这类场次编号前缀**（lint W002） |
| `oj` | 洛谷 / Codeforces / AtCoder / ICPC / CSP-S …；**查不到写 `来源未考证`** |
| `problemId` | `P1050` / `CF2252D` …；**查不到写 `-`** |
| `difficulty` | 入门 / 简单 / 中等 / 困难 / 提高（其它值触发 W026） |
| `category` | 按考点大类（决定侧边栏分组） |
| `tags` | 3–6 个 |
| 复杂度 | 从代码推，非"未知" |
| `codePath` | `题目专辑\{分类}\{题名}\代码.cpp` |

### Step 2 · 建骨架

```bash
node tools/new-problem.js --id <id> --title "<题名>" --oj <OJ> --problemId <题号> \
  --difficulty <难度> --category <分类> --tags "<标签>" --time "<O(...)>" --space "<O(...)>" \
  --level A --code "题目专辑\<分类>\<题名>\代码.cpp"
```

### Step 3 · 放代码

把用户的代码复制到 `codePath`（题目代码习惯用 `代码.cpp`）。**一个字符都不改**。

### Step 4 · 写正文：八个部分一个都不能少

```
## 题目描述
### 输入格式          ← lint W024 要求这三个小节名存在
### 输出格式
### 数据范围          ← 必须写！这是判断复杂度是否可行的唯一依据
## 样例               ← 必须有（### 样例 1 + **输入：** / **输出：** / **解释：**）
## 解题思路           ← 核心章节：从"看到题想到什么"讲到"为什么这个做法对"
## 逐行代码解析       ← 与 .cpp 逐字一致的代码块，或关键片段 + 说明
## 复杂度分析         ← 时间/空间 + 怎么数出来的
## 常见陷阱与注意事项  ← ≥5 条
## 对比与扩展         ← 同类题、变体、可复用套路
```

**样例纪律**：只写**你真正跑过**的输入输出（用 `g++` 编译用户的代码实测一遍最稳）。官方样例拿不到就明说，不要凭记忆写。
**数据范围**：忠实转述题面；题面没写就问用户，不要自己造。

### Step 5 · 门禁与验证

```bash
node tools/lint.js
node build.js
```

再 Ctrl+F5 检查：题目在「📝 题目专辑」里出现、难度徽章、样例、代码区块正常。

## 验收清单

- [ ] `oj` / `problemId` / `difficulty` / `category` 齐全且不编造
- [ ] 「输入格式 / 输出格式 / 数据范围」三个小节都在
- [ ] 「样例」与实际代码输出一致（真跑过）
- [ ] 「解题思路」讲清了"为什么这样对"
- [ ] 代码块与 `.cpp` 一致（或只放片段）
- [ ] `node tools/lint.js` error = 0；`node build.js` 题目数 +1
- [ ] 无调试输出残留（`printf("耗时…")` → W030）

## 常见坑

| 坑 | 处理 |
|---|---|
| 题名带 `D.` 前缀 | 去掉，题号放 `problemId` |
| 数据范围漏写 | W024；从题面复制 |
| 样例凭记忆写 | 必须编译实测（本项目有过 P7915 的教训） |
| 多测题忘记清空数组 | 写进「常见陷阱」 |
| `oj`/`problemId` 空着 | W027；查不到就写 `来源未考证` / `-` |
| 把代码贴进正文后没核对 | W028，改一边必同步另一边 |

## 汇报模板

```
【改动】problems/<id>.md（新建）、题目专辑\<分类>\<题名>\代码.cpp（搬运）
【验证】node tools/lint.js → error 0 / warning N；node build.js → 109 知识点 / 21 题目；样例已编译实测：输入 … → 输出 …
【需要你本人做】确认 oj/problemId 是否正确；补充官方样例（如果我只拿到部分）
【待确认】<我判断过的地方>
```
