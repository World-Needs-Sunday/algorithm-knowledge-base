# 修改知识点 / 题目

> 规范见 `PROJECT_FRAMEWORK.md` §3、§6。核心原则：**只改错的地方，不顺手重构**。

## 铁律（先确认自己记得）

1. **不代写 `.cpp` 实现**：如果用户说"这题 WA"，你只能**指出** bug 位置与修复方向、给边界用例；不许直接给出改好的实现（除非用户明确说"破例帮我写"）。
2. **改完必须过门禁**：`node tools/lint.js`（error 必须 0）→ `node build.js`。
3. **不回退用户没让你改的地方**——保持 diff 最小。

## 输入

用户通常是**一句话 + 我发现的错误**，例如：

- "`graph-johnson` 那条的复杂度写错了，应该是 $O(nm\log n)$"
- "P7915 的第二组样例输出不对"
- "`dp-digit-count` 里那段手算推到 19−d 是错的"
- "我把代码改了，正文也同步一下"
- "这题 WA 了，帮我看看"

## 步骤

### Step 1 · 定位（先别动手）

```bash
# 按标题/关键词找文件
node tools/lint.js --quiet                    # 先看当前门禁状态（改动前的基线）
# 用 grep 在 content/ problems/ 里定位那条内容
```

确认三件事：**改哪个文件**、**是知识点还是题目**、**是否牵涉 `.cpp`**。

### Step 2 · 判断改动类型 → 决定要同步什么

| 改动类型 | 必须同步的地方 |
|---|---|
| 只改正文文字/公式 | 该 `.md`；顺手检查 frontmatter 的复杂度是否仍一致 |
| 改 frontmatter（标题/tags/复杂度/codePath） | 该 `.md`；`codePath` 变了要确认文件真实存在 |
| 改分类/子分类 | 该 `.md` + `knowledge_graph.json`（`subcategories` 登记） |
| 改前置/相关关系 | `knowledge_graph.json`；`related` 要**双向** |
| **改 `.cpp`** | 正文「逐行代码解析」的整段代码块（W028）；若文档里写了"本代码用 X"，也要一起更新 |
| 新增/删除辅助函数、换循环顺序 | 代码块 + 逐行解析文字 + 要点表 + 常见陷阱 |

### Step 3 · 最小改动

- 用 `edit`（定点替换）而不是整体重写，保证 diff 只含该改的行。
- 用户给的是**正确说法**就照办；用户没给、你又需要判断时：
  - 能验证的（例如复杂度数循环层数）→ 验证后再改，并在汇报里说明依据；
  - 不能验证的（题号、年份、官方样例）→ **先问**，不要猜。

### Step 4 · 若问题出在用户的 `.cpp` 里

允许：
- 指出**哪一行、为什么错**、会导致什么现象（WA/TLE/RE）；
- 给出**边界数据**让用户自己验；
- 删除调试输出（`printf("耗时…")` 这类，用户同意时）。

禁止：直接把实现改好。用户明确要求破例时，按铁律标注 `⚠️ 已按你的破例要求代写代码`。

### Step 5 · 门禁与验证

```bash
node tools/lint.js          # error 必须 0（修订类任务最容易把 W028 弄出来）
node build.js
```

浏览器 Ctrl+F5 看改动后的那一条（公式、代码、徽章）。

## 验收清单

- [ ] diff 只包含该改的内容（没有顺手改的格式/无关条目）
- [ ] 若动了 `.cpp` 或正文代码块，两边已同步（W028 = 0）
- [ ] 若动了复杂度，frontmatter 与正文一致，且不是"未知"
- [ ] 若动了图谱，`related` 双向、指向的 id 都存在
- [ ] `node tools/lint.js` error = 0；`node build.js` 数量不变
- [ ] 汇报里写清了"改前 → 改后"和依据

## 常见坑

| 坑 | 后果 | 处理 |
|---|---|---|
| 改了 `.cpp` 忘了同步正文 | W028（本项目历史上 36 处） | 改一边必须改另一边 |
| 改正文忘了改 frontmatter 复杂度 | 两处矛盾 | 一起改 |
| 顺手"优化"了措辞/格式 | diff 变大、难以复核 | 只改被指出的问题 |
| 把 `.md` 里的公式当成散文改 | 破坏 `$` 配对 → 全篇公式不渲染 | 改完检查 `$` 成对 |
| 用户说"样例错了"就直接改 | 可能把对的改错 | 先编译实测，再改 |
| 改了 `id` 或文件名 | 锚点/互链失效（E003） | 除非用户要求，否则不动 id |

## 汇报模板

```
【改动】content/xxx.md 第 N 行：<改前> → <改后>（依据：…）
【验证】node tools/lint.js → error 0 / warning N；node build.js → 109 知识点 / 20 题目
【需要你本人做】<例如：这条结论我无法验证，请你确认>
【待确认】<我做了判断的地方 + 回退方式>
```
