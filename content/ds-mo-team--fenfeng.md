## 算法原理

莫队（Mo's Algorithm）由莫涛提出，是一种解决区间查询问题的算法，一般需要**离线**操作。它建立在双指针思想之上，借助分块维护区间，并通过动态转移来回答一组查询。

核心思路是：如果能在较小代价内把当前区间 $[l, r]$ 转移到相邻区间 $[l', r']$，那么依次处理所有查询时，总代价取决于左右两个指针的累计移动量。若直接按输入顺序逐个处理，当查询区间「左右横跳」、相邻查询跨度极大时，指针总移动量会退化为 $O(n^2)$，与暴力无异。

莫队的关键在于**重排查询的处理顺序**，使指针跳转次数尽可能少。单纯以 $l$ 为第一关键字、$r$ 为第二关键字升序排序的贪心，仍可被构造数据卡掉。引入分块后问题迎刃而解：将元素分块，设第 $i$ 个元素所在块号为 $b_i$，把查询按「$b_l$ 为第一关键字、$r$ 为第二关键字」升序排序。这样左指针每次跳跃不超过块长 $B$，右指针在每个块区间内的总移动不超过 $n$，指针总移动量被均摊到根号量级。

为进一步减少右指针跨块时的无谓折返，还可引入**奇偶化排序**这一常数优化：同一块内，若块号 $b_l$ 为奇数则按 $r$ 升序、为偶数则按 $r$ 降序（相邻块方向相反），使右指针在块间切换时能顺带计算沿途答案，实测可将时间优化约一倍。

莫队需要实现两个核心函数 `add(p)` 与 `del(p)`，分别表示把位置 $p$ 的元素纳入或移出当前区间并维护答案。二者的内部逻辑因题而异，故通常只给出主循环模板。

## 核心公式 / 状态定义与转移方程

**状态定义**：当前维护的区间 $[L, R]$ 以及该区间对应的答案 $\text{nowAns}$。`add` / `del` 负责在区间扩张或收缩时增量维护 $\text{nowAns}$。

**转移代价**：从区间 $[l_i, r_i]$ 转移到 $[l_j, r_j]$ 的代价为

$$
O\bigl(|l_i - l_j| + |r_i - r_j|\bigr)
$$

**排序规则**：设块长为 $B$，第 $i$ 个元素所在块号 $b_i = \left\lfloor \dfrac{i}{B} \right\rfloor$（下标从 $0$ 或 $1$ 起，取整方式略有差异，不影响结论）。查询按 $(b_l,\ r)$ 升序排列，即左端点所在块号为第一关键字、右端点为第二关键字。

**指针移动量**：

- 左指针 $l$：每次跳跃不超过块长 $B$，$q$ 个查询总移动 $O(qB)$；
- 右指针 $r$：每个块区间内总移动不超过 $n$，共 $\dfrac{n}{B}$ 个块，总移动 $O\left(n\cdot\dfrac{n}{B}\right)=O\left(\dfrac{n^2}{B}\right)$。

故总跳跃复杂度为

$$
O\left(qB + \frac{n^2}{B}\right)
$$

由均值不等式，取 $B = \sqrt{\dfrac{n^2}{q}}$ 时取得最小复杂度，即均摊 $O(n\sqrt{q})$。当 $q$ 与 $n$ 同阶时 $B = \sqrt{n}$，退化为常见的 $O(n\sqrt{n})$。

**增量维护**：设相邻区间的转移可以在 $O(k)$ 内完成，则分块即可实现 $O(n\sqrt{q})$ 的根号复杂度；实际中 $O(k)$ 通常为 $O(1)$ 或 $O(\log n)$。

## 逐行代码解析

以下为资料中的主循环模板（`add` / `del` 因题而异，未给出实现，故不构成完整可运行程序）：

```cpp
m = read();                       // m 是询问次数
for (int i = 1; i <= m; i++)
    q[i].l = read(), q[i].r = read(), q[i].id = i;
sort(q + 1, q + m + 1, cmp);      // 按 (b_l, r) 排序，配合奇偶优化
for (int i = 1; i <= m; i++) {
    while (L > q[i].l) Add(--L);  // 左指针左移：纳入新位置
    while (R < q[i].r) Add(++R);  // 右指针右移：纳入新位置
    while (L < q[i].l) Del(L++);  // 左指针右移：移除旧位置
    while (R > q[i].r) Del(R--);  // 右指针左移：移除旧位置
    ans[q[i].id] = nowAns;        // 答案写回原始询问位置
}
for (int i = 1; i <= m; i++) cout << ans[i] << "\n";
```

- **读入与编号**：每条询问读入 `l`、`r`，并用 `id` 记录原始编号；排序会打乱顺序，`id` 用于最终把答案写回正确位置。
- **`Add` / `Del` 是核心**：`Add(p)` 把位置 $p$ 的元素加入区间、`Del(p)` 把位置 $p$ 的元素移出区间，并同步维护当前答案 `nowAns`，二者是莫队唯一需要按题目定制的地方。
- **指针移动顺序**：固定为先扩展（两个 `Add`）后收缩（两个 `Del`），保证收缩时被删除的元素确实在当前区间内，避免出现 $L > R$ 的非法状态。
- **自增自减方向**：`--L`、`++R` 先移动指针再 `Add` 新位置，`L++`、`R--` 先 `Del` 当前位置再移动指针，方向写反会导致答案错乱。
- **答案写回**：`nowAns` 是 `Add` / `Del` 重点维护的对象，每轮循环结束写入 `ans[q[i].id]`，最后按 $1\dots m$ 的原始顺序输出。

## 复杂度分析

设数组长度为 $n$、询问数为 $q$、块长为 $B$。

- **排序**：对 $q$ 个询问排序，耗时 $O(q\log q)$。
- **左指针 $l$**：同一块内每次跳跃不超过 $B$，$q$ 个询问总移动 $O(qB)$。
- **右指针 $r$**：每个块区间内 $r$ 沿数轴至多移动 $n$，共 $\dfrac{n}{B}$ 个块，总移动 $O\left(\dfrac{n^2}{B}\right)$。

总移动量 $O\left(qB+\dfrac{n^2}{B}\right)$，取 $B=\sqrt{\dfrac{n^2}{q}}$ 时两项平衡，得到均摊时间复杂度

$$
O(n\sqrt{q})
$$

当 $q$ 与 $n$ 同阶时退化为 $O(n\sqrt{n})$。这一根号复杂度相当优秀且不会退化，通常可通过 $10^5$ 量级的数据。

空间复杂度为 $O(n+q)$：原数组 $O(n)$，询问数组与答案数组各 $O(q)$。

## 适用场景

普通莫队适用于满足以下条件的**离线区间查询**：

- 所有询问可在回答前一次性读入并重排，不要求强制在线；
- 区间答案可增量维护，即从 $[l, r]$ 转移到相邻区间只需 $O(k)$ 更新，且 $k$ 通常为 $O(1)$ 或 $O(\log n)$；
- 数据规模约 $10^5$，排序与根号级指针移动可在时限内完成。

只要 `add` / `del` 能以较小代价维护区间答案（如区间元素计数、统计出现次数、维护区间和等增量可加信息），即可套用莫队。反之，若加入或删除单个元素的代价高于 $O(\log n)$，或查询必须在线回答，则不适合直接使用普通莫队。

## 常见陷阱与注意事项

- **只能离线**：莫队必须先拿到全部询问才能重排顺序，无法处理强制在线的场景。
- **`add` / `del` 必须足够快**：它们是莫队的前提，单次代价过高会使根号复杂度的常数爆炸，失去意义。
- **块长不是固定 $\sqrt{n}$**：一般最优块长 $B=\sqrt{\dfrac{n^2}{q}}$，仅当 $q$ 与 $n$ 同阶时才退化为 $\sqrt{n}$；查询稀疏时仍用固定 $\sqrt{n}$ 反而更慢。
- **排序必须按 $(b_l, r)$ 两个关键字**：只按 $l$ 升序、$r$ 升序的朴素贪心可被构造数据卡成 $O(n^2)$；配合奇偶化排序还能减少右指针折返。
- **指针移动先扩展后收缩**：否则可能出现 $L > R$，导致 `Del` 移除区间外的元素，产生错误答案。
- **答案写回原始位置**：排序打乱查询顺序后，必须用 `q[i].id` 把答案写回 `ans` 的原始下标，漏写会导致输出顺序错乱。

## 对比与扩展

- **普通莫队 vs 带修莫队**：普通莫队只能处理静态区间查询。当区间支持修改（如单点改色，见洛谷 P1903）时，普通莫队不再可做，需把修改也离线下来，给每个询问增加时间维 $t$，得到三元组 $(l, r, t)$，并按其所在块号三关键字排序。带修莫队多了时间维度，块长取 $n^{2/3}$，复杂度升至 $O(n^{5/3})$；其维护的修改操作必须满足可撤销性，且应用与撤销均为 $O(1)$。
- **普通莫队 vs 回滚莫队**：当删除操作难以 $O(1)$ 维护时，改用回滚莫队，只做扩展不做收缩，在块间通过回滚恢复状态，从而规避删除的困难。
