## 算法原理

在程序里表示一张图，需要把「顶点集合」和「边集合」落到具体的数据结构上。OI 中常用的存图方式有四种，核心取舍在于**查一条边是否存在的速度**与**空间消耗**之间的权衡，以及是否方便遍历某个点的所有出边。

设图有 $n$ 个顶点、$m$ 条边，$d(u)$ 表示顶点 $u$ 的度数（出边数）。四种方式分别是：

- **直接存边**：把所有边平铺进一个数组，每条边记录两个端点与权值（如果有）。
- **邻接矩阵**：用二维数组 $\text{adj}[i][j]$ 表示从 $i$ 到 $j$ 是否有边（或边权）。
- **邻接表**：用「数组 + 链表 / vector」存每个点出发的所有边。
- **链式前向星**：本质是用数组模拟单向链表实现的邻接表，比 vector 版邻接表更省内存、常数更小。

## 核心公式 / 状态定义与转移方程

图的存储属于「数据结构选择」问题，没有状态转移方程；它的核心刻画是各方式的空间与查询复杂度。设 $n$ 为顶点数、$m$ 为边数、$d(u)$ 为顶点 $u$ 的度数：

- 直接存边：空间 $O(m)$；查询两点是否有边需遍历全部边，为 $O(m)$。
- 邻接矩阵：空间 $O(n^2)$；查询边 $(i,j)$ 是否存在为 $O(1)$；遍历点 $i$ 的所有出边需扫一整行，为 $O(n)$。
- 邻接表 / 链式前向星：空间 $O(n+m)$；查询边需遍历出边链表，为 $O(d(u))$；遍历出边也是 $O(d(u))$。

## 逐行代码解析

本节给出四种存图方式的**伪代码 / 思想步骤**，用于说明数据结构形态，不要求与任何完整程序一一对应。

### 直接存边

```cpp
struct Edge { int u, v, w; };  // 一条边：起点 u、终点 v、权值 w
vector<Edge> edges;            // 所有边平铺存储
```

思想步骤：

1. 读入每条边，把它追加进 `edges`。
2. 需要遍历所有边时，直接 `for (auto e : edges)`。
3. 若要判断两点是否相连，只能遍历整个数组逐一比对。

### 邻接矩阵

```cpp
int adj[N][N];  // adj[i][j]：从 i 到 j 的边权；0 表示无边
```

思想步骤：

1. 建图时令 `adj[u][v] = w`。
2. 查询 $(u,v)$ 是否有边：直接读 `adj[u][v]`，$O(1)$。
3. 遍历点 $u$ 的所有出边：枚举 $j = 0 \dots n-1$，若 `adj[u][j]` 非零则是一条出边。

### 邻接表

```cpp
vector<pair<int, int>> adj[N];  // adj[i] 存从 i 出发的边，first 是终点，second 是边权
// 不存边权时可简化为 vector<int> adj[N];
```

思想步骤：

1. 加边时执行 `adj[u].push_back({v, w})`（无向图再反向加一次）。
2. 遍历点 $u$ 的所有出边：`for (auto [v, w] : adj[u])`。
3. 只存实际存在的边，适合稀疏图。

### 链式前向星

```cpp
struct Edge { int to, w, next; } edge[M];  // next 指向同一起点的下一条边
int head[N], tot;                           // head[i] 存 i 的第一条出边在 edge 中的下标

void add(int u, int v, int w) {
    edge[++tot] = {v, w, head[u]};          // 新边插到链表头部
    head[u] = tot;
}
```

思想步骤：

1. 每加一条边就「头插」到 `head[u]` 指向的链表上。
2. 遍历点 $u$ 的所有出边：

```cpp
for (int i = head[u]; i; i = edge[i].next) {
    int v = edge[i].to, w = edge[i].w;
    // 处理边 u -> v
}
```

3. 用数组下标模拟指针，避免 vector 扩容与动态分配的开销。

## 复杂度分析

设 $n$ 为顶点数、$m$ 为边数、$d(u)$ 为顶点 $u$ 的度数。四种方式的复杂度对比如下：

| 存储方式 | 空间 | 查询两点是否有边 | 遍历点 $u$ 的出边 |
|---|---|---|---|
| 直接存边 | $O(m)$ | $O(m)$ | $O(m)$ |
| 邻接矩阵 | $O(n^2)$ | $O(1)$ | $O(n)$ |
| 邻接表 | $O(n+m)$ | $O(d(u))$ | $O(d(u))$ |
| 链式前向星 | $O(n+m)$ | $O(d(u))$ | $O(d(u))$ |

由于四种方式各有取舍，不存在统一的「一个算法」复杂度，因此 frontmatter 中复杂度记作「视具体实现」：实际使用时按上表选择对应的空间与查询复杂度。

## 适用场景

- **直接存边**：需要直接基于「边」来操作、或要按边权排序的算法，典型如 Kruskal 求最小生成树。
- **邻接矩阵**：$n$ 很小（如 $n \le 200$）且需要频繁查询两点间边，或需要全源最短路（如 Floyd）。
- **邻接表**：绝大多数情况的首选，适合稀疏图，Dijkstra、SPFA、DFS、BFS 等通用场景都适用。
- **链式前向星**：对性能要求高、或 vector 被卡常的题目。

考场建议：无脑用**邻接表（vector 版）**基本不会错；当 $n$ 很大（如 $10^6$）或 vector 被卡常时，再换成**链式前向星**。邻接矩阵只在 $n \le 200$ 且需要全源最短路时用，直接存边只在 Kruskal 一类按边操作时用。

## 常见陷阱与注意事项

- **邻接矩阵空间爆炸**：空间为 $O(n^2)$，$n$ 稍大（如 $n > 5000$）内存就会溢出，务必只在 $n$ 很小时使用。
- **无向图要加两次边**：邻接表与链式前向星存无向图时，$(u,v)$ 与 $(v,u)$ 都要各加一次，边数组要开到 $2m$ 大小。
- **链式前向星遍历顺序与插入顺序相反**：因为采用「头插」，遍历出的出边顺序与加边顺序相反；若题目对边顺序敏感需注意。
- **不要把查询复杂度当成 $O(1)$**：邻接表查询两点是否有边是 $O(d(u))$，只有邻接矩阵才是 $O(1)$。
- **重边与自环的语义差异**：邻接矩阵会天然「覆盖」重边（只保留最后写入的一条），邻接表 / 直接存边会保留全部；处理带重边的问题时要注意二者语义不同。

## 对比与扩展

- **邻接表 vs 链式前向星**：二者都是「每个点挂出边链表」，复杂度一致；链式前向星用数组模拟链表、常数更小，但写法更繁琐；vector 版邻接表可读性更好、调试更友好。
- **邻接矩阵 vs 邻接表**：矩阵以空间换「$O(1)$ 查边」，适合稠密图与小规模全源最短路；邻接表以「$O(n+m)$ 空间」换稀疏图的高效遍历。
- **扩展方向**：图的存储是后续所有图论算法（最短路、最小生成树、连通分量、网络流等）的公共基础，选择正确的存图方式能显著影响常数与代码复杂度。进阶题目里还可能出现「按边存 + 排序」「邻接表 + 反向图（用于强连通分量、DAG 最短路）」「vector 前向星混合」等变体。
