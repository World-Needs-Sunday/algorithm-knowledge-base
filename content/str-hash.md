## 算法原理

字符串哈希的核心思想是将字符串映射为一个整数，通过比较整数来替代逐字符比较。多项式滚动哈希把长度为 $n$ 的字符串 $s$ 视为一个 $p$ 进制数，每一位字符的 ASCII 值充当该进制的"数字"，整个字符串的多项式求值结果即为哈希值。由于不同字符串对应不同多项式值的概率极高（在合理选取基数和模数的前提下），这种映射可以在极低冲突率下实现 $O(1)$ 的子串等价判定。

为了支持任意子串的快速哈希查询，算法引入前缀哈希数组 `sum` 和基数幂次数组 `P`。前缀哈希 `sum[i]` 记录前 $i$ 个字符的多项式值，幂次数组 `P[i]` 预存 $q^i$。查询子串 $s[l..r]$ 的哈希时，只需将 `sum[l-1]` 左移（乘以）$q^{r-l+1}$ 对齐到与 `sum[r]` 相同的位权，再做减法即可。这一"高位对齐"技巧是前缀哈希能在 $O(1)$ 内求出子串哈希的关键。

本代码采用 `unsigned long long`（64 位无符号整数）存储哈希值，利用其自然溢出实现对 $2^{64}$ 取模的效果。这种做法省去了显式的取模运算（`%`），在常数上比显式取模更快，是竞赛中常见的写法。代价是模数固定为 $2^{64}$，存在被构造数据针对（如 Thue-Morse 串反哈希）的风险，在对抗性较强的场景中需考虑双哈希。

## 核心公式

前缀哈希递推：
$$\text{sum}[i+1] = \text{sum}[i] \times q + s[i] \pmod{2^{64}}$$

展开后的前缀哈希通项：
$$\text{sum}[i] = \sum_{j=1}^{i} s[j] \times q^{i-j} \pmod{2^{64}}$$

幂次数组递推：
$$P[i] = P[i-1] \times q, \quad P[0] = 1$$

子串 $s[l..r]$ 的哈希值（高位对齐后相减）：
$$H(l, r) = \text{sum}[r] - \text{sum}[l-1] \times P[r-l+1] \pmod{2^{64}}$$

## 逐行代码解析

```cpp
#include<bits/stdc++.h>
using namespace std;
const int q = 131;          // 进制基数，经验值取质数冲突率低
const int nmax = 10010;
vector<unsigned long long>P;
vector<unsigned long long> sum;

// 查询子串 s[l..r] 的哈希值（下标从 1 开始）
unsigned long long getstr(int l , int r)
{
	return sum[r] - sum[l - 1] * P[r - l + 1];
}

int main()
{
	string str;
	cin >> str;
	sum.resize(str.size() + 1 , 0);   // sum[0]=0，sum[i] 对应前 i 个字符
	P.resize(str.size() + 1 , 1);     // P[0]=1

	// 预处理前缀哈希：sum[i+1] = sum[i]*q + str[i]
	for(int i = 0;i < str.size();i++)
		sum[i + 1] = sum[i] * q + (unsigned long long)str[i];

	// 预处理幂次：P[i] = P[i-1] * q
	for(int i = 1;i <= str.size();i++) P[i] = P[i - 1] * q;

	int k;
	cin >> k;
	for(int i = 0;i < k;i++)
	{
		int l , r;
		cin >> l >> r;
		cout << getstr(l,r) << endl;  // O(1) 输出子串哈希
	}
	return 0;
}
```

**关键解析：**

- `const int q = 131`：进制基数选 131（或 13331）这类大于字符集范围的质数，能降低不同字符串映射到同一哈希值的概率。字符 ASCII 范围为 0\~127，基数 131 保证每个字符在该进制下"位权"不产生歧义。
- `sum` 与 `P` 使用 `unsigned long long`：乘法溢出时自动对 $2^{64}$ 取模，等价于 `result % (2^64)` 但无需显式 `%` 运算，速度更快。
- `getstr(l, r)` 中的 `sum[l-1] * P[r-l+1]`：将前 $l-1$ 个字符的哈希值"左移" $r-l+1$ 位（乘以 $q^{r-l+1}$），使其位权与 `sum[r]` 对齐。两者相减后，剩余部分恰好是子串 $s[l..r]$ 的多项式值。
- 下标从 1 开始：`sum[0] = 0` 作为哨兵，保证当 $l=1$ 时 `sum[l-1] = sum[0]` 合法，无需特殊处理边界。

## 复杂度分析

预处理阶段需遍历字符串一次计算 `sum` 数组，再遍历一次计算 `P` 数组，每次仅做一次乘法和一次加法，因此预处理时间为 $O(n)$。每次查询 `getstr` 仅涉及一次乘法和一次减法，为 $O(1)$。空间上 `sum` 和 `P` 各需 $O(n)$，总空间复杂度为 $O(n)$。在需要 $k$ 次查询的场景下，总时间为 $O(n + k)$，远优于暴力逐字符比较的 $O(n \cdot k)$。

## 适用场景

子串匹配与去重（判断两子串是否相同）、Rabin-Karp 字符串匹配、回文判定（正反哈希比对）、重复子串检测、字符串集合判重等。是字符串处理中最基础也最高效的工具之一。

## 常见陷阱与注意事项

1. **哈希冲突**：单哈希（尤其是模 $2^{64}$）可被构造数据针对。安全场景下建议使用双哈希（两组不同基数和质数模数，如 $10^9+7$ 与 $10^9+9$），将冲突概率降至 $O(1/M_1 M_2)$。
2. **基数选择**：基数应大于字符集大小且最好为质数。若基数小于 128，则 ASCII 值可能超过基数导致"进位歧义"（如 `'a'` = 97，若 $q=10$ 则多位混淆）。
3. **自然溢出的安全风险**：模 $2^{64}$ 不是质数，存在结构性弱点。Thue-Morse 串等特殊构造可使 $2^{64}$ 模哈希产生大量冲突，比赛中遇到hack时需改用质数模数。
4. **下标越界**：`sum[l-1]` 当 $l=1$ 时访问 `sum[0]`，必须保证数组从 0 开始且初始化为 0，否则读取到未定义值。
5. **子串长度为 0**：当 $l > r$ 时公式仍会返回值但无意义，调用前应确保 $l \le r$。
6. **大写/小写与编码**：直接用 `str[i]` 作为"数字"时，大小写字母 ASCII 值不同但可能产生非预期行为，需根据题目统一编码。

## 对比与扩展

与 KMP 算法相比，字符串哈希实现更简洁、支持任意子串 $O(1)$ 比较，但存在冲突概率（KMP 是精确匹配无冲突）。与后缀数组/后缀自动机相比，哈希不支持直接求 LCP（最长公共前缀），但可通过二分 + 哈希在 $O(\log n)$ 内求 LCP。扩展方向包括：双哈希提升安全性、结合二分解决最长回文子串 / 最长重复子串等 $O(n \log n)$ 问题、以及用于 Rabin-Karp 多模式匹配。
