## 算法原理

**一句话结论**：Manacher（马拉车）通过一次「插 #」预处理把奇偶回文统一成奇数回文，再借助「已探明的最右回文」的对称性给每个中心一个保底半径，只在未知区域暴力扩展，从而在线性时间内求出最长回文子串。

**解决的问题**：给定字符串 $s$，求它的最长连续回文子串长度。

**奇偶回文的痛点**：回文串的中心有两种形态——奇数回文（如 `aba`）中心是一个字符，偶数回文（如 `abba`）中心是两个字符之间的空隙。如果直接遍历中心，就要分两种情况写代码。预处理就是为了消灭这种分支。

**预处理（统一化）**：在每个字符之间以及两端插入特殊字符 `#`：`123456` 变成 `#1#2#3#4#5#6#`。改造后有三个关键性质：

1. 无论原串奇偶，改造后的串长度恒为 $2n+1$（奇数），所有回文的中心一定落在某个具体字符上；
2. 若以第 $j$ 位为中心的回文半径为 $p[j]$（含中心自身），则对应的原串回文长度为 $p[j] - 1$，所以最后答案是 $\max p[j] - 1$；
3. 原串的每个奇数/偶数回文都与改造串的某个中心一一对应，信息没有丢失。

**哨兵**：代码把改造串写成 `t = "~#" + s 的插井号版本`，最前面的 `~` 是哨兵——它不在原串中出现，`while` 向左扩展碰到它就必然失配，省掉左侧越界判断。右侧没有哨兵，但依靠 `std::string` 在 `operator[]` 取 `pos == size()` 时返回 `'\0'` 这一特性自然停住（`'\0'` 与任何实际字符都不相等）。

**核心思想（线性时间怎么来的）**：维护「目前已探明的最右回文」——右端下标 $r$ 及其中心 $mid$。处理新中心 $i$ 时：

- 若 $i \le r$，则 $i$ 关于 $mid$ 的镜像点 $j = 2 \times mid - i$ 已经算过了。由对称性，$i$ 的回文半径至少有 $p[j]$ 起步；但借来的信息不能越过右边界 $r$，所以保底值是 $\min(p[j], r - i + 1)$。
- 在此保底之上，`while` 只对「真正未知」的区域一左一右暴力比对。
- 每次 `while` 比对成功，$r$ 就右移一格；$r$ 只增不减、最多移动到串尾，所以全程比对总次数是 $O(n)$，其余操作每轮 $O(1)$。

**为什么这样做是对的**：不变量是「$[mid - (p[mid]-1),\ r]$ 这一段关于 $mid$ 对称，且 $r$ 是已探明回文的最右端」。当 $i \le r$ 时，把 $p[j]$ 和 $r-i+1$ 取小作为起步值，得到的半径一定不超过真实半径（对称部分必然相等，只是再往外是否相等未知），因此不会漏扩；`while` 在此基础上逐格验证未知区，算出的 $p[i]$ 就是真实半径。每轮结束后若 $i + p[i] - 1 > r$，就更新 $r$、$mid$ 使不变量继续成立。归纳到底，所有 $p[i]$ 都被正确算出，$\max p[i] - 1$ 即最长回文子串长度。

## 核心公式 / 状态定义与转移方程

**状态定义**：

- $p[i]$：以改造串 $t[i]$ 为中心的回文半径（含中心自身）；
- $r$：目前所有已算回文串中，右端下标的最大值；
- $mid$：对应这个 $r$ 的中心下标；
- $ans$：过程中出现的最大 $p[i]$。

**预处理公式**：$t = \verb|~#| + s[0] + \verb|#| + s[1] + \verb|#| + \cdots + s[n-1] + \verb|#|$，长度 $2n+2$；圆括号里 $t$ 的有效下标是 $0 \sim 2n+1$，中心 candidate 从下标 1 开始。

**转移方程**（对每个中心 $i = 1, 2, \dots$）：

1. 保底：

```text
if (i <= r) p[i] = min(p[mid * 2 - i], r - i + 1);
```

其中 $j = mid \times 2 - i$ 是 $i$ 关于 $mid$ 的镜像点。$p[j]$ 是镜像处的已知半径；$r-i+1$ 是「不超过已知右边界」时能保证的最大半径。两者取小：镜像回文太短则全盘继承（情况 A），镜像回文超出已知范围则只能继承到 $r$ 为止（情况 B）。

2. 扩展：`while (t[i - p[i]] == t[i + p[i]]) ++p[i];` —— 在保底之上比对未知区域，直到失配或碰到哨兵。

3. 更新：若 `p[i] + i > r`，说明找到了更靠右的回文，令 `r = p[i] + i - 1`、`mid = i`。

4. 答案：`ans = max(ans, p[i])`，最终返回 `ans - 1`。

**手算示例**：$s = \verb|aba|$，改造后 $t = \verb|~#a#b#a#|$，下标 $0 \sim 7$。

| 中心 i | 初始 p[i]（min 保底） | while 扩展 | 最终 p[i] | r / mid 更新 |
|---|---|---|---|---|
| 1 | 0（i > r） | t[1] 与自身相等 → 1，t[0]='~' 与 t[2]='a' 失配 | 1 | r=1, mid=1 |
| 2 | 0（i > r） | t[1]='#'==t[3]='#' → 2，t[0]='~' 与 t[4]='b' 失配 | 2 | r=3, mid=2 |
| 3 | min(p[1], 1)=1 | t[2]='a' 与 t[4]='b' 失配 | 1 | r=4, mid=3 |
| 4 | min(p[2], 1)=1 | t[3]=t[5]→2，t[2]=t[6]→3，t[1]=t[7]→4，t[0]='~' 与 t[8] 失配 | 4 | r=7, mid=4 |
| 5 | min(p[3], 3)=1 | t[4]='b' 与 t[6]='a' 失配 | 1 | 无 |
| 6 | min(p[2], 2)=2 | t[4]='b' 与 t[8] 失配 | 2 | 无 |
| 7 | min(p[1], 1)=1 | t[6]='a' 与 t[8] 失配 | 1 | 无 |

$ans = 4$（中心在 $t[4]$，即原串的 `b`），返回 $4 - 1 = 3$，正是 `aba` 的长度。

再看偶数例子 $s = \verb|abba|$：$t = \verb|~#a#b#b#a#|$，中心落在两个 `b` 之间的 `#`（$t[5]$），扩展出 $p[5] = 5$，返回 $5 - 1 = 4$。预处理让偶数回文和奇数回文走完全相同的流程。

## 逐行代码解析

代码拆成 3 个模块，按顺序拼接即完整程序。

### 模块 1 预处理

```cpp
#include<bits/stdc++.h>
using namespace std;
int manacher(const string& s)
{
	string t = "~#";
	t.reserve(s.size() * 2 + 2);
	for (char ch : s)
	{
		t += ch;
		t += '#';
	}

```

- `t = "~#"`：`~` 是左哨兵，`#` 是第一个分隔符。
- `reserve(s.size() * 2 + 2)`：改造后长度正好是 $2n+2$，一次分配避免 `+=` 反复扩容。
- 循环里每个字符后接一个 `#`：`s[0]#s[1]#...#`，保证每个原字符右侧都有一个分隔符，且整串长度恒为奇数。

### 模块 2 核心循环

```cpp
	int r = 0, mid = 0, ans = 0;
	vector<int> p(t.size(), 0);
	for (int i = 1; i < t.size(); i++)
	{
		if (i <= r) p[i] = min(p[mid * 2 - i], r - i + 1);
		while (t[i - p[i]] == t[i + p[i]]) ++p[i];
		if (p[i] + i > r)
		{
			r = p[i] + i - 1;
			mid = i;
		}
		ans = max(ans, p[i]);
	}
	return ans - 1;
}
```

- 循环从 $i=1$ 开始：下标 0 是哨兵，不可能作为回文中心，跳过。
- `if (i <= r)` 是「能否借历史信息」的分界：$i$ 在已知最右回文内部才能用镜像保底，否则 $p[i]$ 保持 0 从零暴力扩展。
- `p[mid * 2 - i]` 计算镜像点 $j$：由 $i - mid = mid - j$ 推出 $j = 2 \times mid - i$。
- `r - i + 1` 把保底限制在已知边界内：$i$ 在 $r$ 内的部分关于 $mid$ 必然对称，越出 $r$ 的部分没有任何保证。
- `while (t[i - p[i]] == t[i + p[i]])`：向左向右各看一格；左侧最终碰到 `~` 失配，右侧最终碰到串尾的 `'\0'` 失配，天然终止，无需手写边界判断。
- `r = p[i] + i - 1`：注意减一。$p[i]$ 是含中心的半径，右端下标 = 中心 + 半径 − 1。
- 返回 `ans - 1`：改造串半径到原串长度的换算（含中心的半径比原回文长度多 1）。

### 模块 3 主函数

```cpp
int main()
{
	ios::sync_with_stdio(false);
	cin.tie(nullptr); cout.tie(nullptr);
	string s;
	cin >> s;
	cout << manacher(s);
	return 0;
}
```

- 常规读入提速后读整串、调用 `manacher`、输出答案。
- 本模板解决「单串最长回文子串长度」；若要输出子串本身，记录 `ans` 对应的中心 $i$，还原 $s$ 中区间 $[(i - p[i]) / 2,\ (i + p[i] - 3) / 2]$ 即可。

## 复杂度分析

- **时间**：$O(n)$，$n$ 为原串长度。外层循环 $2n+1$ 轮，每轮除 `while` 外都是 $O(1)$；`while` 的总比对次数是关键——每次比对成功，$r$ 右移 1 格，$r$ 最大到 $2n+1$；每次 `while` 结束时至多一次失败比对，失败次数受循环轮数 $O(n)$ 限制。所以总时间严格 $O(n)$，而朴素中心扩展是 $O(n^2)$。
- **空间**：$O(n)$。$t$ 长 $2n+2$，$p$ 长 $2n+2$，无其他额外开销。

## 适用场景

- **单串最长回文子串**：Manacher 是线性时间的最优解，模板题直接套用（返回 `ans - 1`）。
- **回文半径数组的衍生应用**：以每个位置为中心的最长回文、回文子串计数、判断某位置是否被足够长的回文覆盖（差分前缀和技巧与 $p$ 数组结合）、双倍回文类问题（如洛谷 P4555）。
- **不要用**：多次询问「任意下标区间是否回文」时，预处理正反哈希 $O(1)$ 判定更合适，Manacher 只有中心信息、不便应答任意区间；字符串极短或只需要一次结果时，朴素 $O(n^2)$ 中心扩展代码更简单，Manacher 的细节多、易写错。

## 常见陷阱与注意事项

1. **返回时忘记 `-1`**：改造串半径 = 原回文长度 + 1，直接返回 `ans` 会比正确答案多 1。
2. **半径语义混淆**：$p[i]$ 含中心自身；右端下标是 $i + p[i] - 1$，不是 $i + p[i]$，`r` 更新时错一个常数会破坏镜像借用。
3. **镜像公式写错**：镜像点必须是 $j = mid \times 2 - i$；写成 $2 \times (mid - i)$ 或 $mid - (i - mid)$ 之外的形态都会借错对象。
4. **`min` 的两个参数位置/含义混淆**：第二参数是 $r - i + 1$（到已知右边界为止的可保证长度），漏了它或把它换成 $r - i$ 都会让半径越过未知区域，产生错误结果。
5. **漏左哨兵**：没有 `~` 时 `while` 向左会在 $i = p[i]$ 时访问负下标，是未定义行为；右端没有哨兵，程序依赖 `std::string` 的 `t[t.size()]` 返回 `'\0'` 的特性停住——若自己改成字符数组实现，要另加右哨兵。
6. **循环起点错**：写成 `i = 0` 会把哨兵当中心；正确起点是 `i = 1`。
7. **预处理漏掉结尾 `#`**：每个字符后接 `#` 但丢末尾一个时，偶数回文以两个字符间的 `#` 为中心仍可行，但长度奇数性质破坏、边界位缺失，容易在最后一个字符处出错——按「先放 `~#`、再逐字符 `ch + '#'`」的写法能自动补全。
8. **多组数据不重置**：$p$、$r$、$mid$、$ans$ 每次进入 `manacher` 都是局部新建的，所以单函数复用没问题；但若把 $p$ 提成全局复用数组，就要记得清空。
9. **只想要长度却拿半径当答案**：给出「以某位置为中心的回文长度」这类需求时，注意答案问的是原串长度还是含 `#` 的半径，单位不同差 1 倍左右。

## 对比与扩展

**与其他求最长回文子串的做法对比**：

| 做法 | 时间 | 空间 | 特点 |
|---|---|---|---|
| 朴素中心扩展 | O(n^2) | O(1) | 代码最短，中心两种分类烦 |
| 区间 DP | O(n^2) | O(n^2) | 思路直观，能吃 O(n^2) 的数据 |
| Manacher（本算法） | O(n) | O(n) | 线性最优，细节多易写错 |
| 哈希 + 二分 | O(n log n) | O(n) | 通用性好，常数比 Manacher 大 |

**扩展思路**：

- **双倍回文（P4555）**：在 Manacher 的 $p$ 数组基础上做预处理与维护，求由两个相邻回文串拼接而成的最长「双倍回文」。
- **回文划分 DP 的加速**：判断任意区间是否回文时，Manacher 的 $p$ 数组 + 差分可以把「区间回文判定」压到 $O(1)$ 预处理之后使用，作为回文串分割类 DP 的预处理部件；
- **只判回文**：字符串哈希正反各预处理一遍，任意区间的回文判定为 $O(1)$，在读入后大量随机询问的场景下比 Manacher 更顺手的替代方案。
