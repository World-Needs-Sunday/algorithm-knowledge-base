## 算法原理

Borůvka 算法是求解**最小生成树**（Minimum Spanning Tree, MST）的经典算法，也是历史上最早提出的 MST 算法之一。与 Kruskal 的"全局最小边优先"、Prim 的"从一点向外扩展"不同，Borůvka 采用**多路并行收缩**的策略：每一轮让当前每个连通块**同时**选出自己连向其他连通块的最小边，然后把所有选中的边一次性加入生成树，使多个连通块合并成更大的连通块。

核心过程（初始时每个节点自成一个连通块）：

1. 对每个连通块，扫描所有边，找出它连向"外部"（即另一个连通块）的**最小边**；
2. 将所有连通块选出的最小边**同时**加入生成树，并用并查集把对应端点合并；
3. 由于每个连通块都会通过一条最小出边与至少另一个块合并，连通块数量每轮**至少减半**；
4. 重复上述过程，直到只剩一个连通块，得到最小生成树。

**正确性**：每个连通块与"其余部分"构成一个**切**，该连通块选出的最小出边正是横跨这个切的最小边。由切定理（Cut Property），横跨切的最小边一定属于某棵最小生成树，因此每轮选出的边都可以被安全加入，最终必然得到 MST。

**复杂度思想**：连通块数每轮至少减半，因此至多 $O(\log n)$ 轮；每轮扫描全部 $m$ 条边，故总复杂度为 $O(m \log n)$。

## 核心公式 / 状态定义与转移方程

### 状态定义

$$\text{fa}[i] = \text{节点 } i \text{ 在并查集中的父节点（根代表其所在连通块）}$$

$$\text{best}[r] = \text{当前轮中，以根 } r \text{ 为代表的连通块连向其他连通块的最小边权，初始为 } +\infty$$

$$\text{bestEdge}[r] = \text{当前轮中连通块 } r \text{ 选出的最小出边}$$

### 每轮扫描：求每个块的最小出边

对每条边 $(u, v, w)$，先求其端点所在连通块的根：

$$r_u = \text{find}(u), \qquad r_v = \text{find}(v)$$

若 $r_u \neq r_v$（该边连接两个不同连通块），则同时更新两端连通块的最小出边：

$$\text{best}[r_u] = \min(\text{best}[r_u],\ w), \qquad \text{best}[r_v] = \min(\text{best}[r_v],\ w)$$

### 合并转移

对每个仍存在最小出边的连通块，将其最小出边的两端点合并，并累加边权：

$$\text{union}(u, v), \qquad \text{ans} \leftarrow \text{ans} + w$$

### 轮数上界

设第 $k$ 轮结束后连通块数为 $C_k$，初始 $C_0 = n$。每个连通块都通过其最小出边与至少一个其他连通块合并，故连通块数至少减半：

$$C_k \le \frac{C_{k-1}}{2} \implies \text{轮数} \le \lceil \log_2 n \rceil$$

### 总复杂度

$$\text{总复杂度} = \text{轮数} \times \text{每轮扫描代价} = O(\log n \cdot m) = O(m \log n)$$

## 逐行代码解析

Borůvka 算法在朋友资料中未给出完整代码，以下是其核心过程的伪代码。

### 第 1 段：初始化与主循环框架

```cpp
// 伪代码：初始化
for i in 1..n:
    fa[i] = i              // 每个节点自成一个连通块
ans = 0                    // 最小生成树边权和
while 连通块数量 > 1:
    for 每个根 r:
        best[r] = INF      // 本轮到其他连通块的最小出边权
        bestEdge[r] = 空   // 对应的最小出边
```

- **`fa`**：并查集父节点数组，初始每个点指向自己，代表 $n$ 个独立的连通块。
- **`ans`**：MST 边权和，随合并不断累加。
- **每轮开始先清空 `best` / `bestEdge`**：因为它们只记录"当前轮"的最小出边，下一轮连通块已变化，必须重新计算。
- **循环终止条件**：连通块数量降到 $1$，说明所有点已连通，MST 完成。

### 第 2 段：扫描所有边，为每个块求最小出边

```cpp
    // 扫描所有边，为每个连通块找最小出边
    for 每条边 (u, v, w):
        ru = find(u); rv = find(v)
        if ru != rv:                    // 该边连接两个不同连通块
            if w < best[ru]:
                best[ru] = w; bestEdge[ru] = (u, v)
            if w < best[rv]:
                best[rv] = w; bestEdge[rv] = (u, v)
```

- **`find` 判断两端点是否同块**：`ru != rv` 说明边 $(u,v)$ 跨两个连通块，才可能是某块的最小出边；同块内部的边直接跳过。
- **双向更新**：一条跨块边对两个端点所在的连通块都是候选出边，因此 `best[ru]` 和 `best[rv]` 都要尝试更新。
- **取 $\min$**：一个连通块可能有多条出边，只保留权值最小的一条。
- **复杂度**：这一轮扫描所有 $m$ 条边，每次 `find` 均摊 $O(\alpha(n))$，故一轮为 $O(m)$。

### 第 3 段：同时合并所有选出的最小出边

```cpp
    // 把所有连通块选出的最小出边同时加入生成树
    for 每个连通块（以根 r 为代表）:
        if best[r] != INF:
            (u, v, w) = bestEdge[r]
            if find(u) != find(v):      // 可能已被其他块提前合并
                union(u, v)
                ans += w
                连通块数量 -= 1
```

- **只有存在最小出边的块才参与合并**：`best[r] == INF` 表示该块没有连向其他块的边，说明图不连通，无生成树。
- **合并前再次 `find` 判重**：两个连通块可能互相选中同一条边，或某块已被本轮其他合并先收缩，因此合并前必须确认两端点仍不在同一块，避免重复累加边权。
- **"同时"加入**：先整体扫出每块的最小出边，再统一合并，是本轮收缩的语义；若边扫边合并会破坏"每个块的最小出边"这一轮的定义。
- **连通块数减半**：每个有出边的块都会与至少另一个块合并，因此本轮结束时连通块数量至多减半。

## 复杂度分析

### 时间复杂度

| 阶段 | 复杂度 |
|---|---|
| 并查集初始化 | $O(n)$ |
| 每一轮扫描全部边 | $O(m)$ |
| 每一轮合并 | $O(n)$ |
| 轮数 | $O(\log n)$ |
| **总计** | $O(m \log n)$ |

每轮连通块数至少减半，故最多进行 $O(\log n)$ 轮；每轮需扫描全部 $m$ 条边并做 $O(1)$ 均摊的并查集操作，总时间复杂度为 $O(m \log n)$。

### 空间复杂度

| 数据结构 | 空间 |
|---|---|
| 边集存储 | $O(m)$ |
| 并查集 `fa` | $O(n)$ |
| 最小出边数组 `best` / `bestEdge` | $O(n)$ |
| **总计** | $O(n + m)$ |

## 适用场景

- **常规题目中较少使用**：Borůvka 在一般 MST 题目里不如 Kruskal（实现简单）或 Prim（稠密图友好）常用，因此普通求 MST 优先考虑前两者。
- **完全图 / 稠密到无法显式存边的图**：当 $m \approx n^2$ 甚至边无法全部显式列出时，Borůvka 的"每轮扫一遍候选"框架可以配合数据结构，只处理"可能成为最小出边"的少数边，从而避免 $O(n^2)$ 甚至更大的枚举。
- **边权由某种规则动态生成的图**：若边权不是显式给出，而是由节点编号、坐标、函数等规则计算得到，可以在每轮扫描时按需计算候选边权，Borůvka 天然适合这种"边在需要时才生成"的场景。
- **结合数据结构优化的 MST**：例如完全图上用 Borůvka 每轮为每个连通块求最小出边时，可借助线段树、堆、分治等结构把单轮降到 $O(n \log n)$ 或 $O(n)$，总复杂度优于直接枚举。
- **需要并行或分层的场景**：每轮各连通块相互独立地选最小出边，天然适合并行处理。

## 常见陷阱与注意事项

1. **每轮必须重新初始化最小出边数组**
   - `best` / `bestEdge` 只对应当前轮，上一轮的值已失效（连通块已经变化）。若不清空会导致沿用旧边、错误合并。

2. **跨块边要双向更新**
   - 一条边 $(u,v,w)$ 对 $u$ 和 $v$ 所在的连通块都是候选出边，只更新一端会漏掉另一块的最小出边。

3. **合并前必须再次判重**
   - 两个连通块可能互相选中同一条边（即同一轮里 $A$ 选 $B$、$B$ 也选 $A$），或某块已被本轮其他合并先收缩。合并前必须再 `find` 一次，确认两端点不在同一块，否则会重复累加边权甚至形成自环。

4. **图不连通的判定**
   - 若某轮存在连通块 `best == INF`（没有连向其他块的边），说明图不连通，不存在最小生成树，应输出无解，而非继续循环。

5. **轮数边界**
   - 连通块数每轮"至少减半"是上界保证，实际轮数可能更少；但需保证循环能正确收敛到只剩一个块，避免死循环或提前退出。

6. **与 Kruskal / Prim 的差异**
   - Borůvka 是"每块同时选最小出边"的并行收缩，不是 Kruskal 的"全局最小边优先"，也不是 Prim 的"从一点扩展"。三者都能得到 MST，但 Borůvka 的价值主要在于特殊图上的可优化性。

## 对比与扩展

### 三种经典 MST 算法对比

| 维度 | Borůvka | Kruskal | Prim |
|---|---|---|---|
| 策略 | 每块同时选最小出边（并行收缩） | 全局最小边优先（边贪心） | 从一点向外扩展最近点（点贪心） |
| 核心数据结构 | 并查集 + 每块最小出边数组 | 并查集 + 边集排序 | 优先队列 / 邻接矩阵 |
| 时间复杂度 | $O(m \log n)$ | $O(m \log m)$ | $O(m \log n)$ / $O(n^2)$ |
| 轮数 / 过程 | $O(\log n)$ 轮，每轮扫全部边 | 排序后一趟选边 | 逐步扩展 $n$ 个点 |
| 稀疏图 | 一般 | 优 | 一般 |
| 稠密图 | 可结合数据结构优化 | 排序开销大 | 矩阵版 $O(n^2)$ |
| 适用场景 | 完全图、边动态生成、需并行 | 常规稀疏图 | 稠密图、有起点要求 |

### 扩展：完全图上的优化

完全图中边数 $m = \frac{n(n-1)}{2}$ 显式存储不可行。Borůvka 每轮只需为每个连通块找到"跨块最小边"，可以按点权、坐标或规则在 $O(n \log n)$ 甚至 $O(n)$ 内完成，从而把整体复杂度压到远低于 $O(n^2)$。这正是朋友资料强调的"完全图、边权由规则动态生成"时 Borůvka 的价值所在。

### 扩展：最小生成森林

图不连通时，Borůvka 的收缩过程自然停在"每个连通分量各成一个块"的状态，即得到最小生成森林，无需额外外层循环。

### 扩展：并行与历史意义

Borůvka 算法（1926 年）早于 Kruskal（1956 年）和 Prim（1957 年），最初用于求解电网的最经济布线问题。其"每块独立选最小出边"的特性使它在并行计算、分布式图处理以及某些离线数据流场景中仍有应用价值。
