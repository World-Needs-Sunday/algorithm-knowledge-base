## 算法原理

### 什么是树的重心

树的重心（Centroid），也叫树的质心，是树中的一个节点。满足：**删掉这个节点后，剩下的各个连通块的大小都不超过整棵树大小的一半**。

换句话说，重心是树中最"居中"的节点——以它为根时，所有子树的大小都不超过 $n/2$。

### 统一符号约定

| 符号 | 含义 |
|------|------|
| $n$ | 整棵树的节点数 |
| $sz[u]$ | 以 $u$ 为根的子树大小 |
| $fa$ | 当前节点的父节点 |
| $v$ | 当前节点的孩子 |
| 孩子方向 | 每个孩子 $v$ 对应的子树，大小为 $sz[v]$ |
| 父亲方向 | 整棵树去掉"以 $u$ 为根的子树"后剩下的部分，大小为 $n - sz[u]$ |

### 核心判断公式

删掉节点 $u$ 后，剩下的连通块分成两类：

1. 每个孩子 $v$ 对应的子树，大小是 $sz[v]$
2. 父亲方向那一块，大小是 $n - sz[u]$

所以，删掉 $u$ 后，最大连通块大小为：

$$
\max\Big(n - sz[u],\ \max_{v \text{ 是 } u \text{ 的孩子}} sz[v]\Big)
$$

如果这个最大值不超过 $n/2$，那么 $u$ 就是树的一个重心。

**重心条件：**

$$
\max\Big(n - sz[u],\ \max_{v \text{ 是 } u \text{ 的孩子}} sz[v]\Big) \le \frac{n}{2}
$$

这是所有求重心方法的共同判断标准。

## 三种求法详解

### 方法一：一次 DFS 回溯判断法

#### 核心思想

在 DFS 过程中，当递归到某个节点 $u$，并且它的所有孩子都已经处理完、准备回溯时：

- 每个孩子的 $sz[v]$ 已经算出来了
- $sz[u]$ 也已经算出来了
- 整棵树大小 $n$ 是已知的
- 父亲方向大小 $n - sz[u]$ 也可以算出来

所以在这个时刻，已经有足够信息判断 $u$ 是不是重心，不需要第二次 DFS。

#### 为什么判断必须在回溯阶段？

刚进入 $u$ 时，孩子的子树还没有被 DFS 处理，$sz[v]$ 还不知道，$sz[u]$ 也还没算完。只有等所有孩子都处理完、准备回溯时，才能知道每个孩子子树多大、以 $u$ 为根的子树多大、父亲方向多大。

**判断时机：处理完所有孩子之后，离开 $u$ 之前。**

#### 算法流程

1. 任选一个节点作为根，比如 1
2. 从根开始 DFS
3. 对于当前节点 $u$：
   - 刚进入时，令 $sz[u] = 1$
   - 遍历所有孩子 $v$：递归 DFS 处理 $v$，回溯回来后 $sz[u] += sz[v]$，同时记录最大的 $sz[v]$（记为 $maxChild$）
   - 所有孩子处理完后：计算 $fatherPart = n - sz[u]$，如果 $\max(maxChild, fatherPart) \le n/2$，则 $u$ 是重心
4. DFS 结束后，记录的节点就是所有重心

#### 优缺点

| 优点 | 缺点 |
|------|------|
| 只需要一次 DFS | 判断放在 DFS 回溯里，初学时容易把时机写错 |
| 时间复杂度 $O(n)$ | 变量多，容易把父亲方向写成 $n - sz[fa]$ |
| 可以找到所有重心 | |
| 思路直接，边算边判断 | |

### 方法二：两次 DFS / 遍历所有节点判断法

#### 核心思想

先做一次 DFS，只求所有节点的子树大小 $sz[u]$。然后遍历每一个节点 $u$，用统一公式判断它是不是重心。

#### 算法流程

1. 任选根，做一次 DFS，求出所有节点的 $sz[u]$ 和 $parent[u]$
2. 遍历所有节点 $u$：
   - 遍历 $u$ 的所有邻居 $v$，如果 $v$ 是孩子（$v \ne parent[u]$），更新 $maxChild$
   - 计算 $fatherPart = n - sz[u]$
   - 如果 $\max(maxChild, fatherPart) \le n/2$，则 $u$ 是重心

#### 优缺点

| 优点 | 缺点 |
|------|------|
| 思路最直观，完全按定义来 | 需要两次扫描：一次 DFS + 一次遍历 |
| 容易理解，容易讲 | 常数比一次 DFS 回溯法稍大 |
| 可以找到所有重心 | |
| 时间复杂度 $O(n)$ | |

> **与方法一的关系**：判断公式完全一样，区别只是判断时机不同。方法一在 DFS 回溯时顺手判断，方法二先全部求完再统一判断。

---

### 方法三：沿重子树移动法

#### 核心思想

先做一次 DFS 求出所有 $sz[u]$。然后从根开始，如果某个孩子 $v$ 满足 $sz[v] > n/2$，说明 $v$ 那边的节点太多，重心一定在 $v$ 的子树里，于是移动到 $v$。重复直到当前节点的所有孩子都满足 $sz[v] \le n/2$，此时停下来的节点就是一个重心。

#### 为什么父亲方向不用检查？

因为一路走下来，当前节点 $c$ 的 $sz[c]$ 一定满足 $sz[c] > n/2$，所以父亲方向大小 $n - sz[c] < n/2$，父亲方向一定不会超过一半，因此只需要检查孩子方向。

#### 算法流程

1. 任选根，做一次 DFS 求所有 $sz[u]$
2. 令当前节点 $cur = root$
3. 检查 $cur$ 的所有孩子 $v$：
   - 如果存在 $v$ 满足 $sz[v] > n/2$，则 $cur = v$，继续检查
   - 如果不存在这样的孩子，停止
4. 停下来的 $cur$ 就是一个重心

#### 优缺点

| 优点 | 缺点 |
|------|------|
| 点分治中非常常用 | 通常只找到一个重心 |
| 只需要一个重心时非常快 | 如果有两个重心，需额外检查 $sz[v] = n/2$ 的孩子 |
| 沿着一条路走，常数小 | 不如方法一、二直观 |
| 时间复杂度 $O(n)$ | |

## 三种方法对比

| 方法 | 扫描次数 | 能否找所有重心 | 适用场景 | 复杂度 |
|------|----------|----------------|----------|--------|
| 一次 DFS 回溯判断 | 1 次 DFS | 能 | 通用，想一次搞定 | $O(n)$ |
| 两次 DFS / 遍历判断 | 1 次 DFS + 1 次遍历 | 能 | 教学，最直观 | $O(n)$ |
| 沿重子树移动 | 1 次 DFS + 沿路移动 | 通常一个 | 点分治 | $O(n)$ |

## 重心的性质

1. 一棵树至少有一个重心，至多有两个重心
2. 如果有两个重心，它们一定相邻
3. 如果有两个重心，它们之间的边会把树分成两个大小各为 $n/2$ 的部分
4. 奇数个节点的树通常只有一个重心
5. 偶数个节点的树可能有两个重心
6. 如果已经找到一个重心 $u$，发现它的某个孩子 $v$ 满足 $sz[v] = n/2$，那么 $v$ 也是重心

## 逐行代码解析

以下代码实现的是**方法一：一次 DFS 回溯判断法**。

```cpp
#include<bits/stdc++.h>
using namespace std;

int n;                        // 树的节点数
vector<vector<int>> edges;    // 邻接表存图
vector<int> ans;              // 存储所有重心

// 初始化：清空答案和邻接表
void init()
{
    ans.clear();
    edges.assign(n + 1, vector<int>());
}

// DFS：返回以 rt 为根的子树大小，同时在回溯时判断 rt 是否为重心
int dfs(int rt, int fa)
{
    int rt_sz = 1;           // 当前子树大小，初始为 1（自己）
    int max_rt = 0, max_sz = 0;  // max_sz：最大孩子子树大小
    for (int i : edges[rt])  // 遍历所有邻居
    {
        if (i == fa) continue;        // 跳过父节点
        int k = dfs(i, rt);           // 递归处理孩子
        rt_sz += k;                   // 累加子树大小
        if (k > max_sz)               // 更新最大孩子
        {
            max_sz = k;
            max_rt = i;
        }
    }
    // ===== 回溯时判断：当前节点是否为重心 =====
    // 条件：父亲方向 <= n/2 且 最大孩子方向 <= n/2
    if (n - rt_sz <= n / 2 && max_sz <= n / 2)
        ans.emplace_back(rt);
    return rt_sz;    // 返回子树大小给父节点
}

int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr); cout.tie(nullptr);
    cin >> n;
    init();
    for (int i = 1; i < n; i++)
    {
        int u, v;
        cin >> u >> v;
        edges[u].emplace_back(v);
        edges[v].emplace_back(u);
    }
    dfs(1, -1);                 // 从节点 1 开始 DFS
    for (int i : ans) cout << i << ' ';  // 输出所有重心
    return 0;
}
```

### 关键变量说明

| 变量 | 含义 |
|------|------|
| `rt` | 当前 DFS 的节点 |
| `fa` | 当前节点的父节点，用于防止走回头路 |
| `rt_sz` | 以 `rt` 为根的子树大小 |
| `max_sz` | 所有孩子中子树最大的那个的大小 |
| `n - rt_sz` | 父亲方向那块的大小 |
| `ans` | 存储所有重心的结果数组 |

### 判断条件解读

```cpp
if (n - rt_sz <= n / 2 && max_sz <= n / 2)
```

- `n - rt_sz <= n / 2`：父亲方向不超过一半
- `max_sz <= n / 2`：最大的孩子子树也不超过一半
- 两个条件同时满足 → 所有方向都不超过一半 → 当前节点是重心

## 复杂度分析

### 时间复杂度

- 每个节点恰好被访问一次
- 每条边恰好被遍历两次（来回各一次）
- 总时间：$O(n)$

### 空间复杂度

- 邻接表：$O(n)$
- DFS 递归栈：最坏 $O(n)$（链状树），平均 $O(\log n)$
- 结果数组：$O(1)$（最多 2 个重心）
- 总空间：$O(n)$

---

## 适用场景

1. **点分治**：每次找重心作为分治中心，保证递归深度为 $O(\log n)$
2. **树的最优根**：求使最大子树最小的根节点
3. **树的中位数**：所有节点到重心的距离之和最小
4. **树上博弈**：某些树上博弈问题的最优策略在重心
5. **树的分解**：将树分解为多个子问题的分治框架

## 常见陷阱与注意事项

### 1. 父亲方向大小写错

父亲方向是 $n - sz[u]$，不是 $n - sz[fa]$。$sz[u]$ 是以 $u$ 为根的子树大小，整棵树去掉这个子树就是父亲方向。

### 2. 判断时机错误（方法一）

必须在 DFS 回溯时判断（所有孩子处理完之后），不能刚进入节点时判断。刚进入时孩子的 $sz$ 还没算出来。

### 3. 条件是 $\le$ 不是 $<$

判断条件是**不超过一半**，即 $\le n/2$，不是严格小于。等于 $n/2$ 也算满足。

### 4. 两个重心的情况

如果 $n$ 是偶数，且某个孩子的 $sz[v] = n/2$，那么当前节点和这个孩子都是重心。方法一、二会自然找到两个，但方法三需要额外检查。

### 5. 点分治中的重心

点分治中，当前处理的是一棵子树，不是整棵树。此时判断重心要用当前连通块大小 $total$，不是整棵树的 $n$。

### 6. 变量不要混

- $u$：当前节点
- $fa$：父节点
- $v$：孩子
- $sz[u]$：以 $u$ 为根的子树大小

### 7. 点分治中已删除的节点不能再访问

在点分治的递归过程中，已经处理过的重心需要标记为"已删除"，下次找重心时不能再经过这些节点。

### 8. 邻接表初始化

每次测试用例前要重新初始化邻接表，注意大小是 $n+1$（节点从 1 开始编号）。

---

## 一句话总结

- **一次 DFS 回溯判断法**：DFS 回溯时，孩子大小已算完，算最大块，不超过 $n/2$ 就记成重心。
- **两次 DFS 判断法**：先 DFS 求 $sz$，再逐个节点按公式判断。
- **沿重子树移动法**：哪边孩子超过一半就往哪边走，走到没有超过一半的孩子，当前节点就是重心。

三种方法本质都基于同一个判断公式：

$$
\max\Big(n - sz[u],\ \max_{v \text{ 是 } u \text{ 的孩子}} sz[v]\Big) \le \frac{n}{2}
$$
