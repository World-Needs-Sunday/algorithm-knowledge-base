## 算法原理

**一句话结论**：给每一轮分配一个自增的「轮号」（时间戳），标记元素时写 `vis[x] = 当前轮号` 而不是写 1，查询时判 `vis[x] == 当前轮号`。上一轮的旧标记因为值小于当前轮号而自动失效，从而**免去每轮开始时的 memset 清空**。

**解决的问题**：多轮处理共享同一个标记数组的场景。比如多轮 BFS/DFS 共用 `vis`、多次二分图匹配共用 `match`，传统写法是每轮开始 `memset(vis, 0, sizeof(vis))`。当数组长度 $n$ 很大、轮数 $t$ 很多时，$t$ 次清零的开销是 $O(t \cdot n)$，可能比每轮真正的标记 + 查询还贵，成为性能瓶颈。

**核心思想怎么来的**：memset 的目的是「让上一轮的标记作废」。作废的本质不是把数组真的写成 0，而是让查询无法把旧标记误认为新标记。既然如此，换一种思路：给每轮一个独一无二、严格递增的编号 `tim`，标记时把 `tim` 写进数组，查询时只有 `vis[x] == tim` 才算本轮标记。旧标记存的是更小的旧轮号，永远追不上当前的 `tim`，于是「作废」被自动实现了——每轮唯一的清空动作就是 `++tim`，$O(1)$。

**为什么这样做是对的**：`vis[x]` 的值只可能取 0 或历史上某一轮的轮号。因为 `tim` 每轮严格 +1，所以「`vis[x] == tim`」当且仅当 x 在本轮被标记过，与「每轮先清零再写 1、判 `vis[x] == 1`」在判定结果上完全一致。第一轮 `++tim` 后 `tim = 1`，恰好与 memset 版的「1」同构；后续每一轮只是把常量 1 换成了更大的常量。

**代码本身的性质**：这是一个演示程序，带交互提示语（`请输入…`）与 `yes/no` 输出，逻辑骨架是：读入元素个数 `n` → 初始化 → 读入轮数 `t` → 每轮先 `++tim`，再读入本轮要标记的 m 个元素并写 `vis[x] = tim`，最后读入 q 个查询，按 `vis[x] == tim` 回答 yes/no。

## 核心公式 / 状态定义与转移方程

**状态定义**：

- `tim`：当前轮号（全局 `unsigned int`），初始 0，每轮开始前自增 1。
- `vis[x]`：元素 x 最近一次被标记时的轮号；0 表示从未被标记过。

**初始化**（`init(n)`）：`vis.assign(n + 1, 0)`（长度 n+1、全 0，下标 1..n 可用，下标 0 闲置），`tim = 0`。

**标记操作**（每轮开始时 `++tim`，然后对每个本轮元素 x）：`vis[x] = tim`。

**查询操作**：x 在本轮被标记过，当且仅当 `vis[x] == tim`。

**与 memset 版的等价关系**：memset 版「清零 → 标记写 1 → 判 `vis[x] == 1`」；时间戳版「`++tim` → 标记写 `tim` → 判 `vis[x] == tim`」。第一轮两者逐字同构，之后每轮时间戳版只是换用更大的常量，旧标记自动失效。

**手算示例**（与实测数据一致）：$n = 5$，共 2 轮。

- 第 1 轮：`++tim` 后 `tim = 1`，标记 2、4 → `vis[2] = vis[4] = 1`；查询 2、3、4 → `vis[2]==1` yes、`vis[3]==0` no、`vis[4]==1` yes。
- 第 2 轮：`++tim` 后 `tim = 2`，标记 1、5 → `vis[1] = vis[5] = 2`；此时 `vis[2] = vis[4] = 1`（旧轮号，自动失效）；查询 4、1 → `vis[4]==2`？不成立 → no（第 1 轮标记过 4 也不作数），`vis[1]==2` → yes。

## 逐行代码解析

代码拆成 5 个模块，按顺序拼接即完整程序。

### 模块 1 头文件与全局变量

```cpp
#include<bits/stdc++.h>
using namespace std;
unsigned int tim;
vector<unsigned int> vis;
```

- `tim`：当前轮号，`unsigned int`——轮号只增不减，用无符号类型语义更贴切。
- `vis`：标记数组，`vector` 动态长度，`vis[x]` 存 x 最近被标记的轮号。
- 全局变量默认零初始化：`tim = 0`、`vis` 为空，但正式使用前仍要调 `init` 分配长度。

### 模块 2 init 初始化

```cpp
void init(int n)
{
	vis.assign(n + 1, 0);
	tim = 0;
}

```

- `assign(n + 1, 0)`：把 `vis` 重置为长度 n+1、全 0 的数组；分配 n+1 是为了下标 1..n 直接可用（下标 0 不用）。
- `tim = 0` 必不可少：保证第一轮 `++tim` 后是 1，与「从未标记」的 0 区分开；若 `tim` 不清零，第一轮就可能是任意值。

### 模块 3 main 与读入 n、t

```cpp
//时间戳优化
int main()
{
	ios::sync_with_stdio(false);
	cin.tie(nullptr); cout.tie(nullptr);
	cout << "请输入总的元素个数\n";
	int n, t;
	cin >> n;
	init(n);
	cout << "请输入查询的轮数\n";
	cin >> t;
	
```

- 关闭同步加速输入输出，与演示程序的交互输出混用没问题。
- 顺序是「先读 n 再 `init(n)`」：`vis` 的长度由 n 决定，读不到 n 就无法分配。
- `t` 是总轮数，主循环 `while (t--)` 每轮处理一次「标记 + 查询」。

### 模块 4 每轮标记

```cpp
while (t--)
	{
		//每次不用重置vis数组，可以节省很多时间
		++tim;
		cout << "请输入本轮被标记的元素\n";
		int m;
		cin >> m;
		for (int i = 1; i <= m; i++)
		{
			int x;
			cin >> x;
			vis[x] = tim;
		}

		
```

- `++tim` 是**唯一的清空动作**：轮号 +1，旧标记全部作废，替代了每轮 $O(n)$ 的 memset——注释里也点明了这一点。
- 标记写的是「当前轮号」`tim` 而不是 1：这是与 memset 版的本质区别，写 1 就退回旧写法且会误判旧标记。

### 模块 5 每轮查询

```cpp
cout << "请输入查询\n";
		int q;
		cin >> q;
		for (int i = 1; i <= q; i++)
		{
			int x;
			cin >> x;
			if (vis[x] == tim) cout << "yes\n";
			else cout << "no\n";
		}
	}

	return 0;
}
```

- 查询判 `vis[x] == tim`：等于当前轮号说明本轮被标记过，回答 yes；旧轮号小于 `tim`，回答 no。
- 每轮查询结束后不需要任何清理，直接进入下一轮的 `++tim`。

## 复杂度分析

- **时间**：`init` 一次 $O(n)$（`assign` 分配并清零）；每轮 m 次标记 + q 次查询，每次都是数组单点读写 $O(1)$，单轮共 $O(m + q)$；t 轮共 $O(n + \sum (m_i + q_i))$。对比 memset 版每轮开始 $O(n)$ 清零、t 轮共 $O(t \cdot n + \sum (m_i + q_i))$：当 n 大、t 多、每轮 m+q 又很小时，时间戳版省掉的就是那笔 $O(t \cdot n)$。
- **空间**：`vis` 长度 n+1，$O(n)$；额外一个全局 `tim`，$O(1)$。

## 适用场景

- **多轮处理共享标记数组**：多次 BFS/DFS 共用一个 `vis`、多次匹配共用一个访问标记、图遍历里需要反复判断「这个点这轮来过没有」等每轮要重置的场景。
- **n 大、轮数多、每轮工作量小**：memset 的 $O(n)$ 占比高时收益最明显。
- **不要用它**：只做一次遍历——一次 memset 的开销无所谓，平白增加 `tim` 这个全局状态；标记值本身要承载「第几轮」以外的语义时（时间戳值已占用数组内容）。

## 常见陷阱与注意事项

1. **忘记 `++tim`**：`tim` 恒为 0，标记写 `vis[x] = 0`，查询判 `vis[x] == 0` 恒真 → 所有查询都输出 yes（连从没标记过的元素也是）。
2. **标记写 1 而不是 `tim`**：等于退回 memset 版写法却又不做每轮清零，上一轮的 1 会被误认为本轮标记。
3. **`init` 里不归零 `tim`**：第一轮 `++tim` 后轮号不定，可能与后续状态混淆；多组测试数据共用全局 `vis`/`tim` 时，每组都要重新 `init(n)`。
4. **下标越界**：`vis` 只分配了 n+1 个元素，标记或查询的 x 必须落在 1..n；x 超范围是未定义行为。
5. **轮号类型与上界**：`unsigned int` 最大约 $4.29 \times 10^9$ 轮，正常竞赛数据远达不到；但若改成 `int` 且轮数超过 $2^{31}$ 会溢出变负，判定全部失效——所以轮号用无符号类型更稳妥。
6. **`vis` 与 `tim` 类型不一致**：如 `vis` 是 `int` 而 `tim` 是 `unsigned`，比较时会发生隐式类型转换，极端值下结果诡异；保持两者同类型（本项目都是 `unsigned int`）。

## 对比与扩展

**memset 每轮清零 vs 时间戳**：

| 写法 | 每轮清空开销 | 标记 | 查询 |
|---|---|---|---|
| memset 版 | $O(n)$ | `vis[x] = 1` | `vis[x] == 1` |
| 时间戳版 | $O(1)$（`++tim`） | `vis[x] = tim` | `vis[x] == tim` |

两者的判定结果完全相同，时间戳版只是把「物理清零」换成「逻辑作废」：用单调递增的轮号让旧值天然失真。代价是 `vis` 里存的不再是 0/1 布尔，而是轮号——若其他代码依赖「`vis` 只有 0/1」这一性质（比如直接 `sum += vis[x]`），则不能直接替换。

**适用边界的再确认**：时间戳优化只省「重置」这一件事。如果每轮的标记量 m 本身是 $O(n)$ 量级，memset 的 $O(n)$ 不再是瓶颈，优化收益不明显；只有在「n 大、每轮只碰少量元素」的形态下，$O(t \cdot n)$ 的清零才会显著压过实际工作量。
