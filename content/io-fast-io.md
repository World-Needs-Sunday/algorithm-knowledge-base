## 算法原理

在算法竞赛中，当数据量达到 $10^6$ 级别时，标准的 `scanf`/`printf` 或 `cin`/`cout` 的 I/O 开销可能占总运行时间的相当比例。快速 I/O 的核心思想是绕过标准库的格式解析机制，用 `getchar()` 逐字符读入并手动解析整数，用 `putchar()` 配合缓冲区逐字符输出，从而大幅降低常数因子。

读入优化 `read()` 的工作流程：先用 `getchar()` 逐字符读取，跳过所有非数字字符（空格、换行、制表符等），同时检测负号 `'-'` 设置符号标志 `f`。遇到数字字符后，通过 $x = x \times 10 + (ch - 48)$ 逐位累加，将字符序列解析为整数值。这个过程省去了 `scanf` 内部的格式串解析、类型匹配等开销，每个字符仅需一次 `getchar()` 调用和简单算术运算。

输出优化 `write()` 的工作流程：将整数 $x$ 的每一位数字通过 $x \% 10$ 逐位提取，转换为字符后存入静态缓冲区 `buf`（正向写入，低位在前）。所有位提取完毕后，逆序输出 `buf` 中的字符（高位在前）。使用静态缓冲区 `static char buf[30]` 复用内存，避免每次调用重新分配。与 `printf` 相比，省去了格式串解析和可变参数处理的开销，且 `putchar` 的批量调用（先攒后输出）比逐位 `printf` 更快。

## 核心公式

读入解析（逐位累加，$ch$ 为当前字符）：
$$x = \sum_{i=0}^{L-1} (ch_i - 48) \times 10^{L-1-i}$$

递推形式：
$$x \leftarrow x \times 10 + (ch - 48)$$

输出分解（逐位提取）：
$$\text{buf}[p] = (x \bmod 10) + 48, \quad x \leftarrow \left\lfloor \frac{x}{10} \right\rfloor$$

符号处理：
$$\text{output}(x) = \begin{cases} \text{'-'} + \text{output}(-x) & \text{if } x < 0 \\ \text{output}(x) & \text{if } x \ge 0 \end{cases}$$

## 逐行代码解析

```cpp
#include<bits/stdc++.h>
using namespace std;

// 快速读入整数
inline int read()
{
	int x = 0, f = 1;          // x 累积结果，f 符号标志（默认正）
	char ch = getchar();
	while (ch < '0' || ch > '9') {    // 跳过非数字字符
		if (ch == '-') f = -1;        // 检测负号
		ch = getchar();
	}
	while (ch >= '0' && ch <= '9') {  // 逐位解析数字
		x = x * 10 + ch - 48;        // 累加当前位
		ch = getchar();
	}
	return x * f;                     // 返回带符号结果
}

// 快速输出整数
inline void write(long long x)
{
	static char buf[30];              // 静态缓冲区，复用内存
	int p = 0;
	if (x < 0) { putchar('-'); x = -x; }  // 处理负数
	if (x == 0) buf[p++] = '0';      // 特判 0
	while (x) {                       // 逐位提取（低位在前）
		buf[p++] = x % 10 + 48;
		x /= 10;
	}
	while (p--) putchar(buf[p]);      // 逆序输出（高位在前）
}
```

**关键解析：**

- `inline`：建议编译器内联展开函数，消除函数调用的栈帧创建和返回开销。在读入/输出 $10^6$ 次时，函数调用开销不可忽略。
- `read` 中 `f = 1`：符号标志默认为正。遇到 `'-'` 时设为 $-1$，最后返回 `x * f`。这种方式比在累加时处理符号更简洁。
- `while (ch < '0' || ch > '9')`：跳过所有非数字字符，包括空格、换行、制表符等分隔符。这使 `read()` 能自动处理任意空白分隔的输入，无需关心具体分隔符。
- `x = x * 10 + ch - 48`：将字符 ASCII 值转换为数字（`'0'` 的 ASCII 为 $48$）并逐位累加。每次乘以 $10$ 将已有数左移一位，加上当前位。
- `static char buf[30]`：静态局部变量在函数调用间保持存在（只分配一次），避免每次调用 `write` 时重新分配栈空间。`30` 位足以容纳 `long long` 的最大位数（约 $19$ 位数字加符号）。
- `while (p--) putchar(buf[p])`：`buf` 中数字是低位在前（先提取个位、十位、...），输出时需逆序从高位到低位。`p--` 先判断 `p` 是否为 $0$ 再减一，保证输出所有位后停止。
- `if (x == 0) buf[p++] = '0'`：特判 $0$ 的情况，因为 `while(x)` 在 $x=0$ 时不进入循环，`buf` 为空会导致无输出。

## 复杂度分析

`read()` 的时间复杂度为 $O(L)$，其中 $L$ 为输入整数的十进制位数。每个字符仅调用一次 `getchar()` 和执行一次乘加运算，常数极小。`write()` 同样为 $O(L)$，$L$ 为输出整数的位数。相比之下，`scanf` 需要解析格式串、匹配类型、处理可变参数等额外开销，常数约为 `read` 的 $5 \sim 10$ 倍。在 $10^6$ 级数据量下，快速 I/O 可节省数百毫秒。空间上 `read` 仅用几个局部变量，`write` 使用 $O(1)$ 的静态缓冲区，总空间复杂度为 $O(1)$。

## 适用场景

算法竞赛中数据量大的题目（$n \ge 10^6$），作为通用 I/O 加速头文件使用。特别适用于需要读入大量整数或输出大量结果的场景，如数论、图论、数据结构等需要大规模数据的题目。

## 常见陷阱与注意事项

1. **`read` 返回 `int` 但输入可能溢出**：当输入整数超过 `int` 范围（$\pm 2.1 \times 10^9$）时，`read()` 会溢出。若需要读入 `long long`，应将 `x` 和返回类型改为 `long long`。
2. **`write` 接收 `long long` 但 `read` 返回 `int`**：类型不一致。若数据范围在 `int` 内则无问题，但需注意读写类型的匹配，避免截断。
3. **`x = -x` 的溢出**：当 $x = \text{LLONG\_MIN} = -2^{63}$ 时，`-x` 溢出（因为 $2^{63}$ 超出 `long long` 正数范围）。实际竞赛中极少遇到此边界，但严格来说需特殊处理。
4. **与 `cin`/`cout` 混用**：若同时使用 `read()` 和 `cin`，或 `write()` 和 `cout`，可能因缓冲区不同步导致输入/输出顺序错乱。建议统一使用一套 I/O 方法，或调用 `ios::sync_with_stdio(false)` 取消同步后谨慎混用。
5. **`getchar` 的性能**：`getchar()` 在某些编译器/平台上仍有缓冲开销。更快的写法是使用 `fread` 一次性读入全部输入到字符缓冲区，再从缓冲区逐字符解析，避免多次系统调用。
6. **`static` 缓冲区的线程安全**：`static char buf[30]` 在多线程环境下不安全（多个线程共享同一缓冲区）。竞赛中通常单线程无影响，但在工程场景中需注意。

## 对比与扩展

与 `scanf`/`printf` 相比，快速 I/O 通过省去格式解析将常数降低数倍，在 $10^6$ 级数据下优势显著。与 `ios::sync_with_stdio(false); cin.tie(nullptr)` 加速后的 `cin`/`cout` 相比，`read`/`write` 通常仍有 $2 \sim 3$ 倍优势。更进一步的优化包括：用 `fread`/`fwrite` 批量读写（一次性将全部输入读入内存缓冲区，再从缓冲区解析，避免逐字符的系统调用），以及针对浮点数的快速读入。扩展方向包括：支持读入字符串、浮点数、模板化（泛型 `read<T>` 自动适配不同整数类型），以及封装为完整的 I/O 工具库。
