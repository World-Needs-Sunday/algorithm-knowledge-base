## 算法原理

带权并查集在普通并查集的基础上，额外维护每个节点到根节点的**距离（权值）**。本题（蓝桥 1156）的场景是将元素排成链式队列：合并操作 `unity(x, y)` 表示将 `x` 所在的整条链追加到 `y` 所在链的末尾，查询操作需要计算两个元素之间相隔多少个节点。

核心维护的数组有三个：`A[]`（父节点）、`k[]`（到根的距离/链长）、`sz[]`（以该节点为根的链的大小）。初始时 $A[i] = i$（各自成链），$k[i] = 0$（到自己距离为 0），$sz[i] = 1$（单节点链大小为 1）。

**合并的关键洞察**：当执行 `unity(x, y)` 将 x 链追加到 y 链末尾时，x 链的根 `rx` 被挂到 y 链的根 `ry` 下。此时 `rx` 到新根 `ry` 的距离应当等于 y 链当前的长度 $\text{sz}[r_y]$——因为 x 链整体排在了 y 链之后，x 链的根距离 y 链根的距离正好是 y 链中所有节点的个数。因此执行 $k[r_x] = \text{sz}[r_y]$，然后更新 $\text{sz}[r_y] \mathrel{+}= \text{sz}[r_x]$（新链大小 = 两条链大小之和），最后 $A[r_x] = r_y$。

**路径压缩时距离的累加**是本实现最精妙的部分。在 `find` 中，当节点 `idx` 的父节点从 `old` 变为新的根时（即 `old != A[idx]`，说明路径被压缩了），`k[idx]` 需要加上 `k[old]`。原因是：`k[idx]` 原本记录的是 `idx` 到旧父 `old` 的距离，而 `k[old]` 在递归 `find` 后已经更新为 `old` 到新根的距离。两者相加 $k[\text{idx}] + k[\text{old}]$ 即为 `idx` 到新根的总距离。这一累加发生在路径压缩的同时，保证了距离信息始终正确。

**查询逻辑**：若两节点 `x` 和 `y` 在同一链中（`find(x) == find(y)`），则它们之间的间隔节点数为 $|k[x] - k[y]| - 1$。$|k[x] - k[y]|$ 是两节点在链中的位置差（距离），减去 1 是因为要排除端点本身，只计算中间的节点数。若不在同一链中则输出 -1。

## 数据结构图示

合并操作 `unity(x, y)` —— 将 x 链追加到 y 链末尾：

```
合并前:
  y链 (根=ry):     y -> ... -> ry        sz[ry]=3, k[ry]=0
  x链 (根=rx):     x -> ... -> rx        sz[rx]=2, k[rx]=0

合并后 (A[rx]=ry):
  y -> ... -> ry -> rx -> ... -> x
                 ↑
           k[rx] = sz[ry] = 3   (rx 到新根 ry 的距离 = y链大小)
           sz[ry] = 3 + 2 = 5   (新链大小)
```

路径压缩时 k 值的累加过程：

```
压缩前:  idx -> old -> ... -> root
         k[idx]=a (idx到old的距离)
         k[old]=b (old到root的距离, 递归find后已更新)

压缩后:  idx ---------> root
         k[idx] = a + b = k[idx] + k[old]   (累加!)

具体示例:
  压缩前:  1 -> 2 -> 3 -> 4(根)
          k[1]=1  k[2]=1  k[3]=1  k[4]=0  sz[4]=4

  find(1) 递归过程:
  1. find(1): old=2, 递归 find(2)
  2. find(2): old=3, 递归 find(3)
  3. find(3): old=4, 递归 find(4) -> 返回4, A[3]=4, old(4)==A[3](4), k[3]不变
  4. 回到 find(2): A[2]=4, old(3)!=A[2](4), k[2]+=k[3] => k[2]=1+1=2
  5. 回到 find(1): A[1]=4, old(2)!=A[1](4), k[1]+=k[2] => k[1]=1+2=3

  压缩后:  1 -----> 4(根)
           2 -----> 4
           3 -----> 4
          k[1]=3  k[2]=2  k[3]=1  k[4]=0
          (距离正确: 1距根3, 2距根2, 3距根1)
```

## 核心操作详解

### init() —— 初始化

**功能**：为 `N` 个元素各自创建独立的单节点链。

**参数**：无（使用全局变量 `N`）。

**算法步骤**：
1. `A` 数组大小为 `N + 1`，每个元素 `A[i] = i`（自身为根）。
2. `k` 数组大小为 `N + 1`，全部初始化为 0（到自身距离为 0）。
3. `sz` 数组大小为 `N + 1`，全部初始化为 1（单节点链大小为 1）。

**关键细节**：三个数组缺一不可。`k[]` 记录到根距离，`sz[]` 记录链大小（用于合并时计算新根的距离）。

### find(idx) —— 查找（带路径压缩 + 距离累加）

**功能**：返回元素 `idx` 所在链的根节点，同时压缩路径并更新距离 `k[]`。

**参数**：`idx` — 待查找的元素编号。

**算法步骤**：
1. 保存旧父节点 `old = A[idx]`。
2. 若 `A[idx] != idx`（不是根），递归调用 `find(A[idx])` 找到根并压缩路径，将 `A[idx]` 更新为根。
3. 判断 `old != A[idx]`（即父节点发生了变化，说明路径被压缩）。
4. 若父节点变化，执行 `k[idx] += k[old]`——将旧父到新根的距离累加到当前节点的距离上。
5. 返回 `A[idx]`（根节点）。

**关键细节**：**必须先保存旧父 `old` 再递归**。递归 `find(A[idx])` 会改变 `A[idx]` 的值，若不提前保存，将无法获取旧父节点的 `k` 值。这一顺序是正确性的核心——`k[old]` 在递归后已被更新为 `old` 到新根的距离，此时累加才是正确的。

### unity(x, y) —— 合并（将 x 链追加到 y 链末尾）

**功能**：将 `x` 所在链追加到 `y` 所在链的末尾，合并为一条链。

**参数**：`x`、`y` — 两个元素编号。合并后 `y` 链的根成为新链的根。

**算法步骤**：
1. 调用 `find(x)` 和 `find(y)` 获取两链的根 `rx` 和 `ry`。
2. 若 `rx == ry`（已在同一链），返回 `false`（无需合并）。
3. 设置 `k[rx] = sz[ry]`——x 链根 `rx` 到新根 `ry` 的距离等于 y 链当前大小。
4. 更新 `sz[ry] += sz[rx]`——新链大小 = 两链大小之和。
5. 执行 `A[rx] = ry`——将 x 链根挂到 y 链根下。
6. 返回 `true`。

**关键细节**：**顺序不能颠倒**——必须先设置 `k[rx]` 再更新 `sz[ry]`，否则 `k[rx]` 会用到更新后的 `sz[ry]` 导致错误。`k[rx] = sz[ry]` 的含义是：x 链排在整个 y 链后面，所以 x 链根距离 y 链根的距离恰好是 y 链的长度。

## 逐行代码解析

```cpp
#include <bits/stdc++.h>
using namespace std;
/*蓝桥1156*/
long long N , M;
vector<long long> A;
vector<long long> k;
vector<long long> sz;
void init()
{
  A.resize(N + 1 , 0);
  for(long long i = 1;i <= N;i++) A[i] = i;
  k.resize(N + 1 , 0);
  sz.resize(N + 1 , 1);
}

long long find(long long idx)
{
  long long old = A[idx];
  if(A[idx] != idx) A[idx] = find(A[idx]);
  if(old != A[idx]) k[idx] += k[old];
  return A[idx];
}

bool unity(long long x,long long y)
{
  long long rx = find(x);
  long long ry = find(y);
  if(rx == ry) return false;
  k[rx] = sz[ry];
  sz[ry] += sz[rx];
  A[rx] = ry;
  return true;
}

int main()
{
  cin >> N >> M;
  init();
  for(long long i = 0;i < M;i++)
  {
    long long p , x , y;
    cin >> p >> x >> y;
    if(p == 1) unity(x,y);
    else
    {
      int rx = find(x);
      int ry = find(y);
      if(rx != ry) cout << -1 << endl;
      else cout << max(k[x],k[y]) - min(k[x],k[y]) - 1 << endl;
    }
  }
  return 0;
}
```

**逐行解析**：

- `vector<long long> A;`：父节点数组。使用 `long long` 防止距离累加时溢出。
- `vector<long long> k;`：距离数组，`k[i]` 记录节点 `i` 到其根的距离（链中位置偏移量）。
- `vector<long long> sz;`：大小数组，`sz[i]` 记录以 `i` 为根的链的节点总数。仅根节点的 `sz` 有意义。
- `k.resize(N + 1, 0);`：距离初始化为 0——每个节点到自身（根）的距离为 0。
- `sz.resize(N + 1, 1);`：大小初始化为 1——每条初始链只有一个节点。
- `long long old = A[idx];`：**关键**——先保存旧父节点编号。后续递归会改变 `A[idx]`，必须在递归前保存。
- `if(A[idx] != idx) A[idx] = find(A[idx]);`：递归查找根并执行路径压缩。递归返回后 `A[idx]` 已指向根。
- `if(old != A[idx]) k[idx] += k[old];`：**核心累加**——若旧父不等于新根（即路径被压缩），将旧父到新根的距离 `k[old]`（已由递归更新）累加到 `k[idx]`。这保证 `k[idx]` 始终等于 `idx` 到当前根的真实距离。
- `k[rx] = sz[ry];`：x 链根到新根的距离 = y 链大小。因为 x 链追加在 y 链末尾，rx 距离 ry 恰好是 y 链中所有节点的个数。
- `sz[ry] += sz[rx];`：更新新链大小 = 原 y 链大小 + 原 x 链大小。
- `A[rx] = ry;`：将 x 链根挂到 y 链根下，完成合并。
- `max(k[x],k[y]) - min(k[x],k[y]) - 1`：等价于 `|k[x] - k[y]| - 1`，即两节点在链中的位置差减 1，得到中间间隔的节点数。

## 复杂度分析

- **时间复杂度**：$O(\alpha(n))$ 每次。路径压缩使均摊查询/合并接近常数。`k[]` 的累加发生在 `find` 中，不增加额外的时间复杂度。
- **空间复杂度**：$O(n)$，需要三个数组 `A`（父节点）、`k`（距离）、`sz`（链大小），各 $O(n)$。使用 `long long` 以防止距离累加溢出。

## 适用场景

- 需要查询元素间排名/距离的链式合并问题（如排队、链合并后查询间隔人数）。
- 元素间存在线性顺序关系，需要在动态合并中维护相对位置。
- 蓝桥 1156 类问题：合并两条链后查询两元素间相隔多少个元素。
- 可推广至任何需要维护"节点到根的权值/距离"的场景，是带权并查集的基础形态。

## 常见陷阱与注意事项

- **find 中必须先保存旧父 `old` 再递归**：这是最常见的错误。若先递归再取 `old = A[idx]`，此时 `A[idx]` 已被更新为根，`old` 就不再是旧父，`k[old]` 也无意义。正确顺序是 `old = A[idx]` 在递归之前。
- **k 和 A 的更新顺序在 find 中至关重要**：先递归 `find(A[idx])`（更新父节点和 k[old]），再判断 `old != A[idx]` 并累加 `k[idx] += k[old]`。顺序颠倒会导致累加错误的值。
- **unity 中 k[rx] 和 sz[ry] 的更新顺序**：必须先 `k[rx] = sz[ry]`（用旧 sz），再 `sz[ry] += sz[rx]`（更新 sz）。若先更新 sz 再设 k，会导致 `k[rx]` 取到合并后的大小。
- **数据类型**：距离累加可能超过 `int` 范围（特别是 N 较大时），使用 `long long` 更安全。
- **查询时必须先 find 再读 k**：`k[x]` 只有在 `find(x)` 之后才是最新的。直接读取未经 `find` 的 `k[x]` 可能是过时的值。

## 对比与扩展

- **带权 vs 基础并查集**：基础并查集只维护连通性，不关心元素间的距离/顺序。带权并查集额外维护 `k[]`（到根距离）和 `sz[]`（链大小），支持距离查询，代价是多两个数组和更复杂的 `find`/`unity` 逻辑。
- **带权 vs 扩展域并查集**：带权并查集维护的是**连续的数值关系**（距离/排名），适合线性结构；扩展域并查集处理的是**离散的对立关系**（敌/友），适合分类问题。两者是并查集的两个不同扩展方向。
- **扩展方向**：
  - **模运算带权并查集**：将距离改为模某个数的余数（如食物链的模 3），用于关系推理。
  - **可撤销带权并查集**：不使用路径压缩（改为按秩合并 + 距离维护），支持回溯。
  - **线段树 + 带权并查集**：在时间维度上分治处理，解决"某时刻的连通性/距离"查询。
