## 算法原理

Sunday 算法由 Daniel M. Sunday 于 1990 年提出，是一种高效的字符串匹配算法。它的核心思想是：**当匹配失败时，关注主串中当前窗口的下一个字符，根据该字符在模式串中的位置来决定模式串向右移动多少位**。

与 KMP 相比，Sunday 算法代码更简洁，在实际应用中往往比 KMP 更快（尤其在字符集较大、模式串较短时），但其最坏时间复杂度为 $O(nm)$，而 KMP 最坏仍是 $O(n+m)$。

### 核心思想

假设主串为 $s$（长度 $n$），模式串为 $p$（长度 $m$）：

1. 从左到右将模式串与主串当前窗口对齐比较
2. 如果匹配成功，记录起始位置
3. 如果匹配失败，看**主串中当前窗口右边的第一个字符**（即 $s[i+m]$）：
   - 如果这个字符**在模式串中出现过**，就把模式串右移，让模式串中最右边的该字符与主串中的该字符对齐
   - 如果这个字符**不在模式串中**，直接把模式串右移 $m+1$ 位（跳过这个不可能匹配的字符）

### 为什么高效

Sunday 算法每次移动的步长通常比 KMP 更大，尤其当模式串中字符不重复时，平均每次可以移动很多位，因此实际运行很快。

## 偏移表（next 数组）

Sunday 算法需要预处理一个**偏移表**（也叫 shift 表或 next 数组），记录每个字符对应的移动步数：

$$
\text{next}[c] =
\begin{cases}
m - \text{pos}(c) & \text{若 } c \text{ 在模式串中出现，pos}(c) \text{ 是最右出现位置} \\
m + 1 & \text{若 } c \text{ 不在模式串中}
\end{cases}
$$

其中 $m$ 是模式串长度。

### 偏移表示例

以模式串 `p = "abcab"` 为例（$m = 5$）：

| 字符 | 最右位置 | next 值（移动步数） |
|------|---------|-------------------|
| a | 3 | 5 - 3 = 2 |
| b | 4 | 5 - 4 = 1 |
| c | 2 | 5 - 2 = 3 |
| 其他 | - | 5 + 1 = 6 |

解释：
- 如果窗口右边的字符是 `a`，模式串右移 2 位（让模式串最右的 `a` 对齐）
- 如果窗口右边的字符是 `b`，模式串右移 1 位
- 如果窗口右边的字符是 `z`，模式串直接右移 6 位

## 算法步骤

1. **预处理偏移表**：遍历模式串，记录每个字符最右边的出现位置，计算每个字符对应的移动步数
2. **匹配过程**：
   - 主串指针 $i = 0$
   - 当 $i \le n - m$ 时：
     - 比较 $s[i..i+m-1]$ 与 $p[0..m-1]$
     - 若完全匹配：记录位置 $i$，然后继续找下一个
     - 若不匹配且 $i + m < n$：$i \mathrel{+}= \text{next}[s[i+m]]$
     - 若不匹配且 $i + m \ge n$：结束

## 逐行代码解析

### 全局变量

```cpp
vector<int> sunday_next, ans;  // 偏移表 / 匹配结果（所有匹配的起始位置）
```

### 预处理偏移表 init

```cpp
void init(const string& str)
{
    int m = str.size();
    sunday_next.assign(128, m + 1);  // 初始所有字符的移动步数为 m+1
    for (int i = 0; i < m; i++)
        sunday_next[str[i]] = m - i; // 字符 str[i] 出现在位置 i，移动 m-i 步
}
```

**关键点**：
- 数组大小 128，对应 ASCII 码表的所有字符
- 初始值设为 $m+1$（不在模式串中的字符移动 $m+1$ 位）
- 从左到右遍历，后面的位置会覆盖前面的，因此最终每个字符保存的是**最右边**的出现位置

### Sunday 匹配主体

```cpp
void sunday(const string& a, const string& b)
{
    ans.clear();
    int n = a.size(), m = b.size();
    for (int i = 0; i <= n - m; i += sunday_next[a[i + m]])
    {
        int j = 0;
        while (j < m && a[i + j] == b[j]) j++;  // 逐字符比较
        if (j == m) ans.emplace_back(i);        // 完全匹配，记录位置
    }
}
```

**逐行解读**：

| 代码 | 含义 |
|------|------|
| `for (int i = 0; i <= n - m; ...)` | $i$ 是主串当前窗口的起始位置，最多到 $n-m$ |
| `i += sunday_next[a[i + m]]` | 匹配失败后，根据窗口右边第一个字符 $s[i+m]$ 查偏移表，移动相应步数 |
| `while (j < m && a[i + j] == b[j]) j++` | 从左到右逐字符比较，j 是匹配成功的字符数 |
| `if (j == m)` | 所有字符都匹配上了，说明找到一个匹配位置 |
| `ans.emplace_back(i)` | 记录匹配的起始下标 |

### 主函数：多模式匹配

```cpp
int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr); cout.tie(nullptr);
    int T;
    cin >> T;
    while (T--)
    {
        string p;
        int t;
        cin >> p >> t;
        init(p);                  // 预处理模式串的偏移表
        while (t--)
        {
            ans.clear();
            string s;
            cin >> s;
            sunday(s, p);         // 在主串 s 中找模式串 p
            if (ans.empty()) cout << -1;
            else for (int i : ans) cout << i << ' ';
            cout << '\n';
        }
    }
    return 0;
}
```

这是一个多测试用例模板：一个模式串对应多个主串，偏移表只需预处理一次。

## 复杂度分析

### 时间复杂度

- **预处理**：$O(m)$ — 遍历模式串一次
- **匹配**：
  - **平均情况**：$O(n/m)$ — 每次平均移动 $m/2$ 位左右，总比较次数很少
  - **最坏情况**：$O(nm)$ — 例如主串全是 `a`，模式串是 `aaaaab`，每次只能移动 1 位，且每次比较到最后才失败
- **实际表现**：在随机数据下，Sunday 通常比 KMP、Boyer-Moore 都快

### 空间复杂度

- $O(|\Sigma|)$ — 偏移表大小等于字符集大小（ASCII 为 128）
- 与模式串长度无关

## 匹配过程演示

以主串 $s = \text{"abcabcabx"}$，模式串 $p = \text{"abcabx"}$（$m=6$）为例：

**初始偏移表**：
```
next['a'] = 5, next['b'] = 4, next['c'] = 3, next['x'] = 1
其他字符 = 7
```

**第 1 轮（i = 0）**：
```
s: a b c a b c a b x
p: a b c a b x   ← 比较到第5位('c' vs 'x')不匹配
         ↑
窗口右边字符: s[0+6] = s[6] = 'a' → next['a'] = 5
i += 5 → i = 5
```

**第 2 轮（i = 5）**：
```
s: a b c a b c a b x
p:           a b c a b x   ← 超出主串范围，结束
```

最终无匹配。

## 常见陷阱与注意事项

1. **数组越界问题**：当 `i + m >= n` 时，`a[i+m]` 会越界。代码中 `i <= n - m` 的循环条件保证了最后一次可能匹配的窗口是合法的，但若最后一次匹配失败后需要继续移动，则会越界。因此匹配失败后如果无法再移动（`i + m >= n`），应直接退出
2. **偏移表初始化**：必须先全部设为 `m+1`，再用模式串中的字符覆盖。不能只初始化出现过的字符
3. **最右位置**：从左到右遍历时，后面的赋值会覆盖前面的，这样自然得到了每个字符的最右出现位置，无需额外处理
4. **字符集大小**：代码中用 128 对应 ASCII，如果是更大的字符集（如 Unicode）需要调整
5. **下标从 0 开始**：Sunday 算法通常用 0 下标实现，与 KMP 类似
6. **找所有匹配位置**：找到一个匹配后，移动步数仍按 `next[s[i+m]]` 计算（而不是移动 1 位），这样可以保持高效

## 与 KMP 算法对比

| 特性 | KMP | Sunday |
|------|-----|--------|
| 核心思想 | 前缀函数（next 数组），利用已匹配的前缀信息 | 偏移表，关注窗口右侧字符 |
| 预处理 | $O(m)$ | $O(m)$ |
| 最坏时间 | $O(n+m)$ | $O(nm)$ |
| 平均时间 | $O(n+m)$ | $O(n/m)$（更快） |
| 空间 | $O(m)$ | $O(\|\Sigma\|)$（常数级） |
| 代码复杂度 | 稍复杂（前缀函数需要理解） | 简洁易懂 |
| 适用场景 | 保证线性时间，最坏情况也可靠 | 实际运行快，竞赛中常用 |
| 主串指针 | 不回退 | 每次跳跃前进 |

**竞赛建议**：大多数题目中 Sunday 算法更快且代码更短，是首选。只有当题目构造了最坏情况数据（如大量重复字符）时，才考虑用 KMP 保证时间。

## 扩展：从右往左比较的变体

Sunday 算法也可以从右往左比较（类似 Boyer-Moore），但核心移动策略不变——始终根据窗口右侧的字符决定移动步数。从右往左比较的好处是：如果第一个比较的字符就不匹配，可以直接跳过，速度更快。

```cpp
// 从右往左比较的版本（伪代码）
int j = m - 1;
while (j >= 0 && a[i + j] == b[j]) j--;
if (j < 0) ans.push_back(i);  // 匹配成功
```

实际竞赛中，从左往右和从右往左的版本差异不大，选择自己习惯的写法即可。
