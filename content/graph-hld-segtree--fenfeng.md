## 算法原理

树链剖分（Heavy-Light Decomposition，简称 HLD，也称重链剖分）是一种把**树上问题转化为序列问题**的技巧。它本身并不负责维护「和」「最大值」「最小值」等具体信息，它的职责是：**把树上的路径或子树表示成若干个连续的序列区间**，从而能够像维护普通序列一样维护树上的信息。至于这些区间上的信息如何维护，则交给线段树、树状数组或其他合适的数据结构。这里先讲它的思想与直接运用。

**引入**：在线性序列上，区间 $[l,r]$ 是天然连续的一段，可以方便地交给线段树或树状数组处理。但在树上，两个节点之间的路径可能弯来绕去——例如要查询节点 $u$ 到 $v$ 路径上的点权和时，路径上的节点并不对应某个简单的编号区间。一种直接做法是让 $u$、$v$ 不断向上跳到最近公共祖先（LCA），但最坏情况下路径长度可达 $O(n)$，若有 $q$ 次询问，复杂度就可能达到 $O(nq)$。

树链剖分的做法是：把树拆成若干条链，给每条链上的节点重新编号，使同一条链上的节点编号连续。这样就能把任意一条树上路径拆成若干段链，再把每段链转化为一个序列区间，从而用维护序列的方式维护。剖分的方式决定了操作的复杂度，这里介绍**理论复杂度最优、OI 中最常见**的剖分算法——重链剖分。

**策略**：首先任选一个节点作为根，之后树就具有了父子关系、深度、子树等概念。

- 对于每个节点 $u$，在它的所有儿子中选择一个**子树大小最大**的儿子作为 $u$ 的**重儿子**，其余为**轻儿子**；若多个儿子的子树大小相同，任选一个即可。
- 连接 $u$ 与重儿子的边称为**重边**，其他连接父子节点的边称为**轻边**。
- 若干条连续的重边构成一条**重链**；特别地，没有重儿子的节点自身可以看成一条只包含自己的重链。

例如下面的树，若节点 $2$ 的子树最大，则 $1\to2$ 是重边，$1\to3$、$1\to4$ 是轻边；节点 $2,5,6$ 中若 $5$ 是重儿子，则 $2\to5$ 是重边、$2\to6$ 是轻边。

```text
        1
      / | \
     2  3  4
    / \
   5   6
```

得到重链以后，按 DFS 序把节点映射到序列上，就得到了重链剖分的序列。

## 核心公式 / 状态定义与转移方程

树链剖分通常通过两次 DFS 完成，需要维护以下信息：

| 数组 | 含义 |
|------|------|
| `fah[u]` | 节点 $u$ 的父节点 |
| `dep[u]` | 节点 $u$ 的深度 |
| `siz[u]` | 节点 $u$ 的子树大小 |
| `son[u]` | 节点 $u$ 的重儿子 |
| `top[u]` | 节点 $u$ 所在重链的链顶 |
| `seg[u]` | 节点 $u$ 对应到序列的编号 |
| `rev[u]` | 序列上第 $u$ 个位置对应的树上节点，即 `rev[seg[v]] = v` |

前 4 个信息在第一轮 DFS 中计算，后 3 个在第二轮 DFS 中计算。

**第一轮 DFS 的递推**（自底向上）：

$$dep[x] = dep[fah[x]] + 1, \qquad siz[x] = 1 + \sum_{i \in \text{children}(x)} siz[i]$$

重儿子的选择：

$$son[x] = \arg\max_{i \in \text{children}(x)} siz[i]$$

**第二轮 DFS 的编号**（自顶向下）：`seg[0]` 作为计数器，初值为 0，`seg[x] = ++seg[0]`，同时记录反向映射 `rev[seg[0]] = x`。

**轻边至少减半（复杂度保证的核心）**：设 $v$ 是 $u$ 的轻儿子。因为 $v$ 不是重儿子，所以一定存在 $u$ 的某个儿子 $w$ 满足 $siz[w] \ge siz[v]$；同时 $u$ 的子树至少包含 $u$ 自身、子树 $v$ 与子树 $w$。于是：

$$siz[u] \ge 1 + siz[v] + siz[w] \ge 2\,siz[v] + 1$$

也就是说，沿一条轻边向下走时，子树大小至少缩小一半。因此从任意节点向根移动时，最多经过 $O(\log n)$ 条轻边。

**编号后的两条性质**：

1. **同一条重链上的节点连续**：若 $u$、$v$ 在同一条重链上，且 $u$ 是链顶到 $v$ 之间的祖先，则它们对应的编号区间为 $[seg[u], seg[v]]$，链上的一段路径就变成了普通序列上的一段区间。
2. **一棵子树对应连续区间**：由于 DFS 会完整访问完一个节点的子树后才离开，节点 $u$ 的子树对应区间 $[seg[u], seg[u] + siz[u] - 1]$，子树操作无需逐个遍历节点，直接处理一个连续区间即可。这条性质与重边无关，普通 DFS 序也具备；但树链剖分通常同时维护 DFS 序，所以可以统一处理路径和子树问题。

## 逐行代码解析

第一轮 DFS 计算父节点、深度、子树大小与重儿子：

```cpp
void dfs1(int x,int f){
	dep[x]=dep[f]+1;
	fah[x]=f;
	siz[x]=1;
	for(int i:G8[x]){
		if(i==f) continue;
		dfs1(i,x);
		siz[x]+=siz[i];
		if(siz[son[x]]<siz[i]) son[x]=i;
	}
}
```

- `dep[x] = dep[f] + 1`：深度 = 父节点深度 + 1。
- `fah[x] = f`：记录父节点。
- `siz[x] = 1`：子树大小先计入自身，再在循环里累加各子节点的 `siz`。
- `if (i == f) continue;`：跳过父节点，避免在无根树上往回走。
- `if (siz[son[x]] < siz[i]) son[x] = i;`：维护子树大小最大的重儿子；`son` 数组默认初始为 0，叶节点的重儿子保持 0。
- `G8[x]` 为原作者的邻接表（`vector<int> G8[N]`），即节点 $x$ 的所有邻接点。

第二轮 DFS 计算链顶、DFS 序编号与反向映射：

```cpp
//该代码中 seg[0] 表示当前节点数，需初始化为 0
void dfs2(int x,int f) {
	top[x]=f;
	seg[x]=++seg[0];
	rev[seg[0]]=x;
	if(son[x]) dfs2(son[x],f);
	for(int i:G8[x]){
	    if(i!=fah[x]&&i!=son[x]) dfs2(i, i);
	}
}
```

- `top[x] = f`：当前节点所在重链的链顶继承自参数 `f`。
- `seg[x] = ++seg[0]`：`seg[0]` 是全局计数器，先自增再赋值，得到当前节点的 DFS 序编号。
- `rev[seg[0]] = x`：记录反向映射，用于从序列下标找回原节点。
- `if (son[x]) dfs2(son[x], f);`：**先递归重儿子**，让重儿子继承同一链顶，保证重链上的节点 DFS 序连续。
- 轻儿子 `dfs2(i, i)`：轻儿子作为新重链的链顶，各自开一条新链。

## 复杂度分析

- **预处理（两次 DFS）**：每个节点各被访问一次，共 $O(n)$。树链剖分本身的复杂度是 $O(n)$ 的。
- **路径拆分**：由于沿一条轻边向下子树大小至少缩小一半，从任意节点向根移动最多经过 $O(\log n)$ 条轻边；一条路径从两端分别向上跳，因此任意两点之间的路径最多被拆成 $O(\log n)$ 条重链上的连续区间。
- **维护序列的额外开销**：把拆分出的区间交给线段树等数据结构维护时，通常要多一个 $\log$，即路径操作整体 $O(\log^2 n)$；子树操作对应单个连续区间，为 $O(\log n)$。
- **空间复杂度**：`fah`、`dep`、`siz`、`son`、`top`、`seg`、`rev` 各 $O(n)$，总空间 $O(n)$。

## 适用场景

- **树上路径修改/查询**：路径点权和、路径最值等，把路径拆成 $O(\log n)$ 段连续区间后交给线段树处理。
- **子树修改/查询**：利用「子树对应连续区间」的性质，一次区间操作即可完成，无需逐点遍历。
- **统一处理路径与子树问题**：树链剖分同时维护了链上的连续性与子树的连续性，是同时需要路径操作与子树操作时的方便统一方案。
- **维护 LCA**：跳链的过程天然可用于求最近公共祖先（本段未展开，可配合线段树或树状数组使用）。

## 常见陷阱与注意事项

1. **重儿子的选择标准**：用「子树大小最大」选重儿子，若多个儿子子树大小相同任选一个即可；选择标准不影响正确性，只影响重链的划分方式，任何划分方式都保证 $O(\log n)$ 的跳跃次数。
2. **`siz[x]` 要先初始化为 1**：子树大小包含节点自身，漏掉会把叶节点算成 0，导致重儿子选错。
3. **第二轮 DFS 必须先递归重儿子**：`if (son[x]) dfs2(son[x], f)` 要放在遍历轻儿子之前，否则重链上的节点在 DFS 序中不连续，后续区间操作会出错。
4. **叶节点无重儿子的判断**：`son` 数组默认初始为 0，叶节点的 `son[x]` 保持 0，`if (son[x])` 不能省，否则会递归到不存在的节点。
5. **`seg[0]` 计数器需初始化为 0**：`seg[x] = ++seg[0]` 依赖 `seg[0]` 从 0 开始，否则整棵树的编号会整体错位。
6. **根节点的父节点**：`fah[root]` 通常设为自身（或 0），防止第一轮 DFS 中误判；无根树建图时需用 `if (i == f) continue;` 跳过父节点，防止往回走。
7. **反向映射 `rev` 的作用**：当需要从 DFS 序下标找回原节点（如按序建树、单点定位、还原被查询区间的实际节点）时，`rev` 比再跑一遍逆映射更直接。

## 对比与扩展

| 剖分方式 | 选择标准 | 特点 |
|----------|----------|------|
| 重链剖分（HLD） | 子树大小最大的儿子 | 任意路径拆 $O(\log n)$ 段，OI 最常见、最通用 |
| 长链剖分 | 子树深度最大的儿子 | 适合维护与深度相关的信息，如求 $k$ 级祖先 |
| 实链剖分（LCT） | 动态维护 | 支持加边/删边等动态树操作，但常数更大、实现更复杂 |

维护序列的数据结构也可选择：

- **线段树**：支持区间修改/查询，是树链剖分最常用的搭配，路径操作 $O(\log^2 n)$。
- **树状数组**：常数更小，适合只需前缀和、或「单点修改 + 区间求和」等场景，同样可行。

此外，树链剖分相比树上差分更「在线」：树上差分适合离线、批量处理，而树链剖分支持在线查询与修改；当需要同时做路径与子树操作时，树链剖分是更统一的方案。
