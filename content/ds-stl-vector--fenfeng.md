## 算法原理

`vector` 是 C++ 标准模板库（STL）中最常用的**序列式容器**（sequence container），其底层是一片**连续内存**，元素在内存中依次相邻排列。连续存储带来两个直接好处：

1. **随机访问 $O(1)$**：`v[i]` 的地址可由首地址加偏移直接算出，无需像链表那样从头遍历。
2. **缓存友好**：遍历时按内存顺序访问，命中 CPU 缓存，常数很小。

vector 的核心机制是**动态扩容**。声明时通常只分配少量（甚至不分配）内存，当 `push_back` 使元素个数达到当前容量上限时，就重新分配一块更大的连续内存，把旧元素拷贝（或移动）过去，再释放旧内存。为了保证均摊效率，新容量一般按常数倍（约 2 倍，视实现而定）增长。

需要区分两个容易混淆的量：

- **`size()`（长度）**：当前实际存放的元素个数，记为 $n$。
- **`capacity()`（容量）**：当前已分配内存最多能容纳的元素个数，恒有 `size()` $\le$ `capacity()`。

此外，vector 重载了比较运算符（两容器按字典序逐元素比较）和赋值运算符（拷贝赋值、移动赋值），因此可以直接用 `==`、`<`、`=` 等对整个容器进行操作。

## 核心公式 / 状态定义与转移方程

vector 不是动态规划类结构，没有状态转移方程；它的核心刻画是「容量增长」与「均摊代价」之间的关系。

设扩容因子为常数 $c > 1$（常见 $c = 2$），从空 vector 开始连续执行 $n$ 次 `push_back`。第 $k$ 次扩容时容量从 $c^{k}$ 增长到 $c^{k+1}$，需要拷贝 $c^{k}$ 个旧元素。整个过程中因扩容产生的总拷贝次数是一个几何级数：

$$
T(n) = \sum_{k=0}^{\lfloor \log_c n \rfloor} c^{k} = \frac{c^{\lfloor \log_c n \rfloor + 1} - 1}{c - 1} \le \frac{c}{c - 1} \cdot n = O(n)
$$

把总代价 $O(n)$ 平摊到 $n$ 次 `push_back` 上，得到**均摊每次 $O(1)$**；其中恰好触发扩容的那一次操作，最坏代价为 $O(n)$。

随机访问按下标直接计算地址（`data()` 返回内部连续内存首元素的指针）：

$$
\text{address}(v[i]) = \text{data}() + i
$$

因此按下标访问是 $O(1)$。

## 逐行代码解析

本节按「声明与创建」「元素访问」「长度与容量」「元素增删与修改」四组给出关键用法，均为伪代码片段，不要求与任何完整程序一一对应。

### 声明与创建

```cpp
#include <vector>
using namespace std;

vector<int> v0;                                 // 1. 空 vector，常数复杂度
v0.reserve(3);                                  // 2. 预留 3 个元素的空间，之后插入前 3 个元素为常数复杂度
vector<int> v1(3);                              // 3. 长度 3，元素默认值 0，线性复杂度
vector<int> v2(3, 2);                           // 4. 长度 3，元素默认值 2，线性复杂度
vector<int> v4(v2);                             // 5. 拷贝构造，内容与 v2 相同，线性复杂度
vector<int> v5(v4.begin() + 1, v4.begin() + 3); // 6. 拷贝区间 [v4[1], v4[2])，线性复杂度
vector<int> v6(std::move(v2));                  // 7. 移动构造，不发生拷贝，常数复杂度（需 C++11）
```

- `reserve(n)` 只改容量不改长度，是提前避免多次扩容拷贝的关键。
- 构造函数 `(n)`、`(n, val)`、拷贝构造、区间构造都是线性复杂度（需要逐个构造元素）。
- 移动构造 / 移动赋值把旧容器的内存指针直接“接管”过来，旧容器被置空，因此是常数复杂度。

### 元素访问

```cpp
v.at(pos);   // 返回下标 pos 的引用；越界抛出 std::out_of_range 异常
v[pos];      // 返回下标 pos 的引用；不检查越界（越界是未定义行为）
v.front();   // 返回首元素的引用
v.back();    // 返回末尾元素的引用
v.data();    // 返回内部连续内存首元素的指针
```

- `at()` 与 `operator[]` 的区别在于是否做边界检查：`at()` 越界会抛出异常，`operator[]` 越界是未定义行为但常数更小。

### 长度与容量

```cpp
v.empty();          // 是否为空，等价于 v.begin() == v.end()
v.size();           // 元素个数，即 std::distance(v.begin(), v.end())
v.resize(n);        // 把长度改为 n：n 变大时补默认值，n 变小时删除末尾元素
v.max_size();       // 容器理论上可容纳的最大元素数
v.reserve(n);       // 预留容量，避免反复分配与拷贝
v.capacity();       // 当前容量（已分配空间可容纳的元素数）
v.shrink_to_fit();  // 把容量收缩到与长度一致，释放多余内存
```

### 元素增删与修改

```cpp
v.clear();       // 清空所有元素（长度归 0，容量不变）
v.insert(it, x); // 在迭代器 it 处插入 x；复杂度与 it 到末尾的距离成线性
v.erase(it);     // 删除迭代器 it 处的元素，返回下一个有效迭代器
v.push_back(x);  // 在末尾插入 x；均摊 O(1)，最坏 O(n)（触发扩容）
v.pop_back();    // 删除末尾元素；O(1)
v.swap(w);       // 与另一个 vector 交换全部内容；O(1)
```

- `insert` / `erase` 在中间操作时，需要把之后的所有元素整体后移或前移，所以是线性复杂度，这是连续内存容器的固有代价。
- `swap` 只交换两个容器内部指向内存的指针，不搬动元素，因此是常数复杂度。

## 复杂度分析

| 操作 | 时间复杂度 | 说明 |
|---|---|---|
| 随机访问 `v[i]` / `at` / `front` / `back` / `data` | $O(1)$ | 连续内存，按地址直接计算 |
| `push_back`（末尾插入） | 均摊 $O(1)$，最坏 $O(n)$ | 扩容时最坏线性，均摊常数 |
| `pop_back`（末尾删除） | $O(1)$ | 只减少长度 |
| `insert` / `erase`（中间操作） | $O(n)$ | 与操作位置到末尾的距离成正比 |
| `resize` / `reserve` / `shrink_to_fit` | $O(n)$ | 需要重建或搬移元素 |
| `clear` | $O(n)$ | 逐个析构元素 |
| `swap` | $O(1)$ | 交换内部指针 |

空间复杂度为 $O(n)$，实际占用由 `capacity()` 决定，通常介于 $n$ 与 $2n$ 之间（视扩容策略而定）。

## 适用场景

**适用**：
- 需要**连续内存**和 **$O(1)$ 随机访问**的场景，如普通数组的「动态长度替代品」。
- 元素只（或几乎只）在**末尾**增删，如记录答案、按顺序收集结果。
- 需要整体遍历、排序、二分查找：配合 `sort`、`lower_bound`、`upper_bound` 使用。
- 需要存储大量数据但长度事先未知、或长度会动态变化的场景。

**不适用**：
- 频繁在**头部或中间**插入 / 删除：每次都要 $O(n)$ 搬移，应改用 `deque` 或 `list`。
- 数据规模巨大且上限已知：静态数组常数更小、无扩容开销。
- 需要元素地址长期稳定（例如已取得元素指针后继续扩容）：扩容会整体搬移，地址失效。

## 常见陷阱与注意事项

1. **`size()` 与 `capacity()` 不要混淆**
   - `size()` 是元素个数，`capacity()` 是已分配容量，两者通常不同。
   - 循环 `for (int i = 0; i < v.size(); i++)` 用 `size`；判断“还能不能装”用 `capacity`。

2. **迭代器 / 指针 / 引用失效**
   - 触发扩容、或发生 `insert` / `erase` / `resize` / `clear` 时，之前保存的迭代器、指针、引用可能失效。
   - 尤其不要写 `auto *p = &v[0]; v.push_back(x);` 后继续使用 `p`——扩容后 `p` 已悬空。

3. **`at()` 与 `operator[]` 的边界检查差异**
   - `at(pos)` 越界抛出 `std::out_of_range`，便于定位问题；`operator[]` 越界是未定义行为，可能读到垃圾值甚至崩溃。
   - 竞赛中为追求常数常用 `operator[]`，但必须自行保证下标合法。

4. **`reserve()` 与 `resize()` 的区别**
   - `reserve(n)` 只把容量调到至少 $n$，**不改变长度**，此时 `v[i]` 仍不可直接访问。
   - `resize(n)` 改变长度：变长时新元素用默认值（或指定值）填充。

5. **`clear()` 不释放内存**
   - `clear()` 后 `size()` 归 0，但 `capacity()` 不变，内存仍被占用。
   - 若要真正释放，用 `vector<int>().swap(v)` 或 `shrink_to_fit()`。

6. **`size()` 返回无符号类型**
   - `v.size()` 的类型是 `size_t`（无符号），`v.size() - 1` 在空容器时会下溢成巨大的无符号数。
   - 与有符号整数比较、相减时要小心，倒序循环建议写成 `for (int i = (int)v.size() - 1; i >= 0; i--)`。

7. **`vector<bool>` 是特化容器**
   - `vector<bool>` 按位压缩存储，元素不是真正的 `bool&`，`&v[0]` 这类取地址操作会编译失败。
   - 需要真正的 `bool` 数组时用 `vector<char>` 或 `std::bitset`。

## 对比与扩展

| 容器 | 底层结构 | 随机访问 | 头部/中间插入 | 内存连续 |
|---|---|---|---|---|
| `vector` | 动态数组 | $O(1)$ | $O(n)$ | 是 |
| `array` | 静态数组 | $O(1)$ | 不支持 | 是 |
| `deque` | 分段数组 | $O(1)$ | 头尾 $O(1)$，中间 $O(n)$ | 否 |
| `list` | 双向链表 | $O(n)$ | $O(1)$ | 否 |

**扩展**：
- **多维 vector**：`vector<vector<int>>` 可表示二维矩阵，但每行的 `vector` 各自独立分配内存，整体并不连续。
- **作为其他容器的底层**：`std::priority_queue` 默认基于 `vector` 实现，`std::stack` 也可指定 `vector` 作为底层容器。
- **手写动态数组**：理解扩容的均摊分析后，可以用「数组 + 记录 size/capacity + 扩容翻倍」手写一个简易版，加深对 STL 的理解；但实际使用中直接调用 `std::vector` 更安全、更高效。
