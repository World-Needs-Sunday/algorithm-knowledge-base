## 算法原理

匈牙利算法（Hungarian Algorithm）由匈牙利数学家 König 和 Egerváry 的理论发展而来，是求解**二分图最大匹配**的经典算法。核心思想基于**增广路定理**：一个匹配是最大匹配，当且仅当图中不存在增广路。

### 基本概念

**二分图匹配**：在二分图 $G = (A \cup B, E)$ 中，选取一组边 $M \subseteq E$，使得 $M$ 中任意两条边没有公共端点，则 $M$ 称为一个匹配。边数最多的匹配称为**最大匹配**。

**增广路**：设 $M$ 是当前匹配。一条从**未匹配点**出发，交替经过**非匹配边**和**匹配边**，最终到达另一侧的**未匹配点**的路径，称为增广路（Augmenting Path）。

增广路的长度一定是奇数，且首尾都是非匹配边。

### 增广路定理

**定理**：一个匹配 $M$ 是最大匹配 $\Leftrightarrow$ 图中不存在关于 $M$ 的增广路。

**推论**（增广路算法的正确性基础）：如果能找到一条增广路 $P$，将 $P$ 上的匹配边与非匹配边互换，匹配数增加 1。反复寻找增广路直到不存在，即得到最大匹配。

### 算法框架

1. 初始匹配为空集
2. 遍历左部每个未匹配点 $u$，尝试从 $u$ 出发寻找增广路
3. DFS 搜索：对 $u$ 的每个邻接点 $v$
   - 若 $v$ 未被匹配：直接匹配 $u \leftrightarrow v$，增广成功
   - 若 $v$ 已匹配给 $w$：递归尝试为 $w$ 寻找新的匹配，若成功则将 $v$ 让给 $u$
4. 若所有左部点都尝试完毕，当前匹配即为最大匹配

### 时间戳优化

朴素实现中，每次 DFS 前需要清空 `vis` 数组标记右侧节点的访问状态。本代码使用**时间戳优化**：用整数 `t` 标记当前轮次，`vis[i] == t` 表示节点 $i$ 在本轮 DFS 中已访问，无需每次清空数组，将每次增广的初始化代价从 $O(m)$ 降为 $O(1)$。

## 核心公式/状态定义与转移方程

### 状态定义

| 变量 | 含义 |
|------|------|
| `edges[u]` | 左部点 $u$ 的邻接表，存储所有可到达的右部点 |
| `match[v]` | 右部点 $v$ 当前匹配的左部点编号，0 表示未匹配 |
| `vis[v]` | 右部点 $v$ 的访问时间戳，记录是第几轮 DFS 访问的 |
| `t`（DFS 参数） | 当前轮次标识，等于当前左部点编号 $i$ |

### 转移方程

对左部点 `idx`，DFS 寻找增广路的递归逻辑：

$$
\text{dfs}(u, t) =
\begin{cases}
\text{true} & \exists\, v \in \text{edges}[u],\; \text{vis}[v] \neq t,\; \text{match}[v] = 0 \\
\text{true} & \exists\, v \in \text{edges}[u],\; \text{vis}[v] \neq t,\; \text{dfs}(\text{match}[v], t) = \text{true} \\
\text{false} & \text{否则}
\end{cases}
$$

成功时更新 `match[v] = u`。

### 增广路的结构

一条增广路形如：

$$
u_0 \xrightarrow{\text{非匹配}} v_0 \xrightarrow{\text{匹配}} u_1 \xrightarrow{\text{非匹配}} v_1 \xrightarrow{\text{匹配}} \cdots \xrightarrow{\text{非匹配}} v_k
$$

其中 $u_0$ 和 $v_k$ 是未匹配点。取反后匹配数 $+1$。

## 逐行代码解析

### 全局变量定义

```cpp
vector<vector<int>> edges;  // 左边点的邻接表
vector<int> match;           // 右边节点配对的左边点
vector<int> vis;             // 右边节点访问时间戳
int top;                      // （未使用）
```

- `edges`：只存**左部→右部**的有向边（二分图匹配中边是单向使用的）
- `match`：下标是右部点，值是左部点，`match[v] = u` 表示 $v$ 匹配了 $u$，0 表示未匹配
- `vis`：时间戳数组，`vis[v] = t` 表示 $v$ 在第 $t$ 轮 DFS 中被访问过

### 初始化函数

```cpp
void init(int n, int m)
{
	edges.assign(n + 1, vector<int>());
	vis.assign(m + 1, false);
	match.assign(m + 1, 0);
	top = 0;
}
```

- `edges.assign(n + 1, ...)`：为 $n$ 个左部点分配邻接表
- `vis.assign(m + 1, false)`：时间戳初始化为 0（所有轮次标识都大于 0，故等价于"未访问"）
- `match.assign(m + 1, 0)`：所有右部点初始未匹配

### DFS 增广核心函数

```cpp
bool dfs(int idx, int t)
{
	for (int i : edges[idx])
	{
		if (vis[i] == t) continue;    // 本轮已访问，跳过
		vis[i] = t;                    // 标记本轮已访问
		if (!match[i] || dfs(match[i], t))  // 右部点未匹配 或 其匹配者可换边
		{
			match[i] = idx;            // 将右部点 i 匹配给左部点 idx
			return true;               // 增广成功
		}
	}
	return false;                      // 所有邻接点都无法增广
}
```

逐行分析关键行：

1. **`if (vis[i] == t) continue;`**：时间戳判重。若 $i$ 在本轮已被访问，说明从 $i$ 出发的递归增广已经失败过，无需重复尝试。这一步保证了每个右部点在单轮 DFS 中最多被访问一次。

2. **`vis[i] = t;`**：在递归前标记访问，防止递归过程中形成环（同一右部点被多次访问导致死循环）。

3. **`if (!match[i] || dfs(match[i], t))`**：增广的两种成功情况：
   - `!match[i]`：右部点 $i$ 未匹配，直接匹配，增广成功
   - `dfs(match[i], t)`：右部点 $i$ 已匹配给 `match[i]`，递归尝试为 `match[i]` 寻找新的匹配。若成功，则 $i$ 让给当前节点 `idx`

4. **`match[i] = idx;`**：更新匹配关系。注意此时可能已经递归修改了 `match[i]` 原匹配者的匹配关系，所以这里只需设置 $i$ 的新匹配。

### 主函数

```cpp
int main()
{
	ios::sync_with_stdio(false);
	cin.tie(nullptr); cout.tie(nullptr);
	int n, m, e;
	cin >> n >> m >> e;
	init(n, m);
	for (int i = 1; i <= e; i++)
	{
		int u, v;
		cin >> u >> v;
		edges[u].emplace_back(v);
	}
	int cnt = 0;
	for (int i = 1; i <= n; i++)
	{
		if (dfs(i, i)) ++cnt;
	}
	cout << cnt;
	return 0;
}
```

关键点：

- **输入**：$n$ 个左部点，$m$ 个右部点，$e$ 条边。边只从左到右添加（单向）
- **`dfs(i, i)`**：第 $i$ 轮 DFS 的时间戳就是 $i$ 本身，这样每轮的时间戳天然唯一，无需额外维护计数器
- **`cnt`**：统计成功增广的次数，即最大匹配数

## 复杂度分析

### 时间复杂度：$O(nm)$

- 外层循环遍历 $n$ 个左部点，每次调用 DFS
- 单次 DFS 最坏情况遍历所有 $m$ 条边（递归深度可达 $n$）
- 总复杂度 $O(n \cdot m)$，其中 $n$ 为左部点数，$m$ 为边数

实际运行中，由于时间戳判重使每个右部点在单轮 DFS 中最多访问一次，单轮 DFS 的实际复杂度更接近 $O(m)$ 而非 $O(nm)$，但最坏上界仍为 $O(nm)$。

### 空间复杂度：$O(n + m)$

- 邻接表 `edges`：$O(n + m)$（$n$ 个左部点的邻接表，共 $m$ 条边）
- `match` 数组：$O(m)$
- `vis` 数组：$O(m)$
- DFS 递归栈深度：最坏 $O(n)$

## 适用场景

### 适用场景

1. **二分图最大匹配**：最基本的用途，如任务分配、人员调度
2. **二分图最小点覆盖**：由 König 定理，最小点覆盖数 = 最大匹配数
3. **二分图最大独立集**：最大独立集 = 顶点总数 $-$ 最大匹配数
4. **最小路径覆盖**：将 DAG 拆分为最少路径，需先拆点二分图化再用匈牙利算法
5. **棋盘问题**：将棋盘黑白染色后建二分图，求解最多放置互不攻击的棋子数

### 不适用场景

1. **一般图最大匹配**：匈牙利算法仅适用于二分图，一般图需用带花树（Blossom Algorithm）
2. **带权最大匹配**：需要最大权匹配时，应使用 KM 算法（Kuhn-Munkres）
3. **超大规模二分图**：$n, m$ 极大（如 $10^6$ 级）时，$O(nm)$ 可能超时，需考虑 Hopcroft-Karp 算法

## 常见陷阱与注意事项

### 1. 建图方向

二分图匹配中，邻接表**只需从左部到右部单向建边**。如果双向建边，DFS 时可能错误地从右部走回左部，导致逻辑混乱。代码中 `edges[u].emplace_back(v)` 只加了左→右的边。

### 2. 时间戳的唯一性

代码中 `dfs(i, i)` 直接用左部点编号 $i$ 作为时间戳。这要求左部点编号从 1 开始且互不相同。如果左部点编号有特殊含义（如从 0 开始），需要改为 `dfs(i, i + 1)` 或使用独立的时间戳计数器，确保时间戳不为 0（因为 `vis` 初始值为 0 表示未访问）。

### 3. match 数组的语义

`match[v]` 存的是右部点 $v$ 匹配的**左部点编号**，不是反过来。如果混淆左右部语义，会导致输出结果错误。

### 4. 多组数据的初始化

如果有多组测试数据，每次必须调用 `init` 清空 `edges`、`match`、`vis`。忘记初始化是常见的 WA 原因。

### 5. 自环边和重边

二分图中不应有自环（左部和右部是不同集合，自环无意义）。重边不影响正确性但浪费空间，可以在加边时去重。

### 6. 左右部点数不对称

代码中 $n$（左部）和 $m$（右部）可以不相等。遍历左部点 $1 \sim n$ 即可，不需要遍历右部点。最大匹配数 $\leq \min(n, m)$。

### 7. `top` 变量未使用

代码中全局变量 `top` 声明了但未使用，属于冗余代码，可以删除。

## 对比与扩展

### 与 Hopcroft-Karp 算法对比

| 对比维度 | 匈牙利算法 | Hopcroft-Karp |
|----------|-----------|----------------|
| 核心思想 | 单条增广路逐次增广 | 每轮找一组最短增广路批量增广 |
| 时间复杂度 | $O(nm)$ | $O(m\sqrt{n})$ |
| 实现难度 | 简单，DFS 递归 | 较复杂，需 BFS 分层 + DFS |
| 适用规模 | $n, m \leq 500$ | $n, m \leq 10^5$ |
| 常数因子 | 小 | 稍大（BFS 分层开销） |

### 与 KM 算法对比

| 对比维度 | 匈牙利算法 | KM 算法 |
|----------|-----------|---------|
| 问题类型 | 无权最大匹配 | 带权最大权匹配 |
| 时间复杂度 | $O(nm)$ | $O(n^3)$ |
| 核心思想 | 增广路 | 顶标 + 相等子图 + 增广 |
| 适用场景 | 无权二分图 | 每条边有权值，求权值和最大的匹配 |

### 扩展：Konig 定理

二分图中有三个经典等式：

- **最小点覆盖 = 最大匹配数**：选择最少的顶点覆盖所有边
- **最大独立集 = 顶点总数 $-$ 最大匹配数**：选择最多的互不相邻的顶点
- **最小路径覆盖 = 顶点总数 $-$ 最大匹配数**（DAG 上，拆点后）

这些定理使匈牙利算法成为解决二分图各类覆盖、独立集问题的核心工具。

### 扩展：一般图最大匹配

一般图（非二分图）的最大匹配需要处理**奇环**（花，Blossom）的情况。带花树算法（Edmonds' Blossom Algorithm）通过"缩花"操作将奇环收缩为一个点，时间复杂度 $O(n^3)$，是匈牙利算法在一般图上的推广。
