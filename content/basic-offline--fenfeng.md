## 算法原理

离线操作是 OI 中一种常见的思想，而非某个具体算法：当「按输入顺序逐个处理」比较困难时，把全部操作（询问、修改等）一次性读入，再按某种合适的顺序统一处理，最后按原始编号还原并输出答案。

其本质是**用「重排操作顺序」换取「更低的单次处理代价」**。很多问题的难点在于按原顺序处理时状态难以维护，或者需要大量重复计算；离线后可以先做预处理、按关键字排序、增量维护答案，从而把重复运算合并、把单次代价摊薄。

与「在线」相对：在线要求对每个询问实时给出答案，且不能预知后续输入；离线则允许看到全部输入后再决定处理顺序。典型流程可概括为三步：**读入全部操作 → 按规则排序或预处理 → 还原输出**。

示例：询问序列原本是 $q_1,q_2,q_3$，若题目允许离线，可按左端点、右端点或时间等关键字排序，变成 $q_2,q_1,q_3$ 处理，处理结束后再按每个询问的原始编号还原输出顺序。

一般情况下，离线算法实现更简单，有时复杂度也更低；但离线也可能被「卡」：若每个询问的真实输入依赖上一次的答案（强制在线），询问就变得不确定，无法离线，这也在变相提示正确解法必须在线。

## 核心公式 / 状态定义与转移方程

离线操作本身没有统一的公式，但可以把「重排后的状态维护」抽象成一个通用模型。

设共有 $m$ 个询问 $q_1,\dots,q_m$，离线允许选择一个重排 $\pi$，依次处理 $q_{\pi(1)},\dots,q_{\pi(m)}$，得到 $ans_{\pi(k)}$，最后按原始编号还原出 $ans_1,\dots,ans_m$。

状态定义：处理到第 $k$ 个询问时，维护一个「当前状态」$S_k$（例如前缀 $[1,r]$ 的统计信息、当前区间 $[l,r]$ 的答案、当前并查集的连通状态等），以及指向当前询问的指针。

转移：从上一个询问的状态 $S_{k-1}$ 移动到当前询问的状态 $S_k$。以莫队维护区间为例，设当前区间为 $[l,r]$，目标区间为 $[l',r']$，指针总移动量为：

$$
\lvert l-l' \rvert + \lvert r-r' \rvert
$$

排序（即选择重排 $\pi$）的目标就是让所有询问之间指针移动的总量尽可能小，从而摊薄单次更新的代价。不同离线算法只在这个「重排规则」和「状态增量维护」上有所区别。

## 逐行代码解析

以下为离线操作的三步思想框架（伪代码，非可运行程序）：

```cpp
// 第 1 步：一次性读入全部询问，并记录原始编号
for (int i = 1; i <= m; i++) {
    read(q[i]);            // 读入第 i 个询问
    q[i].id = i;           // 记录原始编号，供最后还原输出
}
// 第 2 步：按关键字排序（左端点 / 右端点 / 时间 / 权值 / 分块）
sort(q + 1, q + m + 1, cmp);
// 第 3 步：按新顺序增量维护答案
for (int i = 1; i <= m; i++) {
    move(state, q[i]);     // 把当前状态"移动"到 q[i]（增删元素 / 合并 / 撤销）
    ans[q[i].id] = answer(state);
}
// 最后按原始编号 1..m 统一输出 ans[]
```

几个关键点：

- 每个询问都要额外记录原始编号 `id`，否则处理完后无法还原输出顺序。
- 排序规则 `cmp` 由具体算法决定：按右端点排序配合树状数组处理区间统计、按权值排序配合并查集处理连通性、按时间排序处理带时间限制的询问、按分块规则排序（莫队）。
- 第 3 步的「移动」必须支持增量维护：能新增一个元素、删除一个元素（或撤销一步修改），否则无法在相邻询问之间高效转移。

## 复杂度分析

离线操作是思想而非固定算法，复杂度取决于所选的排序规则与状态增量维护方式，故**视具体实现**。

- **时间复杂度**：一般是「排序代价 + 增量维护代价」，例如莫队为 $O(n\sqrt n)$ 级别，扫描线为 $O(n\log n)$ 级别。
- **空间复杂度**：通常只需存下全部操作（$O(m)$）以及当前状态所需的空间，**视具体实现**。

## 适用场景

- 区间查询：多个区间询问可以按右端点或左端点排序后增量处理（扫描线、莫队）。
- 带时间或权值维度的询问：按时间或权值排序后配合并查集、树状数组等维护。
- 需要大量重复预处理的题目：离线后先做一次预处理，避免对每个询问重复计算。
- 多版本、可撤销的问题：把操作组织成树，用 DFS 进入或离开节点时分别执行或撤销操作（撤销与可持久化）。

## 常见陷阱与注意事项

1. **忘记记录原始编号**：离线排序后会打乱顺序，不存 `id` 就无法按原顺序输出答案。
2. **被「强制在线」卡掉**：若每个询问的输入依赖上一次的答案，询问不确定，无法离线，此时必须换在线做法。
3. **相邻状态转移必须可撤销**：莫队删除端点、撤销合并等要求操作可逆；不可逆时不能直接套用离线框架。
4. **排序代价别忽略**：离线省了单次代价，但排序本身有 $O(m\log m)$ 开销，$m$ 很小时离线未必划算。
5. **题目未允许离线时不能擅自重排**：只有保证输出只依赖最终答案、不依赖处理过程顺序时才可离线。

## 对比与扩展

| 方法 | 思想 | 常见复杂度 | 典型用途 |
|---|---|---|---|
| 在线处理 | 逐个询问实时回答 | 视具体实现 | 强制在线、询问依赖上次答案 |
| 离线排序 | 读入全部后按关键字排序 | 排序 $O(m\log m)$ + 增量维护 | 区间统计、连通性、时间维 |
| 扫描线 | 按右端点排序，从左到右扫描 | $O(n\log n)$ | 区间或二维几何问题 |
| 莫队 | 按分块规则排序，移动区间端点 | $O(n\sqrt n)$ | 无修改的区间询问 |
| 撤销与可持久化 | 操作组织成树，DFS 进出时执行或撤销 | 视具体实现 | 多版本、可撤销修改 |

扩展方向：离线操作常与树状数组、线段树、并查集（按秩合并支持撤销）、莫队、可持久化数据结构等结合使用；理解离线思想也是学习莫队、扫描线、整体二分、CDQ 分治等进阶技巧的基础。
