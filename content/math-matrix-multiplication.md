# 矩阵乘法

## 一、问题定义

读入两个矩阵 $A$ 和 $B$，计算它们的乘积 $C = A \times B$；如果维度不满足相乘条件，则输出错误提示。

**矩阵乘法的两条铁律**：

1. **可乘条件**：$A$ 是 $n \times k$ 矩阵、$B$ 是 $k \times m$ 矩阵时才能相乘，即 $A$ 的列数必须等于 $B$ 的行数，否则乘法无定义。
2. **结果形状**：乘积 $C$ 是 $n \times m$ 矩阵，其中：

$$C[i][j] = \sum_{t=1}^{k} A[i][t] \times B[t][j]$$

用文字说：$C$ 的第 $i$ 行第 $j$ 列 = $A$ 的第 $i$ 行 与 $B$ 的第 $j$ 列对应元素乘积之和（行乘列，点积）。

整个程序是典型的"输入 → 处理 → 输出"三段式结构：一个函数负责读入，一个函数负责判维 + 三重循环计算，一个函数负责输出。

## 二、数据结构设计

### 1. 为什么用 vector<vector<long long>>

- 二维 vector 天然对应"矩阵 = 行的序列"，每行是一个一维 vector，行列数可任意指定，无需预设最大规模。
- **long long 的必要性**：矩阵乘法中元素要先乘再加。两个 $10^5$ 量级的数相乘已达 $10^{10}$，超出 int（上限约 $2.1 \times 10^9$）的表示范围。用 long long（上限约 $9.2 \times 10^{18}$）是防止溢出的标准做法。

### 2. 为什么采用 1-based 下标

```cpp
mat.assign(n + 1, vector<long long>(m + 1, 0));
// 读入循环: i = 1..n, j = 1..m
```

- 数学公式中矩阵下标习惯从 1 开始，代码下标与公式下标直接一一对应，写三重循环时无需做"第 i 行其实是下标 i-1"的心算换算，降低出错概率。
- 代价是第 0 行、第 0 列的空间闲置，开销可忽略。
- 这个约定会统一约束后面所有函数的循环边界——全程序保持同一套下标语义是正确性的基础。

## 三、模块一：read_mat —— 读入

```cpp
void read_mat(vector<vector<long long>>& mat)
{
    int n, m;
    cin >> n >> m;
    mat.assign(n + 1, vector<long long>(m + 1, 0));
    for (int i = 1; i <= n; i++)
    {
        for (int j = 1; j <= m; j++)
        {
            cin >> mat[i][j];
        }
    }
}
```

**要点**：

| 细节 | 说明 |
|------|------|
| 按引用传参 `&` | 读入的目的是修改外部矩阵，必须传引用，否则函数内部的赋值会随函数结束而丢失 |
| `assign` 一石二鸟 | 既分配空间，又把所有元素初始化为 0——后续累加所需的"清零"在此一并完成 |
| 行优先读入 | 外层扫行、内层扫列，与输入格式"每行 m 个数"一致 |

## 四、模块二：mul_mat —— 判维与计算（核心）

### 1. 判维：失败信号的设计

```cpp
if (A[1].size() != B.size()) return vector<vector<long long>>();
```

**如何表达"A 的列数"？** 存储时每行开了 m+1 个格子，所以 `A[1].size() = 列数_A + 1`；同理 `B.size() = 行数_B + 1`。于是"列 A = 行 B"的判断写成：

$$\text{列}_A + 1 = \text{行}_B + 1 \iff A[1].size() == B.size()$$

两边的 "+1" 恰好互相抵消，判维条件与数学条件完全等价——这是 1-based 设计的一个"红利"：带偏差的量直接比较，偏差自动消掉。

> 前提是全程序统一使用 1-based 语义，若某处改用 0-based 或漏写/多写 "+1"，判维即失效。

**失败时返回空矩阵**：`vector<vector<long long>>()`（size 为 0）。这是一个干净的信号设计：
- 乘法函数不负责打印错误，保持"计算与 IO 分离"
- 调用方只需检查 `.empty()` 即可区分成功/失败
- 正常矩阵至少有 1 行，永远不会与"空"混淆，无歧义

### 2. 三重循环：标准矩阵乘法

```cpp
int n = A.size(), m = B[1].size();
vector<vector<long long>> ans(n, vector<long long>(m, 0));
for (int i = 1; i < n; i++)
{
    for (int j = 1; j < m; j++)
    {
        for (int k = 1; k < A[1].size(); k++)
        {
            ans[i][j] += A[i][k] * B[k][j];
        }
    }
}
```

对照公式逐个对应：

| 循环变量 | 数学含义 | 范围 |
|---------|---------|------|
| `i` | 结果的行号 = A 的行号 | 1 .. 行A |
| `j` | 结果的列号 = B 的列号 | 1 .. 列B |
| `k` | 公共维度（A 的列 = B 的行） | 1 .. 列A |

**几个细节**：

- **结果的形状**：开 `A.size() × B[1].size()`，即 `(行A+1) × (列B+1)`，有效区域正是 行A × 列B。n、m 的取值各带一个 "+1"，但配合"从 1 开始、以 `<` 为上界"的循环写法，实际遍历的恰好是有效区。
- **内层乘积**：`A[i][k] * B[k][j]` —— A 取第 i 行第 k 个，B 取第 k 行第 j 列，正是"行乘列"的点积结构。
- **`+=` 累加而非赋值**：k 循环把 k 个乘积逐个加到 `ans[i][j]` 上；assign 时已置 0，无需额外清零。
- **循环顺序**：`i-j-k` 顺序可读性最好、最不易写错。若追求缓存友好性可改为 `i-k-j` 顺序（对 B 按行连续访问），属于性能优化，不影响正确性。

### 3. 规范性建议

`mul_mat` 不修改 A、B，签名宜写成 `const vector<vector<long long>>&`——既是 C++ 的良好实践，也能在编译期防止函数体内误改。

## 五、模块三：write_mat —— 输出

```cpp
void write_mat(const vector<vector<long long>>& mat)
{
    if (mat.empty())
    {
        cout << "NO mull" << ' ';
        return;
    }
    for (int i = 1; i < mat.size(); i++)
    {
        for (int j = 1; j < mat[1].size(); j++)
        {
            cout << mat[i][j] << ' ';
        }
        cout << '\n';
    }
}
```

### 1. 先处理失败分支

接住 mul_mat 返回的空矩阵，打印错误提示后提前返回。提示语的具体措辞以题目要求为准。

### 2. 输出循环的核心纪律

**行下标 `i` 配 `mat.size()`（行数 + 1），列下标 `j` 配 `mat[1].size()`（列数 + 1）**，谁是行、谁是列，与 `mat[i][j]` 中下标的位置严格对应。

由于全程使用统一的 1-based + `<` 上界写法，任意形状的矩阵（方阵、1×N、N×1）都能正确遍历、不会越界。

> **测试建议**：验证输出逻辑时，测试用例应同时覆盖方阵和长方形（如 1×3、3×1 的结果）。方阵具有行列对称性，无法区分"行上界"和"列上界"是否配对正确；只有长方形用例才能完整检验行列对应关系。

### 3. 输出格式细节

每行末尾会多打一个空格（`cout << mat[i][j] << ' '` 无差别打印）。多数判题器可容忍；若题目对格式要求严格，可改为"元素间以空格分隔、行末不留空格"的写法，例如先输出第一个元素，其余元素前各补一个空格。

## 六、main 函数：串联三段式

```cpp
int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr); cout.tie(nullptr);
    vector<vector<long long>> A, B, ans;
    read_mat(A), read_mat(B);   // 输入
    ans = mul_mat(A, B);        // 处理(含判维)
    write_mat(ans);             // 输出(含失败分支)
    return 0;
}
```

流程清晰：读 A、读 B、乘、打。所有分支逻辑（成功输出矩阵 / 失败输出提示）封装在 mul_mat 和 write_mat 内部，main 只负责调度——这种结构便于单独测试每个模块，也是 IO 与算法分离的标准组织方式。

## 七、手动示例

设：

$$A = \begin{bmatrix} 1 & 2 \\ 3 & 4 \end{bmatrix},\quad B = \begin{bmatrix} 5 & 6 \\ 7 & 8 \end{bmatrix}$$

计算 $C = A \times B$：

| C[i][j] | 计算过程 | 结果 |
|---------|---------|------|
| C[1][1] | 1×5 + 2×7 = 5 + 14 | 19 |
| C[1][2] | 1×6 + 2×8 = 6 + 16 | 22 |
| C[2][1] | 3×5 + 4×7 = 15 + 28 | 43 |
| C[2][2] | 3×6 + 4×8 = 18 + 32 | 50 |

$$C = \begin{bmatrix} 19 & 22 \\ 43 & 50 \end{bmatrix}$$

## 八、复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | $O(n \times m \times k)$ | 三重循环，行A × 列B × 公共维度k；方阵情形即经典的 $O(n^3)$ |
| 空间 | $O(n \times m)$ | 三个矩阵，总计 $O(nm)$ |

这是朴素矩阵乘法的标准复杂度；更大规模需借助分块或 Strassen 类算法，常规题目无此需求。

## 九、常见陷阱

1. **行列上界的配对**：任何遍历中，行下标必须配 `mat.size()`、列下标必须配 `mat[1].size()`，与 `mat[i][j]` 中两个下标的位置严格对应。测试时必含长方形用例（如 1×3、3×1），因为方阵的对称性无法暴露行列配对错误。
2. **下标语义的全局一致性**：判维条件 `A[1].size() == B.size()` 成立的前提是全程统一 1-based 存储（各带一个 "+1"，比较时抵消）。若某处改用 0-based 或漏写/多写 "+1"，判维即失效。
3. **内层乘积下标顺序**：`A[i][k] * B[k][j]`，i 对应 A 的行、k 是公共维、j 对应 B 的列，书写时按公式逐位核对。
4. **传引用**：读入函数必须以 `&` 接收矩阵参数，否则修改不生效；只读参数建议加 `const`。
5. **数据类型**：乘加运算默认使用 long long，防止溢出；若元素接近 $10^9$ 且公共维度很大，需估算累加上界确认不超 $9.2 \times 10^{18}$。
6. **行末空格**：视判题器严格程度决定是否消除；严格题采用"首元素外均前置空格"的写法。
7. **边界输入**：若题目保证 n, m ≥ 1 则无需处理；若允许 0×0 矩阵，需在入口处先行判断，避免访问 `A[1]` 时下标越界。

## 十、扩展与延伸

- **矩阵快速幂**：利用矩阵乘法的结合律，通过快速幂的思想计算 $A^k$，常用于线性递推加速（如斐波那契第 n 项的 $O(\log n)$ 求解）。
- **矩阵乘法的结合律**：$(A \times B) \times C = A \times (B \times C)$，但**不满足交换律**：$A \times B \neq B \times A$（维度都不一定匹配）。
- **单位矩阵**：主对角线为 1、其余为 0 的方阵，满足 $A \times I = I \times A = A$，是矩阵快速幂的初始值。
- **Strassen 算法**：利用分治策略将矩阵乘法降到约 $O(n^{2.807})$，竞赛中几乎不用，了解即可。
