## 算法原理

虚树是解决**树上多组询问动态规划问题**的一种高效技巧，主要用于**树上选点 DP**：当每次询问只涉及整棵树中极少数的「关键点」时，把与询问无关的节点剥掉，只保留关键点以及连接它们所必需的节点，得到一棵规模大幅缩小的树，再在这棵小树上做 DP。

### 问题引入

给定一棵 $n$ 个节点的树，边有边权。有 $q$ 次询问，每次询问给出一个关键点集合 $S$（设大小为 $k$），要求统计 $S$ 中所有点对之间距离的总和。数据保证 $\sum k \le 5 \times 10^5$，$n, q \le 10^5$。

如果对每次询问都在整棵树上暴力跑一遍 $O(n)$ 的树形 DP，总复杂度为 $O(nq)$，无法通过。但注意：每次真正关心的点只有 $k$ 个，其余节点都是「陪跑」。于是可以把这 $k$ 个关键点独立出来单独建一棵树，在这棵小树上 DP，复杂度降为 $O(\sum k)$ 级别。

虚树的核心思想正是：**把每次询问的关键点分离出来，压缩掉无关的树结构，从而减少不必要的遍历。**

### 为什么 LCA 也要加入

为了保证压缩后的结构仍然是一棵「保留了原树祖先关系」的树，只加入 $k$ 个关键点是不够的——还需要加入这些关键点两两之间的 LCA，用来固定它们的相对位置。一个关键结论是：即使是最坏的二叉树情形，加入的节点总数也不超过 $2k-1$ 个，因此虚树的规模始终是 $O(k)$，复杂度不会退化。

### 基于单调栈的建树方法

利用「同一子树内的 DFS 序连续」这一性质，可以用单调栈建出虚树。先把所有关键点按 DFS 序（`dfn`）排序并去重，然后按如下步骤处理：

1. 将根节点压入栈。记栈顶为 $top$，栈顶之下的元素为 $ftop$。
2. 依次遍历排序后的关键点 $u$，求出 $u$ 与栈顶 $top$ 的 LCA，记为 $lca$。
3. 根据 $lca$ 与栈的关系分三种情况：
   - 若 $lca = top$，说明 $u$ 位于当前栈顶所在的子树内，直接把 $u$ 入栈。
   - 若 $lca \ne top$ 且 $dep[lca] < dep[ftop]$，说明 $top$ 这一支已经处理完毕，在虚树上连边 $ftop \to top$ 并弹出 $top$。
   - 若 $lca \ne top$ 且 $dep[lca] \ge dep[ftop]$，说明 $lca$ 是一个尚未进入虚树的中间节点，弹出 $top$，并依次将 $lca$、$u$ 入栈（若与栈顶重复则不再重复入栈）。
4. 处理完所有关键点后，依次弹出栈中剩余元素，每次连边 $ftop \to top$，虚树即建好。

### 如何在虚树上 DP

虚树建好后，就可以在其上做 DP 回答原问题。以「关键点两两距离之和」为例：先用一次 DP 预处理出每个点到根节点的距离 $h[x]$，则虚树上 $u \to v$ 的边权就是 $h[v] - h[u]$；对虚树上的每条边 $u \to v$，设 $v$ 子树内包含的关键点个数为 $cnt$，则该边对答案的贡献为 $w \times cnt \times (k - cnt)$，树形 DP 一次即可求出总和。

> 虚树没有固定的代码模板：具体的建边方式与 DP 需要按题目具体分析，唯一不变的是「按 DFS 序 + 单调栈」的建树过程本身。

## 核心公式 / 状态定义与转移方程

### 规模上界

设一次询问的关键点个数为 $k$，则虚树的节点总数（关键点 + 补充的 LCA）不超过：

$$
2k - 1
$$

因此在虚树上做一次 DP 的复杂度与 $k$ 成正比，而不是与 $n$ 成正比。

### 边权换算

若 $h[x]$ 表示节点 $x$ 到根节点的路径距离，则虚树上一条边 $u \to v$ 的边权为：

$$
w(u \to v) = h[v] - h[u]
$$

### 距离和的贡献式

对于「求关键点两两之间距离总和」这一类问题，设边 $u \to v$ 的边权为 $w$，$v$ 子树内包含的关键点个数为 $cnt$，则这条边被 $cnt \times (k - cnt)$ 对关键点之间的路径经过，因此对答案的贡献为：

$$
w \times cnt \times (k - cnt)
$$

对虚树做一次自底向上的树形 DP 累加即可。

## 逐行代码解析

> 虚树没有固定模板，本节以**思想步骤伪代码**说明建树与 DP 的流程，不要求与某个完整程序逐字对应。

### 模块一：关键点预处理

```cpp
sort(key + 1, key + 1 + k, cmpByDfn);   // 按 DFS 序排序
k = unique(key + 1, key + 1 + k) - key - 1;   // 去重
```

- 排序后相邻的关键点子树关系最接近，单调栈才能按顺序推进。
- 去重不可省：重复的关键点会导致同一节点被重复入栈，破坏建树过程。

### 模块二：单调栈建树（主循环）

```cpp
st[++tp] = 1;                       // 根节点（或 1 号点）入栈作哨兵
for (int i = 1; i <= k; i++) {
    int u = key[i];
    int l = lca(u, st[tp]);         // u 与栈顶的 LCA
    while (tp >= 2 && dep[l] < dep[st[tp - 1]]) {
        add_edge(st[tp - 1], st[tp]);  // 上一支已结束，连边 ftop -> top
        tp--;
    }
    if (st[tp] != l) {              // l 是中间节点，需插入栈中
        add_edge(l, st[tp]);
        st[tp] = l;
    }
    st[++tp] = u;                   // 关键点入栈
}
```

- `while` 循环对应「$dep[lca] < dep[ftop]$」的分支：此时 $top$ 所在的支已经检索完毕，持续弹栈连边，直到 $lca$ 落到 $top$ 与 $ftop$ 之间。
- `if (st[tp] != l)` 对应「$lca$ 是未检索到的中间节点」的分支：用 $l$ 替换栈顶位置（替换前连边 $l \to top$）。
- 若 $lca = top$，两个分支都不触发，直接 `st[++tp] = u` 入栈，对应「$u$ 在 $top$ 子树内」的情形。

### 模块三：收尾清空栈

```cpp
while (tp >= 2) {
    add_edge(st[tp - 1], st[tp]);
    tp--;
}
```

- 处理完所有关键点后，栈里还留着一条从根到最后一个关键点的「链」，需依次弹出连边。
- 清空后栈中剩下的唯一节点就是虚树的根。

### 模块四：虚树上的 DP

```cpp
// 预处理 h[x]：x 到根的距离；cnt[v]：v 子树内关键点个数
void dfs(int u) {
    cnt[u] = is_key[u];             // 关键点自身计数为 1
    for (auto [v, w] : V[u]) {      // V[u] 为虚树邻接表，边权 w = h[v] - h[u]
        dfs(v);
        ans += w * cnt[v] * (k - cnt[v]);
        cnt[u] += cnt[v];
    }
}
```

- 虚树边权 $w = h[v] - h[u]$ 由预处理出的 $h$ 直接相减得到，无需重新遍历原树。
- 贡献式 $w \times cnt[v] \times (k - cnt[v])$ 表示：$v$ 子树内每个关键点都要与子树外 $k - cnt[v]$ 个关键点配对，都要经过这条边。
- 自底向上汇总 `cnt`，一次 DFS 即可得到全部关键点两两距离之和。

## 复杂度分析

设单次询问的关键点个数为 $k$，所有询问的关键点总数为 $K = \sum k_i$。

| 步骤 | 时间复杂度 |
|---|---|
| 关键点按 DFS 序排序 | $O(k \log k)$ |
| 求 LCA（倍增法） | $O(k \log n)$ |
| 单调栈建树 | $O(k)$（每个点至多入栈出栈一次） |
| 虚树上树形 DP | $O(k)$ |
| **单次询问总计** | $O(k \log n)$（取决于 LCA 实现） |
| **所有询问总计** | $O(K \log n)$ 级别 |

空间复杂度：虚树节点数为 $O(k)$，外加原树的 LCA 预处理数组 $O(n \log n)$（若用倍增 LCA）或 $O(n)$（若用其他在线 LCA）；整体空间由 LCA 预处理决定。

由于虚树没有统一实现，frontmatter 中的复杂度记作「视具体实现」；实际使用时，瓶颈通常在 LCA 查询，建树与 DP 本身均与 $k$ 成正比。

## 适用场景

- **树上多组询问**：题目有 $q$ 次询问，每次只关心若干个关键点，且 $\sum k$ 有保证，例如关键点两两距离之和、关键点集合的最小连通子树等。
- **树上选点 DP**：每次询问在关键点集合上做树形 DP，原树规模 $n$ 很大（如 $10^5$），但单次关键点 $k$ 很小。
- **需要频繁构建小规模树**：关键点集合随询问变化，但原树固定不变——此时 LCA 只需预处理一次，建树过程反复执行。
- **配合 LCA / 树形 DP / 单调栈**：虚树依赖这三者，适合已掌握树形 DP 与 LCA 的读者作为进阶工具。

**不适合**的情形：单次询问就涉及整棵树（$k$ 接近 $n$）时，虚树不会带来收益；树结构频繁变化（动态加边删边）时，LCA 预处理难以维护，也不适合直接套用。

## 常见陷阱与注意事项

1. **重复关键点必须去重**：若同一关键点在集合中出现多次，排序后会导致重复入栈，建树结果错误；排序后务必先 `unique` 再去建树。
2. **关键点的 LCA 也要加入虚树**：只保留关键点无法构成一棵保持祖先关系的树，必须补充 LCA 作为「骨架」；好在节点总数有 $2k-1$ 的上界，不会退化。
3. **排序依据必须是原树的 DFS 序**：排序依据是原树的 `dfn`，不是节点编号；用错排序依据会导致建出的树祖先关系错乱。
4. **区分 $top$ 与 $ftop$**：$top$ 是栈顶，$ftop$ 是栈顶之下的元素；判断「这一支是否已处理完」要比较 $dep[lca]$ 与 $dep[ftop]$，不要与 $dep[top]$ 比较。
5. **弹栈连边的方向**：连边方向为 $ftop \to top$（即父指向子），方向反了会破坏虚树的根向结构，DP 时无法自底向上。
6. **虚树边权要靠原树信息换算**：虚树边是「压缩」出来的，边权通常用根到点的距离之差 $h[v] - h[u]$ 表示，不能直接用原树邻接边权拼接。
7. **DP 要从虚树的根开始**：虚树建完后根是栈中最后剩下的节点，DP 需以它作为起点自底向上汇总；直接遍历原树的根会算错。
8. **不要忽略 LCA 的预处理开销**：总复杂度里 LCA 查询往往占主导，别只盯着 $O(k)$ 的建树而忽略 $O(k \log n)$ 的 LCA 开销。

## 对比与扩展

### 虚树与树链剖分 / 树上差分的区别

| 方法 | 核心思想 | 适用情形 |
|---|---|---|
| 虚树 | 把关键点与 LCA 压缩成小树 | 每次只关心少数关键点，多次询问 |
| 树链剖分 | 把树拆成重链映射到序列 | 树上路径/子树的批量修改与查询 |
| 树上差分 | 用端点标记 + 子树和还原 | 对若干条路径做同一种批量加减 |

三者常互补：虚树压缩「点的规模」，树链剖分解决「路径/子树维护」，树上差分优化「批量路径修改」。

### 虚树与点分治的对比

- 虚树针对「关键点稀疏、多次询问」，把规模从 $n$ 压到 $O(k)$，且保留原树的祖先结构，适合做选点 DP。
- 点分治（重心分治）针对「整棵树上的路径统计」，通过重心递归分治把深度压到 $O(\log n)$，不关心关键点是否稀疏。

### 常见的虚树应用变体

- **关键点两两距离之和**：边权 $h[v]-h[u]$，贡献 $w \times cnt \times (k-cnt)$，一次树形 DP。
- **最小连通块 / 关键点 Steiner 树**：虚树建好后求边权和，或统计连通块内的节点数。
- **多组询问的树上背包 / 选点 DP**：在虚树上做状态 DP，状态规模只与 $k$ 有关。
- **结合换根 DP / 树上前缀和**：虚树把关键点之间的路径信息压缩到小树上，再套用常规树上技巧。

### 延伸阅读

虚树是「树上多组询问」类问题的通用压缩手段，通常与 LCA、树形 DP、单调栈搭配出现。进阶方向包括**点分治、边分治、树链剖分、树上启发式合并（DSU on Tree）**等树上优化技巧，它们从不同角度压缩或拆解树结构。
