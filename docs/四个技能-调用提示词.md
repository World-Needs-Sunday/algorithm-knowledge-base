# 四个技能的调用提示词（照抄即可）

> **原理**：Trae / Claude Code 这类工具是**按 `SKILL.md` 的 `description` 字段自动挑技能**的。
> 所以调用公式就三块：**触发词（命中 description）＋ 目标（文件夹/文件名）＋ 技能锚点（点名 SKILL.md，保险）**。
> ```
> <触发词 + 目标>。按 .trae/skills/<技能名>/SKILL.md 执行。
> ```

## 0. 触发词速查（说什么 → 命中哪个技能）

| 我想干的事 | 这样说（触发词） | 命中的技能 |
|---|---|---|
| 加知识点 | "这是**新知识点**""帮我**入库**""把这份总结整理成**知识点**"+ 文件夹 | `add-knowledge` |
| 加题目 | "这题**加进题目专辑**""帮我**录一道题**"+ 文件夹 | `add-problem` |
| 改内容 | "**XX 那条写错了**""**复杂度不对**""**样例输出应该是**…""**代码改了正文也改一下**" | `edit-content` |
| 看代码 | "**帮我看看为什么 WA**""**帮我审查一下这段代码**" | `edit-content`（代码审查部分） |
| 上传 | "**更新网站**""**上传**""**提交到 GitHub**""**发布**" | `release-github` |

> 想改触发词：直接改对应 `SKILL.md` 顶部 `description:` 里的那几句引号内容即可。

## 0.1 通用三件套（每次都给全，AI 就不会瞎找）

1. **文件夹/文件**：把路径写清，或在 Trae 里 `@` 该文件夹 / 拖进来。例：`C:\Users\penti\Desktop\新建\线段树合并`
2. **技能锚点**：末尾加一句 `按 .trae/skills/<技能名>/SKILL.md 执行`
3. **约束提醒**（可选，一两句）：`代码只搬运不改实现`、`样例必须实测`、`元数据先列给我确认`

## 1. 添加知识点（add-knowledge）

### 标准版（最常用）

```
【添加知识点】文件夹：C:\Users\penti\Desktop\新建\<算法名>
按 .trae/skills/add-knowledge/SKILL.md 执行。

我的预填（没写的你给建议，别猜着填）：
category = <大类>    subcategory = <子分类>
代码是我自己写的 → 只搬运到约定路径，不改实现。
正文章节按规范来，「思路」里的小节映射进对应章节。
元数据先列一遍给我确认，我点头你再动文件。
```

### 变体

| 情况 | 追加这句 |
|---|---|
| 只有思路、代码还没写 | "文件夹里只有 `思路.md`，代码我还没写：先建骨架并留好代码占位，提醒我补 `.cpp`。" |
| 是初赛笔记类（无代码） | "这是初赛笔记类知识点，不需要 `codePath`，章节按考点自由组织。" |
| 同算法已有条目、这是另一个版本 | "这是 `<已有 id>` 的另一个写法，id 加后缀 `-self`/`-2d` 之类区分，并在「对比与扩展」里说清差别。" |
| 我自己知道 id | "id 用 `ds-segtree-merge`，别改。" |

## 2. 添加题目（add-problem）

### 标准版

```
【添加题目】文件夹：C:\Users\penti\Desktop\新建\<题名>
里面有题目 / 代码 / 思路三个文件（文件名不一定叫这个，按内容判断角色）。
按 .trae/skills/add-problem/SKILL.md 执行。

我的预填：
oj = <洛谷/Codeforces/…>   problemId = <P1050 / CF2252D>   difficulty = <中等>
category = <考点大类>

要求：样例必须编译实测过再写；数据范围按题面转述；查不到出处就写「来源未考证」。
代码只搬运不改实现。元数据先列给我确认。
```

### 变体

| 情况 | 追加这句 |
|---|---|
| 没有思路文件 | "没有 `思路.md`，思路部分你从题面和代码反推，写完我核对。" |
| 题面在 OJ 链接上 | "题面在 `<URL>`，你先去取；取不到就停，我去复制。" |
| 只有截图/文字片段 | "题面我贴在下一条消息里，按我给的原文转述，不要补数据范围。" |
| 多测题 | "这是多测题，「常见陷阱」里要写清多测清空。" |

## 3. 修改知识点 / 题目（edit-content）

### 变体 A · 我知道哪里错（最常见）

```
【修改】content/graph-johnson.md 里的复杂度写错了，应该是 O(nm log n)。
按 .trae/skills/edit-content/SKILL.md 执行：只改这一处，diff 保持最小，
改完跑 node tools/lint.js（error 0）→ node build.js，再汇报。
```

### 变体 B · 我给正确说法，你去核对再改

```
【修改】problems/prob-p7915-palindrome.md 第二组样例输出应为 -1（我给的理由：…）。
请先核对，确认后再改；如果你认为我对了，直接改并告诉我依据。
```

### 变体 C · 代码改了，正文要同步

```
【修改】我把 <题目专辑\分类\题名\代码.cpp> 改了，正文里的代码块请按新的 .cpp 同步
（lint W028 必须为 0），逐行解析里提到旧写法的地方也一起更新。
```

### 变体 D · 帮我看看为什么 WA（代码审查，不代写）

```
【代码审查】这题 WA 了。题目在 <problems/xxx.md>，我的代码在 <路径>。
按 .trae/skills/edit-content 的代码审查部分：只指出 bug 在哪一行、为什么错、会给什么现象，
再给我 2–3 组边界数据让我自己验。不要改我的实现。
```

### 变体 E · 我不确定是正文错还是代码错

```
【修改】我跑出来的样例输出和正文写的不一样。帮我定位：是正文记错了，还是代码有问题？
定位清楚再决定改哪边；如果是代码的问题，只告诉我方向，我自己改。
```

## 4. 上传仓库（release-github）

### 标准版

```
【上传】把这次改动构建并推送到 GitHub。
按 .trae/skills/release-github/SKILL.md 执行。
commit 用规范前缀（feat/fix/docs/chore），push 前把 git status 给我看一眼。
推完告诉我线上大约多久生效。
```

### 变体

| 情况 | 这句 |
|---|---|
| 只构建，不上传 | "【构建】只跑 lint + build，先别 push。" |
| 连同工具一起入库（首次） | "【上传】顺便把 `AGENTS.md`、`README.md`、`PROJECT_FRAMEWORK.md`、`tools/`、`templates/`、`docs/`、`.trae/` 和 **`favicon.svg`** 一起入库（favicon 目前未跟踪，线上站点没图标）。" |
| 上传后核对线上 | "【核对】约 10 分钟后帮我对一下线上和本地的四个产物是否一致。" |
| 想撤销上一次发布 | "【回滚】把上一次提交回滚掉（用 revert，别 force push），并推上去。" |

## 5. 兜底：AI 没按技能走时，补这一句

```
停一下。先读 AGENTS.md → PROJECT_FRAMEWORK.md，再按 .trae/skills/<技能名>/SKILL.md
从 Step 1 逐步执行；动手前用 5 行复述计划（任务类型 / 改哪些文件 / 跑哪些命令 /
绝不做什么 / 要问我什么）。
```

## 6. 元数据速答卡（AI 问你要字段时，一次给全省一轮）

```
【元数据预填】
id:
title:
category:
subcategory:
subSubcategory:            （没有就空着）
tags:                      （3–6 个）
timeComplexity:
spaceComplexity:
level:                     A / B / C（不确定就 A）

# 题目额外
oj:
problemId:
difficulty:
```

> **不知道的就留空**，让 AI 按规范给建议；**唯一不能做的是编造**（题号、样例、年份、出处、数据范围）。
> `id` 不确定也没关系——它有前缀规则（`dp-`/`ds-`/`graph-`/`math-`/`str-`/`prob-` …），让 AI 提。

---

## 7. 一张流程图（记住这个顺序就不会乱）

```
① 丢文件夹/指文件  →  ② 说明要干什么（触发词）  →  ③ 点名 SKILL.md
        ↓
   ④ AI 列元数据/计划给你确认（这一步别跳过）
        ↓
   ⑤ 它动手改文件 → 跑 lint(error 0) → build
        ↓
   ⑥ 四段汇报 → 你说「上传」才 push
```
