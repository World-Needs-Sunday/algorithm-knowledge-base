# 让 AI 了解本站 · 入项提示词

> **用途**：开一个新 AI 会话（Trae / Codex / Claude Code / 网页版对话）时，把下面某一段贴进去，让 AI 在动手前就对整个网站、规范与四条纪律有完整认识。
> **配套**：AI 能读文件时，真正的细节在 `AGENTS.md` / `PROJECT_FRAMEWORK.md` / `README.md` / `.trae/skills/`；不能读文件时用「C. 自包含版」。

## 怎么选

| 场景 | 用哪版 | 理由 |
|---|---|---|
| Trae / Codex / Claude Code（能读仓库文件） | **B. 标准版**（推荐） | 让 AI 自己去读权威文件，不靠转述 |
| 同一会话里反复干活 | **A. 一行版** | 规则文件已在上下文里，只需定任务 |
| 网页版对话 AI（读不到你的文件） | **C. 自包含版** | 把关键信息直接写进提示词 |
| 不确定 AI 有没有真读 | **D. 理解自检** | 让它复述，答错就是没读 |
| AI 跑偏了（想代写代码、乱改、编数据） | **E. 纠正口径** | 一句话拉回来 |

## A. 一行版（日常最省事）

```
读 AGENTS.md 与 PROJECT_FRAMEWORK.md，然后按 .trae/skills/ 里对应的技能执行；
动手前先用 5 行复述你的计划（哪类任务 / 改哪些文件 / 跑哪些命令 / 绝不做什么 / 要问我什么）。
```

## B. 标准版（项目内工作，推荐）

```
这是一个「算法知识点查询网站」项目：纯静态，单文件 index.html + 三个构建产物，GitHub Pages 托管。

【第一步：先读，别跳】
1. AGENTS.md             —— 三条铁律 + 四个能力路由 + 汇报格式
2. PROJECT_FRAMEWORK.md  —— 完整框架：目录与数据流、frontmatter 字段表、章节规范、
                            命名约定、KaTeX 陷阱、四个操作流程、lint 规则含义
3. README.md             —— 项目说明：规模、怎么跑、目录速览
读完再动手；不要凭猜测写字段名或路径。

【第二步：确认任务类型，打开对应技能，严格按它的步骤做】
- 添加知识点   → .trae/skills/add-knowledge/SKILL.md
- 添加题目     → .trae/skills/add-problem/SKILL.md
- 修改知识点/题目 → .trae/skills/edit-content/SKILL.md
- 构建并上传 GitHub → .trae/skills/release-github/SKILL.md

【第三步：动手前先复述（我确认后你再改文件）】
5 行以内说清：
(1) 这次属于哪类任务；(2) 准备改/新建哪些文件；(3) 会跑哪些命令；
(4) 哪些事你绝对不会做；(5) 有什么需要我先确认。

【硬性纪律（任何任务都适用）】
- 三条铁律：① 不代写任何 .cpp 实现（只讲思路、指 bug 方向、列边界清单、review）
             ② 改完必须 node tools/lint.js（error 0）→ node build.js
             ③ data.js / code_data.js / problems_data.js 是产物，永不手改
- 不编造题号、样例、年份、出处、数据范围；查不到就写「来源未考证」或来问我。
- 改动最小化：只动与任务相关的文件，不顺手重构、不批量改格式。
- 汇报固定四段：【改动】【验证】【需要你本人做】【待确认】。

【我的输入习惯】
我一般丢一个文件夹：题目.md（只有题目才有）+ 代码.cpp + 思路.md，文件名不固定，
按内容判断哪个是题面/代码/思路。代码只搬运不改实现；题面忠实转述，不补数据范围与样例。
```

## C. 自包含版（给读不到你文件的对话 AI）

```
我要维护一个「算法知识点查询网站」，请先了解它的形态，再按我说的做。

【是什么】
纯静态站点：单文件 index.html（自写 CSS+JS）渲染，没有框架、没有 npm 依赖、没有后端。
现在有 109 个知识点、20 道题目，分 8 个大类（基础算法/动态规划/数据结构/图论/数学/字符串/输入输出/初赛笔记）。

【内容怎么变成网页】
- content/*.md      知识点（Markdown + frontmatter）
- problems/*.md     题目（Markdown + frontmatter）
- knowledge_graph.json  分类描述 + 前置/相关关系
- 各分类目录/*.cpp  我自己写的代码（由 frontmatter 的 codePath 指向）
- 一个构建脚本把它们合成三个数据文件（data.js / problems_data.js / code_data.js），
  页面只读这三个产物；产物永不手改，改了内容必须重新构建。

【一篇知识点长什么样】
frontmatter：id（=文件名）/ title（正式名）/ category / subcategory / tags（3–6 个）/
timeComplexity / spaceComplexity（不许写"未知"）/ codePath / level(A/B/C)。
正文七章，标题逐字用：
  算法原理 → 核心公式 / 状态定义与转移方程 → 逐行代码解析 → 复杂度分析 →
  适用场景 → 常见陷阱与注意事项 → 对比与扩展
（数据结构类在公式章后加「数据结构图示」「核心操作详解」。）

【一道题目长什么样】
frontmatter：id / title / oj / problemId / difficulty / category / tags / 复杂度 / codePath。
正文：题目描述（含 输入格式 / 输出格式 / 数据范围）→ 样例 → 解题思路 →
      逐行代码解析 → 复杂度分析 → 常见陷阱与注意事项 → 对比与扩展。

【三条铁律（最重要）】
1. 不要替我写 .cpp 实现——我自己写。你可以讲思路、指 bug、列边界、给对拍框架、审查代码。
2. 内容与代码必须一致：正文里的整段代码要与 .cpp 逐字一致；改了任一边就同步另一边。
3. 不要编：题号、样例、年份、出处、数据范围查不到就直说，标「待核实」。

【写作禁忌】
不出现「等等」「不对」「我算错了」这类试错痕迹；不出现"自己写的"这类标题自述；
复杂度不许写"未知"；表格里公式内的 | 要写成 \lvert…\rvert；$ 必须成对；
\text{} 内不要用下划线（非要用就写 \_）。
```

## D. 理解自检（让 AI 复述，防止它"假装读过"）

贴完上面的提示词后，紧接着发这一句：

```
先别动手，回答我 5 个问题：
1. 这个站的三个构建产物是什么？哪个目录是它们唯一的真相来源？
2. 我改完内容后要跑哪两条命令？order 是什么？
3. 哪三件事你绝对不能做？
4. 我要新增一道题，你会依次做哪几步、动哪些文件？
5. 什么情况下你必须停下来问我，而不是自己决定？
```

答错任何一条 → 说明它没读或没读懂，先纠正再让它干活。

### D2. 判分要点（标准答案，用来给 AI 的回答打分）

| 题 | 必须答到的关键点 | 常见扣分 |
|---|---|---|
| 1 | 三个产物**名字齐全**（`data.js` / `code_data.js` / `problems_data.js`）+「由 `build.js` 生成、**永不手改**」；真相来源四类：`content/*.md`、`problems/*.md`、`knowledge_graph.json`、各分类目录的 `.cpp` | 把 `index.html` 当产物；漏掉 `.cpp` 或图谱；只答"Markdown" |
| 2 | **先 lint 再 build**；强调 lint 的 error 必须为 0；提到 Ctrl+F5 强刷 | 顺序颠倒；只说"跑一下构建"；不提 error 必须 0 |
| 3 | 三条铁律：① 不代写 `.cpp` 实现 ② 改完必过门禁 ③ 产物永不手改；再加「不编造题号/样例/年份/出处/数据范围」 | 漏掉「不编造」；把"过门禁"说成可选 |
| 4 | ① 按**内容**判断文件夹里三个角色（不看文件名）② 先确认元信息再动手 ③ **原样搬运** `.cpp`（不改实现）④ 按规范写正文（题目是 **7 个二级章节**，`## 题目描述` 下再挂 `### 输入格式 / 输出格式 / 数据范围` 三个小节）⑤ 跑门禁 ⑥ 四段汇报 | 说成"8 章"（那是**数据结构类知识点**的说法）；漏掉"样例必须编译实测过"；漏"不改实现"；不用脚手架直接手搓（易漏字段） |
| 5 | 停下问的情形：题号/出处/样例/数据范围拿不准；`category`/`subcategory`/`id`/难度归类不明；要新建子分类（得同步图谱）；知识点还是题目拿不准；**要动 `.cpp` 实现**；是否 push GitHub | 什么都自己决定（编数据）；或反过来什么都问（规范里写清的东西应自己查） |

**两条容易答错的边界**（能答出来说明真读懂了）：

- **`.cpp` 的"能碰"与"不能碰"**：默认不改实现，只能指方向 + review；**删除调试/计时代码**（`printf("耗时…")` 这类）在用户同意下可以做；用户明确"破例"时才可代写，且回复首行要标注 `⚠️ 已按你的破例要求代写代码`。
- **用户要求与规范冲突时**：不是照做，而是先说明规范（例如标题里不能带"自己写的"、正文不能留完整可提交代码），请用户确认或给替代方案。

## E. 纠正口径（AI 跑偏时一句话拉回）

| 它跑偏的表现 | 你发这句 |
|---|---|
| 想直接给你写 `.cpp` 实现 | "只讲思路与 bug 方向，代码我自己写。" |
| 编了题号 / 样例 / 年份 | "查不到就写『来源未考证』，不许编；样例必须真跑过。" |
| 顺手重构、大改格式 | "只改我指出的地方，diff 保持最小，其他文件别动。" |
| 没跑门禁就说完成了 | "先跑 `node tools/lint.js`（error 必须 0）和 `node build.js`，把输出贴给我。" |
| 手改了 `data.js` 之类产物 | "产物永不手改，改 `content/` 下的源文件再重新构建。" |
| 改了代码没同步正文 | "正文代码块要与 `.cpp` 逐字一致（lint W028），别只改一边。" |
| 汇报只有一句"已完成" | "按【改动】【验证】【需要你本人做】【待确认】四段汇报。" |
| 字段名/路径靠猜 | "先读 `PROJECT_FRAMEWORK.md` §3 的字段表再写。" |

## F. 一页速记（你自己记的）

```
新会话第一句  →  A 一行版（Trae/Codex）或 C 自包含版（网页版）
动手前        →  D 理解自检（5 问）
干活中跑偏    →  E 纠正口径
交付前        →  node tools/lint.js（error 0）→ node build.js
四个能力      →  .trae/skills/add-knowledge | add-problem | edit-content | release-github
权威文件      →  AGENTS.md（铁律） · PROJECT_FRAMEWORK.md（框架） · README.md（说明）
```
