# 内容质量标准

> 解决两个具体问题：**「详细程度参差不齐」** 和 **「知识点多了以后不好用」**。
> 办法：给每条内容定一个**明确的等级**（A/B/C），并写清每一级的底线；等级写进 frontmatter，前端就能如实告诉读者"这条是速查模板，那条是深挖详解"。

## 一、三级定义

| 等级 | 名称 | 定位 | 篇幅参考 | 适合什么内容 |
|---|---|---|---|---|
| **A** | 模板级 | 拿来就能用，够查够抄 | 1500–3000 字 | 冷门知识点、模板型算法、日常查阅 |
| **B** | 详解级 | 能学会，能理解为什么 | 3000–8000 字 | 主力知识点（大多数条目应在这里） |
| **C** | 深挖级 | 能讲给别人听，能应付变形 | 8000 字以上 | 高频重点、易错难点、有优美证明的内容 |

**没有等级 = 按 A 处理。** 不要为了"看起来专业"给所有内容标 C——那等于没有分级。

## 二、所有等级都必须满足的底线（硬性）

以下任意一条不满足，就是**不合格内容**，不是"等级低"：

1. **代码同步**：正文「逐行代码解析」里**如果放了整段代码**，必须与 `codePath` 指向的 `.cpp` **逐字一致**；只放片段 + 逐行说明同样合格（完整代码由页面自动从 `CODE_DATA` 渲染）。`lint.js` 的 W028 只在"放了接近整段、但内容与 `.cpp` 不同"时报警，因此「W028 必须为 0」与「整段可选」并不冲突。

> **补充说明（关于代码写两遍）**：前端 `selectKP()` 已经把 `.cpp` 完整渲染在文章下方的 `<div class="code-section">`（带文件名与复制按钮）。所以正文再贴一份完整代码属于**重复**，也容易与 `.cpp` 走散。两种合格写法：
> - **片段式（推荐）**：正文只放关键片段 + 逐行说明，完整代码交给页面下方自动渲染区；
> - **整段式**：正文放完整代码，但必须与 `.cpp` 逐字一致（改 `.cpp` 后必须同步正文，跑 `lint.js` 看 W028）。
>
> 若选片段式而希望页面不再重复展示，可在前端加一句判断：正文已含与 `.cpp` 相同的代码块时，跳过 `.code-section`。
2. **复杂度一致**：frontmatter 的 `timeComplexity` / `spaceComplexity` 与正文、与实现三者一致，且**不能是"未知"**。
3. **样例可复现**：给样例的，样例输入输出必须**真跑过**，与代码实际输出一致。
4. **结论不自相矛盾**：同一条目内、同一算法在不同条目间，结论不能打架。
5. **无草稿残留**：不出现"等等""不对""纠正一下""？不，等一下"这类推导过程的自我修正；不出现"自己写的""以前没有学的时候写的"这类标题自述。
6. **无编码事故**：不出现 `代紅`（"洛谷"的错误编码）、`锟斤拷`、U+FFFD、`\r\r\n`。
7. **来源可查**：涉及题目，必须给 `oj` + `problemId`；引用他人结论/定理时能说清出处，**不编造**。

## 三、各等级要求

### A 模板级（底线清单）

| 章节 | 要求 |
|---|---|
| frontmatter | 字段齐全，`level: A` |
| 算法原理 | ≥150 字：解决什么问题、核心思想 |
| 核心公式 / 状态定义 | 必须有；状态要写清每个维度含义 |
| 逐行代码解析 | 完整代码 + 至少 5 条要点注释 |
| 复杂度分析 | 时间/空间，并说明怎么数的 |
| 适用场景 | 什么题用它（≥2 类特征） |
| 常见陷阱 | ≥5 条，覆盖边界与数据类型 |

### B 详解级（= A + 以下）

- **手算示例**：至少 1 个"跟着走一遍"的小例子（3–6 个元素规模），展示状态如何转移。
- **逐行解析**：不只是"这行干什么"，要讲**为什么是这个边界/这个顺序**。
- **对比与扩展**：与最易混淆的算法写清区别（≥1 组对比）。
- **陷阱 ≥7 条**，其中至少 2 条来自"我自己踩过的坑"。
- 正确性说明：能用一段话讲清"为什么这样对"（不要求严格证明）。

### C 深挖级（= B + 以下）

- **正确性证明**：归纳/交换论证/反证，写清前提与每一步。
- **复杂度证明**：不是"看起来是 O(n log n)"，而是能数出来（摊还分析、势能、计数论证）。
- **多实现对比**：≥2 种写法的取舍（常数、码量、适用场景）。
- **变形与题目**：列出 2–3 个变体，说明改动点。
- **陷阱 ≥10 条**，含卡常/常数/精度类。

## 四、frontmatter 建议字段

```yaml
level: B              # A | B | C
verified: 2026-10-11  # 最近一次人工复核日期（可选，但很有用）
```

> 后端/前端可以据此显示「模板级 / 详解级 / 深挖级」徽章；`verified` 超过一年可以提示"待复核"。

## 五、抽查清单（复核旧内容时按这个逐项打勾）

- [ ] 公式/结论能否举出反例？（重点看"我总是这样用"的地方）
- [ ] 复杂度声明与代码循环层数是否对得上？
- [ ] 样例：把 `.cpp` 编译跑一遍，输出与正文样例是否一致？
- [ ] 代码与正文代码块是否逐字一致？
- [ ] 前置知识是否真的前置？（"不会它就学不会这条"）
- [ ] 标题是否正式？（无"自己写的""旧版""草稿"）
- [ ] 有没有"未经验证的强断言"（"必然""一定""永远"）？能否证明？
- [ ] 与同一算法的其他条目是否说法一致？
- [ ] 引用（题号、年份、定理名）是否准确？
- [ ] 表格里的公式有没有未转义的 `|`？`$` 是否成对？

## 六、本库真实反例（写新内容时引以为戒）

这些是评测中确认过的错误，都是**"看起来很像对的"**类型：

| 类型 | 例子 | 教训 |
|---|---|---|
| 复杂度想当然 | 并查集条目写「仅路径压缩均摊 O(α(n))」 | α(n) 需要配合按秩合并；单用路径压缩是 O(log n) |
| 年份/出处记错 | 食物链写成「NOI 2024」 | 实为 NOI 2001；出处必须核对 |
| 套用公式不验前提 | 矩阵逆写 `A^{-1} = A^{mod-2}` | 费马小定理只对标量；举个小反例就能发现 |
| 证明想当然 | 最近点对鸽巢「每个小矩形至多 1 点」 | 跨中线的点可以一左一右；标准结论是检查 7 个 |
| 样例凭记忆写 | P7915 第二组样例输出 `-1`，实际有解 | 样例必须复制 + 真跑 |
| 讲解与代码两版 | 36 处 W028 | 代码改了就必须同步正文 |
| 残留调试代码 | P1050 输出后打印耗时 | 提交前搜一遍 `printf`/`cout` |
| 边界未考虑 | 可持久化线段树 `n=1` 无限递归 | 每个算法都问一句"n=1 会怎样" |

## 七、升级路径（A → B → C 该补什么）

| 从 | 到 | 先补 |
|---|---|---|
| A | B | 手算示例 → 逐行"为什么" → 对比表 → 陷阱补到 7 条 |
| B | C | 正确性证明 → 复杂度证明 → 多实现对比 → 变体清单 |
| 任意 | 任意 | 先把「六、真实反例」里同类型的坑排查一遍 |

## 八、等级如何影响排期

- 新内容默认先写 **A**，把"能被检索到"做出来；等某条被反复查阅，再升 B。
- 一批内容里的 **B 级**不超过 30%，**C 级**不超过 10%——否则维护成本会吃掉你所有时间。
- 用 `level` 字段统计各等级数量，季度看一次分布是否合理。
