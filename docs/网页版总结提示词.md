# 网页版提问 → 总结笔记 → Trae 入库

> **这份手册解决什么**：网页版（DeepSeek 等）聊完一堆问答之后，用一句提示词得到**一篇自己就能读、且思路清楚**的笔记；之后若要入库，再交给 Trae 补网页需要的东西。
> **两条分工**：
> - **给你读的笔记**（第 1 节）：纯正文，没有 frontmatter / 文件路径 / 字段名，重点是**思路**。
> - **给网页用的包装**（第 3 节）：frontmatter、规范章节名、代码同步、门禁——**由 Trae 做**，不用你操心。

---

## 0. 流水线与责任边界

```
① 网页版提问            ② 一句话总结                ③ 想入库时再交给 Trae
   （反复追问）      →   得到「可直接阅读的笔记」 →   补 frontmatter / 规范章节名
   【第 2 节开场词】     【第 1 节总结词】              贴 .cpp、跑 lint、build
```

| 事项 | 谁做 |
|---|---|
| 思路、公式、复杂度、易错点、迁移套路 | 网页版（① ②） |
| `.cpp` 实现（含暴力、造数据） | **你本人**（铁律：AI 不代写） |
| `oj` / 题号 / 样例 | **你核实**；拿不到就写「待核实」，绝不编 |
| frontmatter、章节名对齐、代码逐字同步、跑门禁 | Trae（③） |

## 1. 【核心】可直接阅读的总结提示词

### 1.1 完整版（推荐，复制即用）

````
把我们上面这段关于「<题目/知识点>」的讨论，整理成一篇我可以直接阅读的笔记。
不要输出 frontmatter、文件路径、字段名，或任何"给程序看"的东西——只要人能一口气读完的正文。

【结构：按这个顺序，标题用词可微调，顺序别变】
# 标题（题目写题名，知识点写算法名）
## 一句话结论      这道题/这个知识点核心是什么，1–3 句
## 题目在问什么     只有题目时写：用我的话复述题意 + 数据范围 + 真正的难点在哪
## 思路是怎么想出来的   ★最重要，占全文 1/3 以上
   - 从哪个信号/特征开始下手（看到什么 → 想到什么）
   - 关键的那一步转化或观察是什么，为什么它能突破
   - 容易先想到但走不通的方向，以及走不通的**具体原因**
   - 想法如何一步步收敛到最终做法
## 具体做法        分步骤（编号）；该给公式给公式，该给伪代码给伪代码
## 为什么这样是对的  正确性的直觉或要点；边界/特殊情况为什么这么处理
## 复杂度          时间与空间各一句，并说明怎么算出来的
## 容易错的地方     3–6 条，写成"如果…就会…"的可执行提醒
## 可以迁移到哪     同类题、变式、下次遇到什么特征可以套这套思路

【写法要求】
1. 思路要写透，但用**复盘口吻**：允许写"一开始容易往 X 想，但 X 不行，因为……"；
   禁止保留现场试错痕迹（"等等""不对""我算错了""重新算一遍"）。
   读者要看到的是**为什么这条路对**，不是我当时怎么绕的。
2. 公式用 LaTeX：行内 $...$、块级 $$...$$；\text{} 里不要用下划线（非要用就写 \_）。
3. 表格里公式中不要出现裸的 |（写成 \lvert…\rvert）。
4. 代码只放关键片段或伪代码，不贴完整可提交程序（完整代码我自己写）。
5. 全部内容基于我们上面的讨论；某处没把握就在那句后面写「（待核实）」，
   不要猜，也不要用"必然/一定/永远"这类强断言掩盖不确定。
6. 篇幅：普通题 800–1500 字；讨论很深可以到 2500 字，但不要注水、不要重复。
7. 不要客套话（"我按你的要求整理了…"），直接从标题开始给正文。
````

### 1.2 精简版（每天用，约 15 行）

````
把我们上面关于「<题目/知识点>」的讨论整理成一篇能直接读的笔记，不要 frontmatter、
不要字段名、不要文件路径，只给正文。按这个顺序写，重点写透第 3 节：

1. # 标题
2. ## 一句话结论
3. ## 题目在问什么（题意 + 数据范围 + 难在哪）
4. ## 思路是怎么想出来的（占 1/3 以上：从什么信号下手、关键那步转化是什么、
   容易先想到但走不通的方向及原因、想法怎么收敛到正解）
5. ## 具体做法（分步骤，公式/伪代码按需）
6. ## 为什么这样是对的
7. ## 复杂度（怎么算出来的）
8. ## 容易错的地方（3–6 条，"如果…就会…"）
9. ## 可以迁移到哪

要求：思路用复盘口吻写（可写"容易先想到 X，但 X 不行，因为…"），禁止"等等/不对/
我算错了"这类现场试错痕迹；公式 $...$ / $$...$$；不确定就标「（待核实）」，不要猜；
篇幅 800–1500 字。
````

### 1.3 只想快速留个"思路"时的一句话版

````
用 300 字以内把这道题的**思路链条**写清楚：看到题的第一反应 → 关键观察/转化 →
为什么它能work → 容易走的弯路 → 最后落到什么做法。不要代码，不要客套。
````

## 2. 【可选】开场提示词（会话第一句发一次，让后面的回答天然带思路）

```
接下来我会就某个题目或算法反复追问。请这样回答我：

1. 先讲"怎么想到的"再给结论：看到题的第一个反应是什么、关键观察是什么、
   哪些方向看起来可行但其实走不通（以及为什么）。
2. 只保留最终正确的结论；说错了就在下一次回答里直接给更正后的完整版本，
   不要写"等等""不对""我算错了"这类现场试错痕迹。
3. 复杂度要说明怎么数出来的；公式用 $...$ / $$...$$。
4. 不确定的地方明确标「（待核实）」，不要猜，也不要用"必然/一定"盖过去。
5. 代码只给伪代码或关键片段，完整实现我自己写。
6. 涉及题目请给题号；拿不到就说"来源未考证"。
```

## 3. 想入库时：把这篇笔记交给 Trae（你不用自己加网页的东西）

```
这是我写好的笔记正文（下面贴）。请把它落成 content/<id>.md：

1. 先跑 node tools/new-kp.js --id <id> --title "<正式标题>" --category <大类>
   --subcategory <子分类> [--tags "..."] [--time "..."] [--space "..."] --level A
   （题解用 tools/new-problem.js，并补齐 oj / problemId / difficulty / 数据范围）
2. 把我正文里的小标题改成规范章节名（算法原理 / 核心公式 / 逐行代码解析 /
   复杂度分析 / 适用场景 / 常见陷阱与注意事项 / 对比与扩展），内容一字不改；
3. 我的「思路是怎么想出来的」一节归入「## 算法原理」，保持它的叙述顺序；
4. 我随后给你 .cpp，你把它放进「逐行代码解析」的代码块，必须与 .cpp 逐字一致；
5. 跑 node tools/lint.js（error 必须为 0）→ node build.js；
6. 不要代写任何 .cpp 实现；我标了「（待核实）」的地方保留标记并单独列给我。
```

> 这样分工的好处：**网页版那段总结永远保持"人能读"**，网页需要的东西（frontmatter、章节名、代码同步）全部由 Trae 事后补，不会污染你的笔记。

## 4. "思路"这一节怎么写才算好（对照示例）

| ❌ 不合格（现场试错 / 只有结论） | ✅ 合格（复盘口吻 / 讲透为什么） |
|---|---|
| "算出来是 9×(10−d)，等等不对，重新算是 10。" | "个位贡献看起来和 $d$ 有关，但把 $q = 9-d$ 代进两个分支会发现：$d \le 8$ 走 `q >= i` 分支加 1，$d = 9$ 走 `q + 1` 分支也加 1，所以 $d = 1 \sim 9$ 的个位贡献恒为 10。" |
| "先暴力，不行，改用并查集。" | "正着做没法增量维护最大面积——每次切割要重算两边；把操作**倒过来**看，切割就变成"把两块并起来"，于是用并查集维护每块面积，倒序回答即可。" |
| "复杂度是 O(n log n)，用树状数组。" | "$n$ 个位置每个最多被树状数组处理 $\log n$ 次，所以是 $O(n\log n)$；空间只开了值和下标两个数组，$O(n)$。" |
| "注意边界。" | "如果 $n = 1$，线段树区间 $[1,1]$ 会一直递归到自己，必须先判 `l == r` 返回——这就是可持久化线段树那条 $n=1$ 无限递归的坑。" |

**一句话原则**：思路写"为什么这条路对、别的路为什么不走"，而不是"我当时先写错了什么"。

## 5. 门禁规则对照表（只在入库时才需要，平时读笔记不用管）

| 入库要求 | 对应规则 | 不满足会怎样 |
|---|---|---|
| 标题用正式名（无"自己写的""D. xxx"） | W002 | 侧边栏出现草稿味标题 |
| `id` 小写连字符、与文件名一致 | W001 / E003 | 锚点、互链失效 |
| `tags` ≤8（建议 3–6） | W010 | 标签稀释检索 |
| 复杂度不许写"未知" | W007 / W008 | 条目缺关键信息 |
| 章节名用规范词 | W022 | 缺必备章节 |
| 必须有「适用场景」 | W023 | — |
| 题目必须有「数据范围」 | W024 | 无法判断复杂度可行性 |
| 题目必须有 `oj` + `problemId` | W027 | 读者找不到原题 |
| 代码块与 `.cpp` 逐字一致（或只放片段） | W028 | **代码与讲解两版**，最坑的一类 |
| 无 `printf("耗时")` 之类调试输出 | W030 | 提交 OJ 直接 WA |
| 表格公式里的 `|` 转义、`$` 成对 | W019 / W018 | 表格错位、公式不渲染 |
| 无"等等/不对/？不，等一下" | W017 | 草稿残留 |

## 6. 网页版最容易翻车的 6 类（`docs/内容质量标准.md` §六有完整案例）

| 类型 | 例子 | 防线 |
|---|---|---|
| 复杂度想当然 | 并查集写"仅路径压缩均摊 $O(\alpha(n))$" | 要求"说明怎么数出来的" |
| 出处/年份记错 | 食物链写成 NOI 2024（实为 2001） | 题号年份必须核实，拿不到就标待核实 |
| 套公式不验前提 | 矩阵逆写 $A^{-1}=A^{mod-2}$（费马只对标量） | 要求写清前提 + 能举反例 |
| 样例凭记忆写 | P7915 样例输出写成 −1（实际有解） | 样例必须真跑过 |
| 代码与讲解两版 | 36 处代码漂移 | 代码留占位，`.cpp` 写好后逐字同步 |
| 残留调试代码 | P1050 输出后再打印耗时 → WA | 提交前搜一遍 `printf` / `cout` |

## 7. 速查

```
每次提问：  先发【第 2 节 开场提示词】（一次会话发一次）
聊到位了：  发【第 1.1 节 总结提示词】→ 得到一篇可直接读的笔记
想入库：    把笔记 + 【第 3 节】丢给 Trae，补 frontmatter、贴 .cpp、跑门禁
```

**常用 id 前缀**（Trae 落文件时用）：`basic-` 基础算法 · `dp-` 动态规划 · `ds-` 数据结构 · `graph-` 图论 · `math-` 数学 · `str-` 字符串 · `io-` 输入输出 · `exam-` 初赛笔记 · `prob-` 题目

**等级**：新内容默认 `level: A`（模板级）；被反复查阅再升 B；一批里 B ≤ 30%、C ≤ 10%。
