## 题目描述

你正在玩电子游戏并进入一个奖励关。系统依次随机抛出 $k$ 次宝物，每次可选择吃或不吃（必须在下一个宝物抛出前决定，且现在不吃的以后也不能再吃）。宝物共 $n$ 种，每次抛出每种的概率都是 $\frac{1}{n}$ 且相互独立。

获取第 $i$ 种宝物得 $p_i$ 分，但第 $i$ 种宝物有一个前提宝物集合 $s_i$：只有当 $s_i$ 中所有宝物都至少吃过一次，才能吃第 $i$ 种宝物（抛到当前不能吃的宝物，等于白白损失一次机会）。$p_i$ 可以为负。假设采取最优策略，求平均一共能得到多少分。

### 输入格式

第一行两个整数 $k$、$n$，表示抛出次数与宝物种数。第 $2$ 到 $n+1$ 行，第 $i+1$ 行有若干个整数：首先一个整数 $p_i$ 表示第 $i$ 种宝物的分数，接着若干个互不相同的整数表示前提宝物集合 $s_i$，行尾以 $0$ 结束。

### 输出格式

一行一个实数，表示答案，保留六位小数。

### 数据范围

$1 \le k \le 100$，$1 \le n \le 15$，$-10^6 \le p_i \le 10^6$。

## 解题思路

### 从 $n \le 15$ 想到状压

每种宝物只有「吃过 / 没吃过」两种状态，$n$ 种宝物的状态合起来正好是一个 $n$ 位二进制数 `mask`：第 $i$ 位为 $1$ 表示已经吃过第 $i$ 种宝物。因为 $n \le 15$，`mask` 的取值范围只有 $2^n \le 32768$，完全可以直接枚举。于是「当前已经吃过哪些宝物」这一信息被完整地压进了一个整数，这就是状压 DP 的入口。

### 为什么必须倒着推

先尝试正推：从第 $1$ 轮到第 $k$ 轮依次做决策。问题在于，第 $r$ 轮面对宝物 $i$ 时，「吃」还是「不吃」取决于**未来还会抛出什么**——例如一个分数很低的宝物，如果未来能靠它解锁一个高分宝物，那现在就该吃；但未来是随机的，正推时并不知道。决策依赖未知的未来，正推无法直接得出最优策略。

倒推则恰好绕开这一点。设 `dp[r][mask]` 表示「从第 $r$ 轮到第 $k$ 轮（共 $k-r+1$ 轮），当前已吃集合为 `mask` 时，未来能获得的最大期望得分」。倒推时从 $r=k$ 一路算回 $r=1$，那么计算 `dp[r][mask]` 时，它只依赖 `dp[r+1][·]`，而 `dp[r+1][·]` 已经在上一轮算好了——「未来」被提前求出来了，当前轮的决策就不再面对未知信息。

### 状态与转移

边界是 `dp[k+1][mask] = 0`：第 $k$ 轮结束之后不再有任何宝物，期望为 $0$。

对于状态 `(r, mask)`，枚举本轮抛出的宝物 $i$（$1 \le i \le n$，每种出现的概率都是 $\frac{1}{n}$）：

- 若前置条件满足，即 `(s[i] & mask) == s[i]`（`s[i]` 是第 $i$ 种宝物的前置条件掩码），则玩家可以吃、也可以不吃，取较优者：

$$
b_i = \max\Big(dp[r+1][mask],\ p_i + dp[r+1][mask \mid (1 \ll (i-1))]\Big)
$$

其中 `mask | (1 << (i-1))` 是「吃掉第 $i$ 种宝物」之后新的已吃集合。

- 若前置条件不满足，只能不吃，$b_i = dp[r+1][mask]$。

把 $n$ 种宝物各自的决策值取平均，得到：

$$
dp[r][mask] = \frac{1}{n}\sum_{i=1}^{n} b_i
$$

最终答案就是 `dp[1][0]`：从第 $1$ 轮开始、初始什么都没吃过时的最大期望。

### 为什么这样做是对的

第一，**无后效性**：`(r, mask)` 完整刻画了当前局面——轮数和已吃集合。之后每一轮抛出宝物的概率分布都与「过去具体按什么顺序抛出、做出过什么选择」无关，只与「现在已吃集合 `mask`」有关，因此可以安全地只按 `(r, mask)` 递推。

第二，**最优子结构**：在第 $r$ 轮，一旦决定「吃」或「不吃」，剩下的期望得分恰好是 `dp[r+1][新mask]` 或 `dp[r+1][mask]`，两者都已经是该子局面的最优值，取 `max` 就是当前局面的最优决策。

第三，**期望的线性性**：第 $r$ 轮的期望等于「每种宝物以 $\frac{1}{n}$ 概率出现时的最优决策值」的平均值，直接累加再除以 $n$ 即可，不需要考虑宝物之间的相关性（它们独立等概率出现）。

把三者合起来，倒推的归纳保证 `dp[1][0]` 就是全局最优策略下的期望得分。

## 逐行代码解析

本题资料未提供完整可运行代码，仅给出推导与实现要点，以下按模块给出伪代码。

### 模块一：状态与前置条件的位掩码表示

```text
读入 n（宝物种数）、k（轮数），以及每种宝物的分数 p[1..n]
读入每种宝物的前置条件，压成位掩码 s[1..n]
// 约定：mask 的第 (i-1) 位为 1 ⇔ 第 i 种宝物已经吃过
//       s[i] 的第 (j-1) 位为 1 ⇔ 吃第 i 种之前必须先吃第 j 种
```

- $n \le 15$，一个 `int` 的低 $15$ 位足以表示全部「已吃 / 未吃」信息，状态总数 $2^n$。
- 第 $i$ 种宝物统一映射到第 $(i-1)$ 位，`mask | (1 << (i-1))` 就表示「吃掉第 $i$ 种」。
- `s[i]` 是前置条件集合，判断能否吃第 $i$ 种只需检查 `(s[i] & mask) == s[i]`。

### 模块二：倒序 DP 框架与边界

```text
for mask = 0 to (1 << n) - 1:
    dp[k+1][mask] = 0               // 第 k 轮之后没有宝物，期望为 0

for r = k downto 1:                 // 从最后一轮往前推
    for mask = 0 to (1 << n) - 1:
        total = 0
        for i = 1 to n:             // 本轮等概率抛出宝物 i
            best = ...              // 见模块三，面对宝物 i 的最优决策值
            total += best
        dp[r][mask] = total / n     // 每种宝物概率 1/n
```

- 边界 `dp[k+1][·] = 0` 表示「已经过完 $k$ 轮，之后不再得分」。
- $r$ 必须从 $k$ 递减到 $1$，保证用到 `dp[r+1][·]` 时它已经算好，这是倒推的关键。
- 最终答案 `dp[1][0]` 对应「从第 $1$ 轮开始、什么都没吃」。

### 模块三：面对宝物 $i$ 的「吃 / 不吃」决策

```text
for i = 1 to n:
    if (s[i] & mask) == s[i]:       // 前置条件满足，可吃可不吃
        best = max(
            dp[r+1][mask],                        // 不吃：状态不变
            p[i] + dp[r+1][mask | (1 << (i-1))]   // 吃：加 p[i]，并入第 i 种
        )
    else:                           // 前置条件不满足，只能不吃
        best = dp[r+1][mask]
```

- 「吃」的收益是 `p[i]` 加上吃掉之后新状态 `mask | (1 << (i-1))` 的最优期望 `dp[r+1][...]`。
- 「不吃」的收益是 `dp[r+1][mask]`，已吃集合保持不变。
- 必须用 `max` 比较两种选择，而不能「看到 $p_i < 0$ 就拒绝」——负分宝物可能是解锁后续高分宝物的钥匙。

## 复杂度分析

- **时间复杂度**：状态数为 $O(k \cdot 2^n)$，每个状态枚举 $n$ 种宝物求一次决策，总复杂度 $O(k \cdot n \cdot 2^n)$。取 $k=100$、$n=15$ 时约 $100 \times 15 \times 32768 \approx 4.9 \times 10^7$，在 C++ 中可直接通过。
- **空间复杂度**：朴素做法存整张 `dp` 表为 $O(k \cdot 2^n)$；由于 `dp[r]` 只依赖 `dp[r+1]`，用滚动数组只保留相邻一层可降到 $O(2^n)$。

## 常见陷阱与注意事项

1. **负分宝物不能贪心跳过**：$p_i$ 可能为负，但吃下负分宝物才能解锁后面更高分的宝物；若按「负分就不吃」的贪心策略会漏掉最优解，转移必须老老实实用 `max` 比较「吃」与「不吃」。
2. **必须倒序枚举 $r$**：若正推，当前决策依赖未来抛出的宝物（未知），状态转移无法成立；只有从 $r=k$ 倒推到 $r=1$，`dp[r+1]` 才是已知的。
3. **前置条件判断要精确**：判定能否吃第 $i$ 种宝物的条件是 `(s[i] & mask) == s[i]`，即 `mask` 要覆盖 `s[i]` 的全部置位；写成 `(s[i] & mask) != 0` 是错的，那只是「至少满足一个前置」。
4. **位序要对齐**：宝物编号 $i$ 与二进制位 $(i-1)$ 之间必须全程一致——`mask` 的第 $(i-1)$ 位、`s[i]` 的第 $(j-1)$ 位、以及吃后的 `mask | (1 << (i-1))` 要使用同一套编号，否则前置条件判断会错位。
5. **边界与精度**：`dp[k+1][·] = 0` 必须显式初始化；精度建议用 `long double`，输出时保留 6 位小数（如 `printf("%.6Lf", ans)`）。

## 对比与扩展

- **倒推 vs 正推的适用判据**：期望 DP 不一定都要倒推。当决策只依赖「过去」或「当前」、与未来无关时（例如按固定概率往前走的随机过程），正推即可；本题的「吃 / 不吃」决策依赖「未来还能吃到什么」，因此才需要倒推——这是判断何时该倒推的核心信号。
- **状压 DP 的入口特征**：状态维是「某个元素集合是否已选」，且元素个数很小（本题 $n \le 15$）时，优先考虑状压；本题还把它与「概率期望」叠加，是两类 DP 的经典结合。
- **与本库知识点的联系**：本题是「期望 DP」知识点的直接应用——用期望的线性性把每轮拆成 $n$ 个等概率分支再取平均，并借助倒推消除对未来的依赖；状压部分则是把「已吃集合」编码成一个整数。
- **同类延伸**：许多需要「从终点反推最优策略」的期望 / 概率 DP 题（例如必须等到未来信息才能决策的游戏）都可以套用本题的「倒推 + 线性期望 + 集合状态」框架，区别只在于状态维换成其他信息。
