## 题目描述

（题面配图为兔子插画，不嵌入正文。）

小 C 的兔子不是雪白的，而是五彩缤纷的。每只兔子都有一种颜色，不同的兔子可能有相同的颜色。小 C 把她标号从 1 到 $n$ 的 $n$ 只兔子排成长长的一排，来给他们喂胡萝卜吃。排列完成后，第 $i$ 只兔子的颜色是 $a_i$。

俗话说得好，"萝卜青菜，各有所爱"。小 C 发现，不同颜色的兔子可能有对胡萝卜的不同偏好。为了使得胡萝卜喂得更加准确，小 C 想知道在区间 $[l_j,r_j]$ 里有多少只颜色为 $c_j$ 的兔子。

不过，因为小 C 的兔子们都十分地活跃，它们不是很愿意待在一个固定的位置；与此同时，小 C 也在根据她知道的信息来给兔子们调整位置。所以，有时编号为 $x_j$ 和 $x_j+1$ 的两只兔子会交换位置。小 C 被这一系列麻烦事给难住了。你能帮帮她吗？

### 输入格式

输入第 1 行两个正整数 $n,m$。

输入第 2 行 $n$ 个正整数，第 $i$ 个数表示第 $i$ 只兔子的颜色 $a_i$。

接下来 $m$ 行，每行为以下两种中的一种：

- `1 l r c`：询问在区间 $[l,r]$ 里有多少只颜色为 $c$ 的兔子；
- `2 x`：$x$ 和 $x+1$ 两只兔子交换了位置。

### 输出格式

对于每个 1 操作，输出一行一个正整数，表示对于这个询问的答案。

### 数据范围

- 所有测试点：$1\le l_j<r_j\le n$，$1\le x_j<n$；
- $n,m\le 3\times 10^5$，$a_i,c\le 3\times 10^5$（**题面表格缺失，按做题笔记补录**）；
- 特殊性质 1：保证对于所有操作 1，有 $|r_j-l_j|\le 20$ 或 $|r_j-l_j|\ge n-20$；
- 特殊性质 2：保证不会有两只相同颜色的兔子。

## 样例

**输入：**

```
6 5
1 2 3 2 3 3
1 1 3 2
1 4 6 3
2 3
1 1 3 2
1 4 6 3
```

**输出（本代码实测，与官方一致）：**

```

```

**解释：** 前两个 1 操作和后两个 1 操作对应相同；在第三次的 2 操作后，3 号兔子和 4 号兔子交换了位置，序列变为 `1 2 2 3 3 3`。

## 解题思路

### 一、题目在问什么

一维序列上的「单点（相邻交换）修改 + 区间颜色计数」：查询 $[l,r]$ 内颜色 $c$ 的个数，修改只有相邻两只兔子交换。$n,m\le3\times10^5$，查询次数多、区间大——每次查询 $O(n)$ 扫描最坏 $9\times10^{10}$ 次操作，必超时；必须做到单次 $O(\log n)$。

### 二、核心直觉：颜色 → 位置映射

把两件事分开维护：

- `col[i]`：位置 $i$ 的颜色（位置 → 颜色）；
- `idx[c]`：颜色 $c$ 出现的所有位置，**升序排列**（颜色 → 位置）。

于是「区间 $[l,r]$ 内颜色 $c$ 的数量」=「升序数组 `idx[c]` 里落在 $[l,r]$ 内的元素个数」——**端点定位后下标相减**：

```cpp
return upper_bound(idx[c].begin(), idx[c].end(), r)
     - lower_bound(idx[c].begin(), idx[c].end(), l);
```

下界用 `lower_bound`（第一个 $\ge l$），上界用 `upper_bound`（第一个 $>r$），两个迭代器相减恰为数量，无需任何循环。

### 三、修改只有相邻交换，为什么位置数组仍然有序（关键性质）

交换 $x$ 与 $x+1$，设 $col[x]=ca$、$col[x+1]=cb$：

- 位置数组里至多两个元素受影响：`idx[ca]` 里的 $x$ 要改成 $x+1$，`idx[cb]` 里的 $x+1$ 要改成 $x$；
- 用 `lower_bound` 定位这两个值，改掉即可，**不需要重建数组**。

**为什么改完仍然升序**（这是本解法的生命线）：

- 看 `idx[ca]`：把 $x$ 改成 $x+1$。$x$ 的前驱（若有）$<x<x+1$ 不受影响；$x$ 的后继（若有）一定 $>x+1$——因为位置 $x+1$ 的颜色是 $cb\ne ca$，$x+1$ 根本不在 `idx[ca]` 里。所以新值仍小于后继。
- 看 `idx[cb]`：把 $x+1$ 改成 $x$。$x+1$ 的前驱（若有）一定 $<x$——因为位置 $x$ 的颜色是 $ca\ne cb$，$x$ 不在 `idx[cb]` 里；后继 $>x+1>x$。所以新值仍大于前驱。

**结论：相邻交换不破坏任何颜色位置数组的单调性**，二分的前提全程成立。单次修改 $O(\log k_{ca}+\log k_{cb})$。

**初始天然有序**：预处理按 $i=1..n$ 顺序 `emplace_back(i)`，每个 `idx[c]` 生来升序，无需排序。

### 四、暴力 → 正解对比

| 维度 | 暴力扫描 | 颜色→位置映射 + 二分 |
|---|---|---|
| 单次查询 | $O(r-l+1)\le O(n)$ | $O(\log n)$ |
| 单次修改 | $O(1)$（直接 swap） | $O(\log n)$（二分定位后改一个值） |
| 预处理 | 无 | $O(n)$ |
| 空间 | $O(n)$ | $O(n+V)$（$V$ 为颜色值域） |
| 前提 | 无 | 修改必须保持位置数组有序（相邻交换满足） |
| $n,m=3\times10^5$ 是否可行 | 否（约 $9\times10^{10}$） | 是（约 $10^6$ 级） |

### 五、手算走读（样例 1）

初始 `col = [1,2,3,2,3,3]`，`idx[1]=[1]`、`idx[2]=[2,4]`、`idx[3]=[3,5,6]`。

- 查询 `1 1 3 2`：`idx[2]` 中落在 $[1,3]$ 的元素 = `[2]` → 1 ✓。
- 查询 `1 4 6 3`：`idx[3]` 中落在 $[4,6]$ 的 = `[5,6]` → 2 ✓。
- 修改 `2 3`：$ca=col[3]=3$、$cb=col[4]=2$；`idx[3]` 中把 3 改成 4 → `[4,5,6]`；`idx[2]` 中把 4 改成 3 → `[2,3]`；`col[3]=2, col[4]=3` → 序列 `1 2 2 3 3 3` ✓。
- 查询 `1 1 3 2`：`idx[2]=[2,3]` 落在 $[1,3]$ → 2 ✓。
- 查询 `1 4 6 3`：`idx[3]=[4,5,6]` 落在 $[4,6]$ → 3 ✓。

### 六、通用模板

```cpp
vector<int> pos[V];   // 每种值出现的位置，保持升序

// 区间 [l, r] 内值 v 的个数
int count_in_range(int l, int r, int v) {
    return upper_bound(pos[v].begin(), pos[v].end(), r)
         - lower_bound(pos[v].begin(), pos[v].end(), l);
}
```

适用条件：值域有限（可直接开数组）、修改操作不破坏位置数组的单调性。这正是「值 → 有序位置数组 + 二分计数」这一族问题的最基础形态。

## 逐行代码解析

代码拆成 3 个模块，按顺序拼接即完整程序。

### 模块 1 全局数组与查询函数

```cpp
#include<iostream>
#include<vector>
#include<algorithm>
using namespace std;
const int nmax = 3e5 + 5;
vector<int> idx[nmax],col;

//读取数量
int get(int l, int r, int c)
{
	return upper_bound(idx[c].begin(), idx[c].end(), r) - lower_bound(idx[c].begin(), idx[c].end(), l);
}


```

- `idx` 是**长度为 nmax 的 vector 数组**（静态存储）：`idx[c]` 只被颜色 $c$ 使用，$c\le3\times10^5$ 时不越界；颜色超过 nmax 需要离散化（见陷阱 8）。
- `col` 是全局 vector、`main` 里 `assign(n+1,0)` 后按下标使用；`get` 就是「上界减下界」的一行式——数量来自迭代器差，没有显式循环。

### 模块 2 相邻交换

```cpp
//交换
void _swap(int a)
{
	int b = a + 1;
	//相邻交换不会破坏有序性
	if (col[a] == col[b]) return;
	int ca = col[a], cb = col[b];
	int idx_a = lower_bound(idx[ca].begin(), idx[ca].end(), a) - idx[ca].begin();
	idx[ca][idx_a] = b;
	int idx_b = lower_bound(idx[cb].begin(), idx[cb].end(), b) - idx[cb].begin();
	idx[cb][idx_b] = a;
	swap(col[a], col[b]);
}


```

- `b = a + 1` 永不出界：题目保证 $1\le x<n$，交换对象总是相邻两只。
- **同色直接 return**：`col[a]==col[b]` 时序列不变。注意本题代码里即使不 return，两次 `lower_bound` 也会先后写到同一槽位、最终恰好恢复原状（见陷阱 1），但 return 让意图清晰、免去两次无谓二分。
- `idx_a` 是 `idx[ca]` 中值 $a$ 的下标，改写成 $b$；`idx_b` 同理把 $b$ 改成 $a$——每色数组恰好一个值 ±1，且不会越过任何邻居（第三步的保序证明）。
- 最后 `swap(col[a], col[b])` **必须同步**位置→颜色表，否则下一次交换会定位错颜色。

### 模块 3 主函数

```cpp
int main()
{
	ios::sync_with_stdio(false);
	cin.tie(nullptr); cout.tie(nullptr);
	int n,m;
	cin >> n >> m;
	col.assign(n + 1, 0);
	for (int i = 1; i <= n; i++)
	{
		int x;
		cin >> x;
		idx[x].emplace_back(i);
		col[i] = x;
	}
	for (int i = 1; i <= m; i++)
	{
		int op;
		cin >> op;
		if (op == 1)
		{
			int l, r, c;
			cin >> l >> r >> c;
			cout << get(l, r, c) << '\n';
		}
		else
		{
			int x;
			cin >> x;
			_swap(x);
		}
	}
	return 0;
}
```

- 读入 $n,m$ 后按 $i=1..n$ 顺序 `emplace_back(i)`：位置递增插入，`idx` 天然升序，不需要 sort。
- `op==1` 走查询、否则走交换；交换操作输入只有一个 $x$。

## 复杂度分析

- 预处理 $O(n)$（顺序插入天然有序，无需排序）；
- 单次查询 $O(\log k_c)\le O(\log n)$；单次修改两次 `lower_bound` $O(\log k_{ca}+\log k_{cb})$；
- 总计 $O((n+m)\log n)$，$n,m\le3\times10^5$ 完全可行；
- 空间：`col` $O(n)$；`idx` 数组按值域开 $O(V)$ 个头 + 共 $n$ 个位置元素 → $O(n+V)$，$V$ 为颜色值域上限。

## 常见陷阱与注意事项

1. **同色交换**：`col[a]==col[b]` 时先 return。本题实现里若不 return，两次 `lower_bound` 会先后命中同一个槽位、恰好把值改回原样，结果不坏——但这是实现细节的巧合：第一次把 $a$ 改成 $b$ 后，第二次找 $b$ 会命中刚写过的槽位再改回 $a$。换一种"先记录两个下标、再一次性改写"的写法时，同色不特判就会留下 `..., x+1, x, ...` 逆序、二分全错。所以 return 是**应当保留的好习惯**，别因为它"当前无害"就删。
2. **上下界开闭**：下界 `lower_bound`（第一个 $\ge l$）、上界 `upper_bound`（第一个 $>r$），相减才是数量；写成 `upper_bound(r+1)` 或下界也用 `upper_bound` 会差 1，偏移非常隐蔽。
3. **下标从 1 开始**：位置数组存的是 $1..n$ 的位置值，`col` 开 $n+1$；二分比较的是位置值本身，与 0 基下标无关。
4. **`col[]` 必须同步更新**：`idx` 改完别忘了 `swap(col[a], col[b])`，否则后续交换定位错颜色、改错数组。
5. **有序性是生命线**：一旦修改变成"任意两个位置交换"或"单点赋值"，位置数组不再保序，二分直接失效，必须换树状数组（离散化 + 单点修改前缀和）或带修莫队。
6. **同色交换与保序证明的依赖**：第三步证明用了「$x+1$ 不在 `idx[ca]` 里」，即 $col[x+1]\ne ca$——这恰是同色特判之外的默认情形；若颜色可以同色，证明前提不成立，所以同色必须先排除。
7. **值域越界**：`idx` 是静态数组，颜色编号 $>nmax$ 或为负会越界；值域扩大时改 `map<int, vector<int>>` 或先离散化（见对比与扩展）。
8. **静态数组体积**：`idx[nmax]` 是 $3\times10^5$ 个 `vector` 对象（每个 24 字节级）≈ 7MB 静态区，属于常规开销；若同时开多个同尺寸结构要注意内存总量。

## 对比与扩展

**暴力 vs 正解**：见「四、暴力 → 正解对比」表——正解把查询的 $O(n)$ 压成 $O(\log n)$，代价是修改从 $O(1)$ 升到 $O(\log n)$，并引入"保序"前提；本题修改恰好是相邻交换，前提成立。

### 变式 1：值域扩大（预提案 1，经确认写入）

**触发条件**：颜色编号很大（超过内存可承受的数组上界）或为负，`idx` 不能再按值域直接开数组。

**方案 A：map 存桶**。把"桶数组"换成"按需创建"的映射：只有真实出现过的颜色才有桶，桶内仍是升序位置数组。查询时先查该颜色是否存在——不存在直接答 0，存在则对桶内数组做同样的 `upper_bound − lower_bound`；修改时先定位两个桶再各自二分改写。要点：

- 内存只与**实际出现的颜色种数**有关（$O(n)$ 级别），不再受值域上界支配；
- 复杂度多了「一次树查找」的常数，桶内二分不变；
- **在线可用**：不需要预先知道所有询问。

**方案 B：离散化**。把所有出现过的颜色（初始 $a_i$ 连同每个询问里的 $c$）收集、排序、去重，映射到 $[1,t]$；之后桶数组开 $t+1$ 大小，代码与本题原版**除"取桶时先查映射表"外完全一致**。要点：

- 桶编号紧凑、内存 $O(n+q)$，常数优于 map；
- **必须把询问里的 $c$ 也纳入映射**，否则查询颜色没有桶、会漏答或越界；
- 离散化需要**离线**（全部询问已知才能收集颜色）。本题多操作全部给出、天然离线，方案 B 完全可行；若题目要求在线回答（边读边答），离散化做不了，只能走方案 A 的 map。

**两案取舍**：在线 → map；离线且追求常数 → 离散化。二分模板本身一行不变，变的是"取桶"这一步。

### 变式 2：修改破坏单调性（来自做题笔记变式 2）

**触发条件**：修改不再是相邻交换——比如任意两个位置互换、单点改颜色（赋值）。此时位置数组不再保持升序，`upper_bound − lower_bound` 的计数失去意义，本解法失效。

**方案 A：树状数组（按颜色分组）。** 把"有序位置数组 + 二分计数"换成"前缀和差分"：

- 对每种颜色维护一个「出现与否」的 0/1 序列（下标是位置），区间 $[l,r]$ 内该颜色的个数 = 该序列在 $[l,r]$ 的和；
- 单点修改 = 旧颜色序列在旧位置减 1、新颜色序列在新位置加 1，都是 BIT 的单点修改，$O(\log n)$；
- 颜色多时按实际出现颜色离散化编号，或对询问离线按颜色分批处理；
- 优点：**完全不依赖有序性**，任意交换、任意赋值都支持；缺点：实现比二分版重，常数更高。

**方案 B：带修莫队。** 当询问的"计数"**不可减**时（典型如「区间内不同颜色的种数」加上单点修改），前缀和差分不再适用，树状数组方案失效；此时把修改当成第三维时间，对 $(l,r,t)$ 三维分块转移，复杂度约 $O(n^{2/3})$ 级：

- 优点：能处理不可减计数 + 带修改的统一框架；
- 缺点：离线、复杂度高于 $O(\log n)$、常数大，只在 BIT 处理不了时才选它。

**取舍与本题定位**：可减性计数（某颜色的出现次数）+ 任意修改 → 树状数组；不可减计数（种数等）→ 带修莫队。本题之所以能用最轻的"有序数组 + 二分"，正是因为修改被限定为相邻交换、保序性质成立——这是题目给的特殊红利；一旦红利消失，就按上面两条路升级。

**举一反三（来自做题笔记）**：
- P1903 [国家集训队] 数颜色：区间颜色计数 + 单点修改的经典题，与本题同属「单点修改 + 区间查询」一族；
- LeetCode 34 在排序数组中查找元素的第一个和最后一个位置：`upper_bound − lower_bound` 端点定位的基础练习。

**同色反例走查（预提案 2，经确认写入）**：设 `col=[2,1,1]`、`idx[1]=[2,3]`，若交换 2、3 两只（同色）且**不特判**：$ca=cb=1$。第一次 `lower_bound(idx[1], 2)` 命中槽 0，改写为 3 → `idx[1]=[3,3]`；第二次 `lower_bound(idx[1], 3)` 命中**槽 0**（刚写过的 3），改写为 2 → `idx[1]=[2,3]` 复原。可见本实现恰好自我修复；但若实现改为「先记 `idx_a`、`idx_b` 两个下标，再分别写 `b`、`a`」（很多模板这么写），槽 0 写成 3、槽 1 写成 2 → `[3,2]` 逆序，此后 `idx[1]` 二分结果全错。两种写法只差"是否重新查找"，同色特判是防住第二类写法的唯一保险。
