## 题目描述

给定两个仅由数字组成的字符串 $a$ 和 $b$。一次操作中，你可以在任意一个字符串里选择两个相邻字符，把它们替换为两者的和模 10。例如：

```
57246 → 2246  (5+7=12 → 2)
57246 → 5946  (7+2=9)
57246 → 5766  (2+4=6)
57246 → 5720  (4+6=10 → 0)
```

每次操作后字符串长度恰好减 1。你可以执行任意多次操作（包括零次），必须使两个字符串相等（$|a| = |b|$ 且对应每个位置的字符都相同）。求最终得到的相同字符串的**最大可能长度**；若无法使它们相等，输出 $-1$。

### 输入格式

- 第一行：$t$（$1 \le t \le 2 \times 10^3$）
- 每组数据两行：字符串 $a$ 和 $b$（$1 \le |a|, |b| \le 5 \times 10^3$，仅含数字）

保证 $\sum (|a| + |b|) \le 10^4$。

### 输出格式

每组数据输出一个整数。

## 解题思路

### 第一步：操作的本质——"切香肠"

把字符串想象成一根香肠，每次操作把相邻两段捏成一段，新段的值 = 两段之和的个位数。捏一通之后，串里的每个字符都对应原串中**连续的一段**，值 = 该段数字之和模 10。

**关键结论**：任意一种"切段方案"都能通过捏合实现，且段与段之间互不打扰（加法可任意结合，每段内部从左往右捏到底即可）。因此问题完全等价于：

> 给 $a$ 选一种切成 $L$ 段的方案，给 $b$ 也选一种切成 $L$ 段的方案，要求两者的"每段之和模 10 的序列"完全相同。$L$ 越大越好。

### 第二步：换记账方式——前缀和模 10 的"读数链"

逐段比较段和太繁琐，换一种记账方式：想象一个里程表从左到右扫过原串，每碰到一个切点就记录"到目前为止扫过的所有数字之和模 10"。

设前缀和模 10 序列为 $p_0 = 0, p_1, p_2, \ldots, p_n$（$p_0 = 0$ 为哨兵，$p_n = \text{sum}(a) \bmod 10$）。则：

- 第 $i$ 段的值 $= (p_i - p_{i-1}) \bmod 10$
- 两条读数链相同 $\iff$ 每个"读数差"相同 $\iff$ 最终串逐字符相同

问题转化为：找一条尽量长的读数链 $w_0 \to w_1 \to \cdots \to w_L$，使得 $a$ 和 $b$ 中都存在一串递增的切点位置，每个切点上的前缀和模 10 恰好是链上对应的值。

### 第三步：链的头尾"焊死"

- **链头**：第一个切点必然是位置 0，读数 $= 0$，没有选择
- **链尾**：最后一个切点必然是串尾，读数 $= \text{sum}(a) \bmod 10 = \text{sum}(b) \bmod 10$（记为 $S$），也没有选择

**$-1$ 的来源**：最终串的和 $\equiv \text{sum}(a) \pmod{10}$，同时 $\equiv \text{sum}(b) \pmod{10}$。若两者个位不同，永远不可能相等，输出 $-1$。

**$-1$ 之外一定有解**：个位相同时，两边全部捏成一团，各自得到 $S$，长度 1 的公共串总可以做得到。

### 第四步：核心——中间部分就是 LCS

链的中间部分 $w_1, \ldots, w_{L-1}$ 需要在 $a$ 的中间读数序列（位置 1 到 $n-1$ 的前缀和模 10）中按顺序出现，也要在 $b$ 的中间读数序列中按顺序出现——这正是**最长公共子序列（LCS）**的定义。

$$\boxed{\text{答案} = \text{LCS}(\text{midA}, \text{midB}) + 1}$$

其中 $\text{midA}$ 是 $a$ 的位置 1 到 $n-1$ 上的前缀和模 10 序列（去掉头 0 和尾 $S$），$\text{midB}$ 同理。

**为什么必须 DP、不能贪心**：例如 $\text{midA} = [1, 2, 3]$，$\text{midB} = [2, 3, 1]$。贪心地一见到 1 就匹配只得 1 个；而正确答案是先放过 1，匹配 2、3，得 2 个。早匹配可能堵死后面的匹配，必须用 DP 全局考虑。

### 完整例子走查

**例 1**：$a = 123$，$b = 321$

- $a$ 前缀和模 10：$[0, 1, 3, 6]$；$b$ 前缀和模 10：$[0, 3, 5, 6]$。尾都是 6 $\checkmark$
- $\text{midA} = [1, 3]$，$\text{midB} = [3, 5]$。LCS $= [3]$，长度 1
- 答案 $= 1 + 1 = 2$。链 $0 \to 3 \to 6$，读数差 $33$

**例 2**：$a = 3111$，$b = 1311$

- $a$ 读数：$[0, 3, 4, 5, 6]$；$b$ 读数：$[0, 1, 4, 5, 6]$。尾都是 6 $\checkmark$
- $\text{midA} = [3, 4, 5]$，$\text{midB} = [1, 4, 5]$。LCS $= [4, 5]$，长度 2
- 答案 $= 3$。链 $0 \to 4 \to 5 \to 6$，读数差 $411$

**例 3**：$a = 55$，$b = 555$。个位 $0 \ne 5$，输出 $-1$。

## 逐行代码解析

### 快速输入

```cpp
inline void read(vector<int>& arr)
{
    arr.clear();
    arr.emplace_back(0);      // 哨兵：位置 0 的前缀和 = 0
    char ch = getchar();
    while (ch < '0' || ch > '9') ch = getchar();  // 跳过非数字字符（换行等）
    while (ch >= '0' && ch <= '9')
    {
        arr.emplace_back(ch - 48);  // 存原始数字值
        ch = getchar();
    }
}
```

- `arr[0] = 0`：哨兵，使前缀和计算统一（$p_0 = 0$）
- 读入后 `arr` 为 $[0, d_1, d_2, \ldots, d_n]$，长度 $n+1$

### 前缀和模 10（原地转换）

```cpp
for (int i = 1; i < A.size(); i++) A[i] = (A[i] + A[i - 1]) % 10;
```

将原始数字序列原地转换为前缀和模 10 序列。此时 `A` 为 $[0, p_1, p_2, \ldots, p_n]$，其中 $p_i = (\sum_{k=1}^{i} d_k) \bmod 10$。

### LCS 动态规划

```cpp
vector<vector<int>> dp(A.size(), vector<int>(B.size(), 0));
for (int i = 1; i < A.size(); i++)
{
    for (int j = 1; j < B.size(); j++)
    {
        if (A[i] == B[j]) dp[i][j] = dp[i - 1][j - 1] + 1;
        else dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]);
    }
}
```

- **状态定义**：`dp[i][j]` = `A[1..i]` 与 `B[1..j]` 的 LCS 长度
- **转移方程**：
  - `A[i] == B[j]`：当前读数可以配对，`dp[i][j] = dp[i-1][j-1] + 1`
  - 否则：取两边末尾不用的较大值，`dp[i][j] = max(dp[i-1][j], dp[i][j-1])`
- **下标从 1 开始**：`A[0] = B[0] = 0`（哨兵），LCS 从位置 1 开始匹配，等价于"链头 0 已自动匹配"

### 输出

```cpp
if (A.back() == B.back()) write(dp[A.size() - 1][B.size() - 1]);
else write(-1);
```

- `A.back()` 和 `B.back()` 分别是两串的总和模 10（链尾 $S$）
- 若两者不同，输出 $-1$
- 若相同，输出 `dp[n][m]`，即完整前缀和序列的 LCS 长度。由于链头 0 和链尾 $S$ 必然匹配，完整 LCS $=$ 中间 LCS $+ 2$，答案 $=$ 完整 LCS $- 1$。但代码直接用完整序列做 LCS，$\text{dp}[n][m]$ 已经包含链头和链尾的匹配，恰好等于答案

## 复杂度分析

### 时间复杂度

| 操作 | 复杂度 | 说明 |
|---|---|---|
| 前缀和模 10 | $O(n + m)$ | 两个串各一次线性扫描 |
| LCS DP | $O(nm)$ | 二维 DP 表 |
| **总计** | $O(nm)$ | DP 主导 |

单组最坏 $n = m = 5000$，DP 约 $2.5 \times 10^7$ 步，$\sum(|a|+|b|) \le 10^4$ 保证不会多组同时最大。

### 空间复杂度

| 实现 | 空间 | 说明 |
|---|---|---|
| 二维 DP 表 | $O(nm)$ | 本实现，直观 |
| 滚动数组优化 | $O(\min(n,m))$ | 只保留两行，适合内存受限场景 |

## 常见陷阱与注意事项

1. **忘记 $-1$ 判定**
   - 总和模 10 不同时永远不可能相等，必须先检查 `A.back() == B.back()`

2. **端点处理**
   - 代码使用完整前缀和序列（含头 0 和尾 $S$）做 LCS，答案直接是 `dp[n][m]`
   - 若用去掉头尾的中间序列做 LCS，答案 $= \text{LCS}(\text{midA}, \text{midB}) + 1$
   - 两种口径不能混用

3. **LCS 不能用贪心**
   - 贪心匹配会堵死后续匹配，必须用 DP 全局考虑

4. **前缀和必须取模 10**
   - 读数链的值是 $\bmod 10$ 意义下的，直接比前缀和（不取模）会导致错误

5. **$n = 1$ 或 $m = 1$ 的边界**
   - 中间序列为空，在同余前提下答案为 1（两边都是单字符，已相等）

6. **哨兵 `A[0] = 0` 的作用**
   - 使前缀和计算统一，同时使 LCS 的 `dp[0][j] = dp[i][0] = 0` 自动初始化

## 对比与扩展

| 方法 | 时间 | 空间 | 特点 |
|---|---|---|---|
| **前缀和模 10 + LCS DP（本算法）** | $O(nm)$ | $O(nm)$ 或滚动 $O(\min(n,m))$ | 问题转化 + 经典 DP |
| 暴力模拟所有操作 | 指数级 | $O(n+m)$ | 枚举所有捏合方式，不可行 |
| 贪心匹配 | $O(n+m)$ | $O(1)$ | 似是而非，反例已说明 |

### 扩展

- **问题转化思维**：将"捏合操作"转化为"切段方案"，再转化为"前缀和读数链"，最终归约为 LCS——这是一条经典的"操作 $\to$ 切分 $\to$ 前缀和 $\to$ 子序列"转化链
- **模意义下的前缀和**：前缀和取模后值域缩小到 $0 \sim 9$，但 LCS 不能利用这一点加速（仍需 DP 保证全局最优）
- **滚动数组优化**：LCS 只依赖上一行，可用两行滚动数组将空间降至 $O(\min(n,m))$
