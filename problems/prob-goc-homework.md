## 题目描述

有 $n$ 个同学排成一列，位置依次为 $1 \sim n$，讲台在位置 $0$。有 $m$ 本作业堆成一摞，只能**从上往下**逐本拿取，第 $i$ 本作业属于同学 $a_i$。

GOC 一次最多携带 $w$ 本作业（$w \le 5$），他可以随时回讲台取下一批作业，沿路分发；发完全部作业后**最后不必回到讲台**。求发完所有作业的**最短总行走距离**。

题面未给出显式的输入格式说明；依据所附代码，输入共两行：

- 第一行三个整数 $n,m,w$，分别表示同学数、作业本数、一次最多携带的本数；
- 第二行 $m$ 个整数 $a_1,a_2,\dots,a_m$，依次表示自上而下第 $i$ 本作业归属的同学编号。

### 输出格式

题面未给出显式的输出格式说明；依据所附代码，输出一行一个整数，表示发完所有作业的最短总行走距离。

### 数据范围

- $n \le 24$，$m \le 1000$，$w \le 5$；
- 同学编号 $a_i$ 满足 $1 \le a_i \le n$（由「第 $i$ 本作业属于同学 $a_i$」可直接得出）。

## 解题思路

看到 $w \le 5$，第一个念头是：**手里这一摞作业的目标集合很小，可以整个塞进状态**；再看 $n \le 24 < 2^5$，每个同学编号恰好能用 $5$ 个二进制位编码，于是 $w$ 本作业最多 $5w \le 25$ 位，压进一个 `int` 绰绰有余。这就是「状态压缩 + 记忆化搜索」的入口。

### 关键性质：沿路分发

问题的核心动作是「从讲台（位置 $0$）走到某个位置 $d$，再返回讲台」。这一趟往返的代价是 $2d$，而途中会依次经过位置 $1,2,\dots,d$——也就是说，**只要手里有目标 $\le d$ 的作业，这一趟都能顺路发掉，不必额外绕路**。于是决策退化成「选一个最远的落点 $d$」，代价只由 $d$ 决定，与手里具体发几本无关。

### 状态定义

用 `dfs(i, state)` 表示：已经处理完前 $i$ 本作业（第 $1 \sim i$ 本已被取走或分发），当前手里还拿着若干本作业，这些作业的目标编号被压缩在 `state` 里（每本占 $5$ 位，按从高到低排列，空位为 $0$）。函数返回**从当前局面出发，发完剩余所有作业还需要的最短额外距离**。

编码方式：`state` 从高到低第 $j$ 个 5 位块存同学编号 $x_j$，即 `state = (x[1] << 5*(w-1)) | (x[2] << 5*(w-2)) | ...`（具体顺序无所谓，只要能唯一表示「手里拿着哪个多重集合」即可）。用 `std::map<int, i64>` 对每个进度 $i$ 做记忆化。

### 转移方程

设 $x[1..w]$ 为解码出的目标数组（非零值按降序排列，空位为 $0$）。

**递归基**（$i = m$）：所有作业都已取走，只需把手里剩下的全部发掉。因为最后不用回讲台，只走一趟，代价就是最远目标的位置：

$$
dfs(m, state) = \max_{1 \le j \le w} x_j
$$

（手里为空时最大值是 $0$，代价为 $0$。）

**决策一 · 再拿一本**（手里不足 $w$ 本且 $i < m$）：把第 $i+1$ 本作业加入手中，不产生行走代价：

$$
dfs(i, state) \to dfs(i+1, state')
$$

其中 $state'$ 是把 $a_{i+1}$ 插入手中后重新排序压缩的结果。

**决策二 · 发掉一批**：枚举手里出现的某个目标 $d$，从讲台出发走到 $d$ 再回来（代价 $2d$），顺路发掉**所有目标 $\le d$ 的作业**，手里只保留目标 $> d$ 的：

$$
dfs(i, state) = \min_{d \in \text{hand}}\Big(2d + dfs\big(i,\, state'\big)\Big)
$$

其中 $state'$ 是删去所有目标 $\le d$ 的作业后得到的新状态。注意递归时 $i$ 不变——这一决策只发书、不取新书。

最终答案为 $dfs(0, 0)$（还没取书、手里为空）。

### 为什么这样做是对的

- **每次出发都回讲台**：除最后一次外，每次「走到 $d$ 再回来」恰好对应一次往返，符合「可以随时回讲台取下一批」的规则；最后一次已在递归基里特殊处理，只走单程。
- **拿书顺序单调**：只能从上往下拿，所以「已处理到第 $i$ 本」这个进度只会单调前进；决策二不动 $i$，决策一让 $i$ 加一，任何合法发书序列都能被这棵搜索树枚举到。
- **顺路一次发掉不更贵**：$w$ 很小，手里书不多；若把同一个目标 $d$ 分两趟发，两趟都要走到 $d$，总代价至少 $4d$，而一趟发完只需 $2d$。更一般地，走到 $d$ 时把途中所有目标 $\le d$ 的作业一并发掉，不会比分开走更贵，因此「顺路一次发掉」不会漏掉更优解。
- **编码无冲突**：$n \le 24 < 2^5$，每个编号占满 $5$ 位互不重叠；$5w \le 25$ 位不会溢出 `int`，压缩与解码是一一对应的。

## 逐行代码解析

### 模块一：入口与读入

```cpp
#include <bits/stdc++.h>

using i64 = long long;

void solve(void) {
    int n, m, w;
    std::cin >> n >> m >> w;
    std::vector<int> a(m + 1);
    for (int i = 1; i <= m; i++) std::cin >> a[i]; // 读入自上而下每本作业的目标同学
```

- `i64` 是 `long long` 的别名，距离累加可能较大，用 64 位整数保险。
- `a` 下标从 $1$ 开始，`a[i]` 就是自上而下第 $i$ 本作业归属的同学。
- 全部逻辑收进 `solve`，配合 `main` 里的 `while (t--)` 循环，方便将来扩展多测。

### 模块二：编码函数、记忆化表与递归基

```cpp
    auto get = [&](std::vector<int> &x) -> int { // 把 w 个目标打包进一个 int
        int res = 0;
        for (int i = 1; i <= w; i++) res |= (x[i] << (5 * (w - i)));
        return res;
    };

    std::vector<std::map<int, i64>> f(m + 1); // 按进度 i 分桶的记忆化表
    auto dfs = [&](auto && self, int i, int c) -> i64 {
        if (f[i].count(c)) return f[i][c]; // 已算过直接返回
        std::vector<int> x(w + 1);
        for (int i = 1; i <= w; i++) x[i] = (c >> (5 * (w - i))) & 31; // 解码：每 5 位一个编号
        if (i == m) {
            return f[i][c] = *std::max_element(x.begin() + 1, x.end()); // 全部取完：最后一趟不用回讲台
        }
```

- `get` 把 `x[1..w]` 从左到右依次放到高位到低位，每个占 $5$ 位；`& 31` 就是取低 $5$ 位（$31 = 2^5 - 1$），与编码一一对应。
- `f` 是「按进度分桶」的记忆化表：`f[i]` 只存进度为 $i$ 的那些状态，避免把 $i$ 和状态编码混在一个键里。
- 递归基 `i == m` 时所有作业已取走，返回手里最远目标的编号 `max_element(x[1..w])`，即单程距离；手里为空时最大值是 $0$。

### 模块三：决策一 · 再拿一本作业

```cpp
        i64 ans = 1e18;
        int s = 0;
        for (int i = 1; i <= w; i++) {
            //if ((c >> (5 * i)) & 31) s++;
            if (x[i]) s++; // 统计手里非空位（已携带本数）
        }

        if (s < w) { // 手里没满，可以再拿一本
            std::vector<int> b(w + 1);
            for (int j = 1; j <= w; j++) b[j] = x[j];
            b[s + 1] = a[i + 1]; // 把下一本放入当前空位
            std::sort(b.begin() + 1, b.end(), std::greater<int>()); // 降序规范化，相同目标相邻
            ans = std::min(ans, self(self, i + 1, get(b)));
        }
```

- `ans = 1e18` 是「尚未找到可行解」的哨兵，配合 `min` 完成取最小。
- `s` 统计手里非零位的个数（即当前携带本数），只有 `s < w` 才允许再拿。
- 拿书后 `i` 加一、距离不加（在讲台取书不花行走），并把新状态降序排序——排序是后面去重与「删掉 $\le d$」两步正确性的前提。

### 模块四：决策二 · 发掉一批作业

```cpp
        for (int j = 1; j <= w; j++) {
            int d = x[j];
            if (d == 0) continue; // 空位跳过
            if (j > 1 && x[j] == x[j - 1]) continue; // 去重：同一目标只枚举一次
            std::vector<int> b(w + 1);
            int idx = 1;
            for (int k = 1; k <= w; k++) {
                if (x[k] > d) b[idx++] = x[k]; // 顺路发掉所有目标 <= d，只保留 > d
            }
            ans = std::min(ans, (i64)2 * d + self(self, i, get(b))); // 往返代价 2d，i 不变
        }

        return f[i][c] = ans;
    };
```

- 降序排列保证相同目标相邻，`x[j] == x[j - 1]` 即可跳过重复值，每个不同目标只枚举一次。
- `if (x[k] > d)` 保留严格大于 $d$ 的、丢掉 $\le d$ 的——这正是「走到 $d$ 时顺路发掉所有更近同学」的编码实现。
- 决策二递归时 `i` 不变（只发书、不取新书），往返代价固定为 $2d$；`(i64)2 * d` 先转成 64 位再相乘，避免 `int` 溢出。

### 模块五：输出与主函数

```cpp
    std::cout << dfs(dfs, 0, 0); // 初始：还没取书、手里为空
}

int main(void) {
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);

    int t = 1;
    //std::cin >> t;
    while (t--) solve();

    return 0;
}
```

- 答案就是 `dfs(0, 0)`：进度为 $0$、手里为空，从这出发发完所有作业的最短额外距离。
- 关同步、解绑输入输出，是常规加速；`t` 固定为 $1$，保留注释掉的读入可随时改多测。

## 复杂度分析

- **时间复杂度**：状态总数为 $O\big(m\cdot(n+1)^w\big)$（进度维 $0 \sim m$，状态是 $w$ 个 $5$ 位块的压缩编码，每块取值 $0 \sim n$）。这是很松的上界，实际可达状态远少于它——手里最多 $w$ 本、每本目标只能落在 $1 \sim n$，还要受「从上往下拿」的进度约束。单次转移需解码 $O(w)$、决策二枚举至多 $w$ 个去重目标并重建 $O(w)$，合计 $O(w^2)$。对 $m \le 1000$、$w \le 5$ 完全可行。
- **空间复杂度**：$O\big(m\cdot(n+1)^w\big)$，即 `std::map` 记忆化表的总规模，同样受「可达状态远小于上界」的约束。

## 常见陷阱与注意事项

1. **5 位编码依赖 $n$ 的上界**：每本用 $5$ 位是因为 $n \le 24 < 2^5$；若 $n$ 升到 $\ge 32$，编号会占满并溢出 5 位块，压缩与解码互相污染，必须把位宽改成 $\lceil\log_2 n\rceil$，并同步改掩码 `& 31`。
2. **决策二删的是 $\le d$，不是 $= d$**：`if (x[k] > d)` 保留严格大于 $d$ 的，即顺路把 $\le d$ 的都发掉；若误写成「只删等于 $d$」，会漏掉「顺路发更近同学」这项免费优化，答案偏大。
3. **降序排序是去重正确性的前提**：`if (j > 1 && x[j] == x[j-1]) continue;` 靠相邻相等去重，只有先 `sort(..., greater<int>())` 保证降序，相同目标才会相邻；否则同一目标可能被重复枚举（虽不导致错误，但徒增状态）。
4. **递归基只走单程**：$i = m$ 时返回 $\max x_j$ 而不是 $2\max x_j$；若忽略「最后不用回讲台」这条规则多乘 $2$，会直接 WA。
5. **拿书分支的边界**：决策一读 `a[i+1]` 仅在 $i < m$ 时发生（$i = m$ 已提前返回）；`s < w` 保证 `b[s+1]` 不越界。若把递归基提前返回删掉，或把 `s < w` 误写成 `s <= w`，都会访问到 `a[m+1]` 或 `b[w+1]`。
6. **记忆化键要区分进度**：这里用 `vector<map<int,i64>> f(m+1)` 按 $i$ 分桶；如果把 $(i, c)$ 混进同一个 `int` 键，$i$ 与压缩编码可能冲突，务必分开或使用能区分两维的键。

## 对比与扩展

- **与旅行商 / 邮递员问题的关系**：这类「从一个点出发访问若干目标求最短路」天然是 TSP 风格；但本题所有目标都在一条直线 $1 \sim n$ 上，且可反复回原点，于是「访问到 $d$ 就顺路覆盖 $1..d$」这条一维几何性质，把「选点集顺序」的指数枚举压缩成「只决定最远落点 $d$」。
- **状态压缩 DP 的通用套路**：当「需要保留的一个小集合」加「一个单调推进的进度」都能塞进状态时，就可用 `dfs(进度, 压缩集合)` 记忆化；本题「编号 $\le 2^k$ 的元素用 $k$ 位打包」的技巧，可推广到任何元素编号较小的场景。
- **参数再大一点的走向**：本题 $w \le 5$ 是状压可行的关键；若 $w$ 或 $n$ 显著增大，状态空间会爆炸，通常要换思路（例如按「最后一次回讲台」划分的区间 DP，或最小化往返次数的费用流建模）。
- **变式**：若去掉「最后不用回讲台」、要求必须回到讲台，只需把递归基的 $\max x_j$ 改为 $2\max x_j$，其余逻辑不变。
