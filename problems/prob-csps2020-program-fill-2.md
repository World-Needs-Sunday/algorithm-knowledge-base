## 题目描述

给定 $n$ 个数（$n \le 10000$），每个数是 16 位的非负整数，即 $0 \le a_i < 2^{16} = 65536$。

要求从中选出一个**子序列**（保持原顺序，可不连续），使得分值最大。

分值的定义：子序列中每相邻两个元素做异或（XOR）运算，统计异或结果二进制中 1 的个数，把所有相邻对的 1 的个数加起来，就是总分。

形式化地，设选出的子序列为 $b_1, b_2, \ldots, b_k$，则分值为：

$$
\text{分值} = \sum_{i=1}^{k-1} \text{popcount}(b_i \oplus b_{i+1})
$$

其中 $\text{popcount}(x)$ 表示 $x$ 的二进制表示中 1 的个数。

### 输入格式

- 第一行一个正整数 $n$。
- 第二行 $n$ 个非负整数 $a_1, a_2, \ldots, a_n$。

### 输出格式

- 输出一个整数，表示最大分值。

### 数据范围

对于 $100\%$ 的数据，$n \le 10000$，$0 \le a_i < 2^{16} = 65536$。

### 提示

用高低 8 位分拆的状态压缩 DP。

## 样例

### 样例输入

```
4
3 12 0 15
```

### 样例输出

```
10
```

### 样例解释

选出全部 4 个数构成子序列 $[3, 12, 0, 15]$：

- $3 \oplus 12 = 0011_2 \oplus 1100_2 = 1111_2 = 15$，popcount = 4
- $12 \oplus 0 = 1100_2 \oplus 0000_2 = 1100_2 = 12$，popcount = 2
- $0 \oplus 15 = 0000_2 \oplus 1111_2 = 1111_2 = 15$，popcount = 4

总分：$4 + 2 + 4 = 10$。

## 解题思路

### 一、题意翻译

题目大白话：从一排数中按顺序挑一些数出来（子序列），使得两两相邻之间的"二进制差异位数"之和最大。

两个数的异或结果中有几个 1，就说明它们有几位不一样。所以"相邻一对的得分" = 两数二进制不同的位数。要让总分最高，就要让相邻的数"长得尽量不一样"——16 位全都相反的话，一对最多能拿 16 分。

### 二、朴素 DP：O(n²) —— 不够好

设 $f(i)$ 表示"以第 $i$ 个数为结尾的子序列的最大分值"。

转移：第 $i$ 个数可以接在任何一个更早的数 $j$ 后面，也可以自己单开一个子序列：

$$
f(i) = \max\!\Big(0, \max_{j < i}\big(f(j) + \text{popcount}(a_j \oplus a_i)\big)\Big)
$$

总时间复杂度 $O(n^2)$，$n=10^4$ 时约 1 亿次运算，偏紧且可扩展性差。

瓶颈在于：每次转移必须枚举"前一个数是谁"。能不能不枚举前一个数，改成枚举前一个数的**压缩信息**？

### 三、关键观察：值域小才是命门

注意每个数只有 16 位，也就是说全世界的数总共只有 65536 种。$n$ 有一万个，但种类只有六万多种。

这提示我们：别把状态建在"第几个数"上，把状态建在"数值"上。

设 $g(v)$ 表示"以值为 $v$ 的某个数结尾的最大分值"。读完一个新数 $a$，我们想对所有可能的旧值 $v$ 求：

$$
g(a) = \max\!\Big(0, \max_{v}\big(g(v) + \text{popcount}(v \oplus a)\big)\Big)
$$

但"所有旧值"有 65536 个，每次转移枚举 65536 个旧值，还是太慢。

问题卡在：转移要同时枚举旧值的 16 位，太宽了。

### 四、核心性质：异或和计数都能"按位拆"

得分的定义是异或结果中 1 的个数。异或是逐位独立运算的，"数 1 的个数"也是把每一位的 1 加起来。所以得分可以拆成两部分：

$$
\text{popcount}(p \oplus a) = \text{popcount}(p_{\text{高}} \oplus a_{\text{高}}) + \text{popcount}(p_{\text{低}} \oplus a_{\text{低}})
$$

其中 $p_{\text{高}}$ 表示 $p$ 的高 8 位，$p_{\text{低}}$ 表示 $p$ 的低 8 位。

这个朴素的等式是整道题的钥匙——得分可以拆成"高 8 位得分"和"低 8 位得分"，两笔账分开算、最后相加。

### 五、高低 8 位分拆

把每个 16 位数 $a$ 拆成两半：

- 高 8 位：$x = a \gg 8$（相当于 $a$ 整除 256）
- 低 8 位：$y = a \mathbin{\&} 255$（相当于 $a$ 除以 256 的余数）

代码中 `M = 16`，`B = 8`，`MS = 255`，就是这个意思。

这样一来，转移时可以只枚举前驱的**高 8 位**（256 种），低 8 位那部分账用别的办法处理。

### 六、"预付费"技巧

新数 $a$ 来了，它跟前驱 $p$ 的总得分是：

- 高 8 位得分：$p$ 的高 8 位 异或 $a$ 的高 8 位，数 1
- 低 8 位得分：$p$ 的低 8 位 异或 $a$ 的低 8 位，数 1

高 8 位好办：转移时枚举前驱的高 8 位 $z$（256 种），顺手就能算。

低 8 位是难点：它同时依赖"前驱的低 8 位"和"当前数的低 8 位"。如果表里只存"前驱以高 8 位 $h$ 结尾的最大分值"，那前驱的低 8 位信息就丢了，这笔账没法算。

**解决办法（预付费技巧）**：把表升级成二维的 `Max[高8位][低8位]`，含义是：

> 在所有已经出现过、且高 8 位等于 $h$ 的数 $p$ 中，取 "$p$ 为结尾的最大分值 $+$ $p$ 的低 8 位与 $l$ 异或后 1 的个数" 的最大值。

翻译成人话：假如下一个数的低 8 位是 $l$，而之前有个高 8 位为 $h$ 的前驱 $p$，那么把 $p$ 和这个未来数之间的**低 8 位得分先预支**、加在 $p$ 的分值上，最多能攒到多少分。

要点：
- 预付的账（$p$ 的低 8 位 异或 $l$）是按 $l$ 的取值分别存好的——$l$ 只有 256 种，所以每种可能的"未来低 8 位"都各存了一份
- 如果高 8 位为 $h$ 的数还一个都没出现过，`Max[h][l]` 就是负无穷，表示"查无此人，不许转移"

### 七、转移流程

新数 $a$ 到来，设它的高 8 位是 $x$、低 8 位是 $y$。

**第一步（查询）**：枚举前驱的高 8 位 $z$（共 256 种），算以 $a$ 结尾的最大分值 $v$：

$$
v = \max\!\Big(0, \max_{0 \le z \le 255}\big(\text{Max}[z][y] + \text{popcount}(x \oplus z)\big)\Big)
$$

其中 `Max[z][y]` 里已经包含了"前驱分值 + 前驱与 $a$ 之间的低 8 位得分"，再加上高 8 位得分，就是完整的转移得分。

$v$ 的初值是 $0$，含义是"$a$ 自己单开一个子序列，得分 0"。

**第二步（更新）**：把 $a$ 自己也"预付费"地写进表里。枚举未来数的低 8 位 $z$（共 256 种）：

$$
\text{Max}[x][z] = \max\!\big(\text{Max}[x][z],\ v + \text{popcount}(y \oplus z)\big)
$$

这里预付的账是"$a$ 的低 8 位与未来数的低 8 位 $z$ 的异或得分"。

**第三步**：全局答案 `ans` 取 `ans` 和 `v` 中较大者。

### 八、为什么这样不会算重、不会算漏

**不会算漏**：任何最优子序列，考虑它的最后一对相邻数 $p$ 和 $a$。$p$ 被处理时，它的分值带着"对 $a$ 的低 8 位的预付费"存进了 `Max[p高8位][a低8位]`（因为更新时 $z$ 枚举了全部 256 种，一定覆盖 $a$ 的低 8 位）。$a$ 处理时查询 $z = p$ 的高 8 位，把高 8 位的账补上，加出来正好是完整分值。

**不会算重**：每个相邻对的得分恰好被拆成低 8 位（预付时算）+ 高 8 位（查询时算）两笔，各算一次，不重不漏。

**取 max 天然正确**：同一个 $(h, l)$ 格子里如果有很多前驱，存最大值即可，转移时取到的自动就是最优的那个。

### 九、初始化与边界的两个"坑"

**坑一：Max 表必须初始化成负无穷，不能是 0。**

0 会被理解成"存在一个分值为 0 的前驱"，但开局谁都没出现过。用 0 会导致凭空多出转移、答案虚高。负无穷表示"这一格无效"，配合取 max 就自动被忽略。

**坑二：v 的初值必须是 0，不能是负无穷。**

因为只选一个数也是合法子序列，分值是 0。如果 v 从负无穷起步而表里全是负无穷，v 就永远是负无穷，一个数都不选的错误就会发生。

代码里 `INF` 取 $10^{15}$ 这么大，是因为分值最大约 $n \times 16$（一万个数、每对最多 16 分），负无穷要"负得足够多"才不会被当真。

### 十、手算验证（缩小版）

16 位太大不好手算，我们做一个缩小版：4 位拆 2+2，思想一模一样。此时 `MS = 3`，表是 4×4 的。

输入序列：$3, 12, 0, 15$，写成 4 位二进制并拆开：

| 数 | 二进制 | 高 2 位 x | 低 2 位 y |
|----|--------|----------|----------|
| 3 | 0011 | 0 | 3 |
| 12 | 1100 | 3 | 0 |
| 0 | 0000 | 0 | 0 |
| 15 | 1111 | 3 | 3 |

流程：

1. **处理 3（x=0, y=3）**：Max 全是负无穷，v = 0（单干）。更新 Max[0][z] = 0 + popcount(3 ⊕ z)。得 Max[0] = [2, 1, 1, 0]。
2. **处理 12（x=3, y=0）**：查询 Max[z][0]，只有 Max[0][0]=2 有效。v = 2 + popcount(3 ⊕ 0) = 2 + 2 = 4。对应子序列 [3, 12]，得分 4。更新 Max[3][z] = 4 + popcount(0 ⊕ z)，得 [4, 5, 5, 6]。
3. **处理 0（x=0, y=0）**：查询 Max[z][0]，Max[0][0]=2、Max[3][0]=4。v = max(2+0, 4+2) = 6。对应子序列 [3, 12, 0]，得分 6。更新 Max[0][z] = 6 + popcount(0 ⊕ z)，得 [6, 7, 7, 8]。
4. **处理 15（x=3, y=3）**：查询 Max[z][3]，Max[0][3]=8、Max[3][3]=6。v = max(8+2, 6+0) = 10。对应子序列 [3, 12, 0, 15]，得分 10。

最终答案 10，与样例输出一致。

### 十一、复杂度分析

| 维度 | 复杂度 | 说明 |
|---|---|---|
| 时间 | $O(n \cdot 2^B)$ | 每个数查询 256 次 + 更新 256 次，共 $n \times 512$ |
| 空间 | $O(2^{2B})$ | $256 \times 256$ 个 long long，约 0.5 MB |

总计约 500 多万次运算，瞬间跑完。对比朴素 DP 的 1 亿次，优化效果显著。核心原因：把"枚举前驱的 16 位"拆成了"预付低 8 位 + 枚举高 8 位"，枚举量从 $2^{16}$ 降到了两次 $2^8$。

### 十二、一句话提炼

当转移代价依赖于"前驱值"和"当前值"的两部分、且每部分都能按位独立计算时，可以把值域拆成高低两半：把涉及"前驱低半段 × 当前低半段"的那笔代价，提前按当前低半段的每一种取值预付并存进二维表；转移时只需枚举前驱的高半段。枚举量从"两半的乘积"降到"两半各自"，这正是"状态压缩 + 代价前移"的经典组合拳。

### 头文件与常量定义

```cpp
#include <iostream>
using namespace std;
typedef long long LL;

const int MAXN = 40000, M = 16, B = M >> 1, MS = (1 << B) - 1;
const LL INF = 1000000000000000LL;
```

- `M = 16`：每个数的二进制位数
- `B = 8`：分拆后的半长（高 8 位 / 低 8 位）
- `MS = 255`：半长的掩码（低 8 位全 1）
- `INF = 1e15`：无穷大，用于初始化负无穷

### DP 表与工具函数

```cpp
LL Max[MS + 4][MS + 4];   // Max[高8位][低8位]
```

二维 DP 表，`Max[h][l]` 的含义见"预付费技巧"一节。

```cpp
int w(int x) {                    // 统计 x 二进制中 1 的个数
    int s = 0;
    while (x) {
        x &= x - 1;               // 去掉最低位的 1
        s++;
    }
    return s;
}
```

Brian Kernighan 算法：每次 `x &= x - 1` 消掉最低位的一个 1，循环次数等于 1 的个数。比逐位检查更快。

```cpp
void to_max(LL& x, LL y) {       // 如果 x < y，将 x 改为 y
    if (x < y) x = y;
}
```

引用传参的取 max 工具函数，代码更简洁。

| 维度 | 复杂度 | 说明 |
|---|---|---|
| 时间 | $O(n \cdot 2^{M/2})$ | 每个数两次 $2^8$ 循环，共 512n |
| 空间 | $O(2^{M})$ | $256 \times 256$ 个 long long，约 0.5 MB |

注：$M = 16$ 为总位数，$B = M/2 = 8$ 为半长。如果数的位数不同，可以相应调整分拆点。

## 常见陷阱与注意事项

1. **Max 表初始化必须是负无穷**：不能是 0，否则开局就会有"分值为 0 的虚拟前驱"，导致答案虚高。

2. **v 的初值必须是 0**：单个元素也是合法子序列，分值为 0。如果 v 从负无穷起步，就会出现"一个数都不选"的错误。

3. **查询和更新的方向别写反**：查询枚举的是"前驱的高 8 位"，更新枚举的是"未来数的低 8 位"。两者的枚举对象不同。

4. **预付的账是"前驱低半段异或当前/未来低半段"**：方向不能反。更新时是 `v + w(y ^ z)`，其中 y 是当前数的低 8 位，z 是未来数的低 8 位。

5. **数据类型必须用 long long**：分值最大约 $n \times 16 = 160000$，int 虽然够，但转移时中间值（加上预付费）可能更大，用 long long 更安全。

6. **INF 要足够大**：负无穷要"负得足够多"，使得取 max 时无效格子不会被误选。一般取答案上界的 10 倍以上即可。

## 对比与扩展

| 对比维度 | 朴素 DP | 高低位分拆 DP（本题） |
|---|---|---|
| 状态定义 | f(i)：以第 i 个数结尾 | Max[h][l]：高 h 低 l 的预付费最大值 |
| 转移方式 | 枚举所有前驱 j | 枚举前驱高 8 位（256 种） |
| 时间复杂度 | $O(n^2)$ | $O(n \cdot 2^{M/2})$ |
| 空间复杂度 | $O(n)$ | $O(2^M)$ |
| 适用条件 | 通用 | 值域小且代价可按位拆分 |
| 核心技巧 | — | 预付费 + 高低位分拆 |

**扩展思考**：
- 如果位数是 20 位，可以拆成 10+10，表大小 1024×1024，每次转移 2048 次
- 如果位数是 32 位，可以拆成 16+16 或使用 meet-in-the-middle 思路
- 类似的"代价可拆分 + 预付费"技巧还可用于其他状压 DP 问题，比如基于位运算的转移代价
- 当模数不互质时，CRT 的扩展版本 EXCRT 也用了类似"逐次合并"的思想
