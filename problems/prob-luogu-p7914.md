## 题目描述

小 w 定义一个「符合规范的超级括号序列」为由 `(`、`)`、`*` 组成的字符串，对给定常数 $k$ 满足（设 $S$ 为不超过 $k$ 个 `*` 组成的**非空**串）：

1. `()`、`(S)` 是合法序列；
2. 若 `A`、`B` 合法，则 `AB`、`ASB` 合法；
3. 若 `A` 合法，则 `(A)`、`(SA)`、`(AS)` 合法；
4. 所有合法序列均由上述规则得到（空串不是合法序列）。

现在给定一个长度为 $n$ 的字符串，部分位置已确定，部分位置是 `?`。求把所有 `?` 确定后，能得到多少个不同的合法序列，答案对 $10^9+7$ 取模。

### 输入格式

第一行两个正整数 $n, k$；第二行一个长度为 $n$、仅由 `(`、`)`、`*`、`?` 构成的字符串 $S$。

### 输出格式

一个非负整数，表示答案对 $10^9+7$ 取模的结果。

### 数据范围

- $1 \le k \le n \le 500$。
- 测试点 $1\sim3$：$n\le15$；$4\sim8$：$n\le40$；$9\sim13$：$n\le100$；$14\sim15$：$n\le500$ 且 $S$ 仅含 `?`；$16\sim20$：$n\le500$。

## 解题思路

### 从「括号」的本质想到区间 DP

合法括号序列的核心结构只有两种：**嵌套**（形如 `(…)` 把一段合法内容包起来）与**拼接**（形如 `AB` 把两段合法内容接起来）。这两种操作都作用在**一段连续区间**上，因此天然适合区间 DP：设状态表示子串 $s[l..r]$ 的方案数，从小到大枚举区间长度，再枚举分割点合并左右两部分。

### 直接两维为什么会重复计数

若只开两维 $dp[l][r]$，合并时会遇到致命问题：同一个合法序列可能有多种「最后一次拼接」的方式。例如 `()()` 既可看成 `()` 接 `()`，也可被描述为「左括号序列 + 右括号序列」；`(())` 既是被括号包裹，也符合拼接的描述。若不加以区分，多条转移路径会把同一个序列各算一遍，导致重复计数。

### 关键转化：按「形态」给序列打标签

解决思路是**把合法序列按首尾形态分类**，每一类对应唯一的转移入口，保证不重不漏。题解把每个区间 $[l,r]$ 的内容拆成 6 种形态，用 $dp[l][r][0..5]$ 计数：

| 状态 | 形态描述 | 示例（$k$ 足够大） |
|:---:|------|------|
| `0` | 整段全由 `*` 组成 | `***` |
| `1` | 首尾正好被一对括号包裹，内部是合法内容 | `(())`、`(*())` |
| `2` | 左端以括号序列开头、右端以 `*` 结尾 | `()**`、`(**)*` |
| `3` | 左端以括号序列开头、右端以括号序列结尾（含状态 1） | `()()`、`(())` |
| `4` | 左端以 `*` 开头、右端以括号序列结尾 | `**()`、`*(*)` |
| `5` | 左端以 `*` 开头、右端以 `*` 结尾（含状态 0） | `***`、`**()*` |

状态 1 是状态 3 的子集、状态 0 是状态 5 的子集。代码在每轮区间转移结束后分别执行 `h[l][r] += b[l][r]` 与 `tr[l][r] += sr[l][r]`，把状态 1 并入状态 3、把状态 0 并入状态 5。之所以分开存，是因为它们虽然在最终答案中都要被统计，但在**转移过程中**扮演的角色完全不同：例如状态 2 只能「左边取状态 3、右边接全 `*`」，状态 4 只能「左边取状态 4 或 5、右边接状态 1」。不区分形态就会走错转移或重复累加。

### 两个基础预处理

1. `sr[l][r]`：区间 $[l,r]$ 能否被全部填成 `*`（且长度不超过 $k$）。空区间视为可以，即 `sr[i][i-1] = 1`；非空区间当且仅当 `sr[l][r-1] = 1`、$s[r]$ 是 `*` 或 `?`，且长度 $r-l+1 \le k$ 时成立。

2. `cmk(l,r)`：当 $s[l]$ 是 `(` 或 `?`、且 $s[r]$ 是 `)` 或 `?` 时为真，表示 $l$ 与 $r$ 能配成一对括号。

### 六类转移方程

代码中六个数组 `sr / b / f / h / c / tr` 依次对应状态 0~5。

- **状态 1（`b[l][r]`）**：当 `cmk(l,r)` 成立时，内部可以是全 `*`（状态 0）或状态 2/3/4，分别对应规则 3 的 `(*)`、`(SA)`、`(A)`、`(AS)`：

$$
b[l][r] = sr[l+1][r-1] + f[l+1][r-1] + h[l+1][r-1] + c[l+1][r-1]
$$

- **状态 2（`f[l][r]`）**：枚举分割点 $i \in [l, r-1]$，左半必须为状态 3、右半为全 `*`（状态 0）：

$$
f[l][r] \gets f[l][r] + h[l][i] \cdot sr[i+1][r]
$$

- **状态 3（`h[l][r]`）**：一是状态 1 直接并入；二是左半为状态 2 或状态 3、右半接一个状态 1：

$$
h[l][r] \gets h[l][r] + \big(f[l][i] + h[l][i]\big) \cdot b[i+1][r]
$$

- **状态 4（`c[l][r]`）**：左半为状态 4 或状态 5、右半接一个状态 1：

$$
c[l][r] \gets c[l][r] + \big(c[l][i] + tr[l][i]\big) \cdot b[i+1][r]
$$

- **状态 5（`tr[l][r]`）**：一是状态 0 直接并入；二是左半为状态 4、右半接全 `*`（状态 0）：

$$
tr[l][r] \gets tr[l][r] + c[l][i] \cdot sr[i+1][r]
$$

以上所有累加均在模 $10^9+7$ 意义下进行。

### 为什么这样就不重不漏

每一种「形态」都规定了该序列下一步**唯一**的拼接方式：状态 2 只能向右再接一段 `*` 变成状态 5，状态 4 只能向右再接一个被括号包裹的块，等等。因此任意合法序列在生成时只会经过一条固定的状态转移链，不会同时被两条路径计算。又因为状态 3 覆盖了所有「以括号序列开头、以括号序列结尾」的串，而合法序列的两端必然都是括号（不可能是 `*`），所以最终答案就是 $dp[1][n][3]$，对应代码中的 `h[1][n]`。

### 括号配对判断 cmk

```cpp
bool cmk(int l,int r){
    if((s[l]=='('||s[l]=='?')&&(s[r]==')'||s[r]=='?')) return true;
    else return false;
}
```

- `cmk(l,r)` 判断位置 $l$、$r$ 能否配成一对括号：左端是 `(` 或 `?`，右端是 `)` 或 `?`。
- 只有 `cmk(l,r)` 成立时才计算状态 1（`b[l][r]`），否则该区间无法被整体包裹。

### 区间 DP 主循环与状态转移

```cpp
    for(int len=1;len<=n;len++){
        for(int l=1;l<=n-len+1;l++){
            int r=l+len-1;
            //if(len<=k&&sr[l+1][r]==1&&(s[l]=='*'||s[l]=='?')) sr[l][r]=1;
            if(len<=k&&sr[l][r-1]==1&&(s[r]=='*'||s[r]=='?')) sr[l][r]=1;
            if(len>=2){
                bool u=cmk(l,r);
                //cout<<u<<" "<<l<<" "<<r<<"\n";
                if(u) b[l][r]=(sr[l+1][r-1]%mod+f[l+1][r-1]%mod+h[l+1][r-1]%mod+c[l+1][r-1]%mod)%mod;
                for(int i=l;i<r;i++){
                    f[l][r]=(f[l][r]%mod+h[l][i]*sr[i+1][r]%mod)%mod;
                    h[l][r]=(h[l][r]%mod+(f[l][i]+h[l][i])*b[i+1][r]%mod)%mod;
                    c[l][r]=(c[l][r]%mod+(c[l][i]+tr[l][i])*b[i+1][r]%mod)%mod;
                    tr[l][r]=(tr[l][r]%mod+c[l][i]*sr[i+1][r]%mod)%mod;
                }
            }
            h[l][r]=(h[l][r]%mod+b[l][r]%mod)%mod;
            tr[l][r]=(tr[l][r]%mod+sr[l][r]%mod)%mod;
        }
    }
```

- 外层按区间长度递增、内层枚举左端点，保证转移所需的更短区间都已算好。
- `sr[l][r]` 的递推只在 `len<=k` 时进行，落实「`*` 段长度不超过 $k$」的限制。
- `b[l][r]` 对应状态 1（被括号包裹）；`f/h/c/tr` 各自按转移方程累加，循环结束后把状态 1 并入状态 3、状态 0 并入状态 5。
- 所有累加都即时对 `mod` 取模，保持中间量在模意义下。

## 复杂度分析

### 时间复杂度

- 状态规模：$n^2$ 个区间，每个区间维护 6 个形态。
- 每个区间在转移时要枚举分割点 $i$，代价 $O(n)$。
- 总复杂度 $O(n^3)$；$n \le 500$ 时约 $1.25 \times 10^8$ 量级，配合较小的常数可以接受。

### 空间复杂度

- 六个 `N×N` 的数组（`sr/b/f/h/c/tr`），规模 $O(6n^2) = O(n^2)$。

## 常见陷阱与注意事项

1. **重复计数的根源**
   - 若不区分形态，`(())` 会同时被「括号包裹」和「拼接」两条路径计数。
   - 状态 1 与 3、状态 0 与 5 必须分开存，转移时各司其职，最后再并入。

2. **状态并入的时机**
   - 代码在每轮区间枚举结束后才执行 `h[l][r] += b[l][r]` 与 `tr[l][r] += sr[l][r]`。
   - 若在转移循环中途就并入，会污染同一轮的后续转移，造成重复。

3. **空区间的 `*` 边界**
   - `sr[i][i-1]=1` 处理了 `()` 这种内部为空串的情况（此时区间 $[l+1, r-1]$ 为空）。

4. **`#define int long long` 的必要性**
   - 转移中出现 `(f[l][i]+h[l][i]) * b[i+1][r]`，两个小于模数的数相乘可达约 $10^{18}$，普通 `int` 会溢出。
   - `signed main()` 是 `long long main` 的等价写法。

5. **下标从 1 开始**
   - 用 `s=' '+s` 在串首补一个空格字符，使下标与 DP 区间 $[1,n]$ 对齐，避免边界特判。

6. **答案取状态 3 的原因**
   - 合法序列首尾必须是括号，因此必然是「以括号序列开头、以括号序列结尾」的状态 3，即 `h[1][n]`。

### 扩展

- 本题「按首尾形态拆分状态」是区间 DP 计数去重的通用套路，可迁移到「括号着色计数」「表达式拆分计数」等区间计数问题。
- 若去掉 $k$ 限制（`*` 段长度任意），状态 0 与状态 5 会退化为更简单的全 `*` 前缀判断，整体框架不变。
- 与「括号树」「合法括号序列」等经典题一样，都依赖「括号序列可由嵌套与拼接唯一分解」这一核心性质。
